# 设计：家长端朗读诊断文案改用当前通过线

## 现状与方案

parent-app 有两处静态文案把 `low_pron_accuracy` 解释为“低于 60”：

- `ReadingDiagnosticScreen.kt` 的 `diagnosticReason`：列表每条记录的“柠檬认字判定”行。
- `ReadingDiagnosticGuide.kt` 的 `appFields`：字段说明页的条目。

两处都不读取记录内容。认字端当前规则为字 50、词 50、句 30（[LEARNING-RULES.md](../../kid-literacy-app/docs/LEARNING-RULES.md)），因此改为：

- 列表文案：`至少一项发音准确度低于通过线（字、词 50 分，句 30 分；含特殊值 -1）`
- 说明页条目：`柠檬认字发现至少一个逐项 PronAccuracy 数值低于该次朗读的通过线：字 50、词 50、句 30（更早版本客户端的单字通过线为 60，历史记录按当时规则解释）。当前规则也把 -1 归入此项；-1 应按腾讯的“完全不匹配”理解。`

列表文案不与单条记录的类型联动：同一行已显示目标类型（字/词/句）与目标文本，家长可据此对应；逐条定制需要把 `targetType` 传入原因格式化函数，且历史记录仍无法区分规则版本，收益有限。

## 文件与依赖影响

- parent-app/src/main/java/com/lemonkids/parent/feature/profile/ReadingDiagnosticScreen.kt：替换 `diagnosticReason` 中 `low_pron_accuracy` 的文案。
- parent-app/src/main/java/com/lemonkids/parent/feature/profile/ReadingDiagnosticGuide.kt：替换 `appFields` 中同名条目说明。
- 不修改查询接口、日志结构、云函数、数据库和 kid-literacy-app；查询接口不返回 `decisionVersion`，本次不为文案改动新增云函数部署包。
- parent-app/README.md 未描述该阈值，无需同步；历史需求文档保留原文。

## 测试与交付

执行 `GRADLE_USER_HOME="$PWD/.gradle-system" ./gradlew :parent-app:assembleDebug :parent-app:testDebugUnitTest`，确认构建和既有单测通过；文案为字符串常量，不新增单测。自动测试通过后请求安装许可，安装到当前连接的 Pad 供人工验收；验收通过后提交推送并标记完成。

## 风险与回滚

文案与真实规则不一致会误导家长排查；本次只改两个字符串常量，风险低。回滚时恢复原字符串即可，不涉及数据或接口。
