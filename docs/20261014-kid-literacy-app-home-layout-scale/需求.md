## 原始需求

> 柠檬认字 app 新增 UI 优化需求：
> 1. 下面的认字和我的，应该要固定展示在屏幕底部，也不是页面底部。
> 2. 首页的 UI 与效果图不一样，效果图是两列展示，项目里实际只展示一列。
> 3. 不知道是不是视口倍数有什么问题，项目打开后看上去比效果图里的元素都要大很多。

2026-10-14 补充说明：

> 1. 首页认字空间不足也不能退回单列。
> 2. 本单的ui在 /Users/yupengjun/lemon-kids/kid-literacy-app/design-concepts 你要仔细比对尺寸，先修改首页认字页个元素的尺寸。

## 背景、目标与范围

上一轮花园 UI 已按用户确认完成；当时设计将“认字 / 我的”放在滚动末尾，首页分组逐组占满一行，因而与此次明确的参考图要求不一致。本需求优化首页与“我的”的一级导航定位、首页任务组排列，以及首页整体视觉比例。

目标：首页任务组始终以两列排列；导航固定在屏幕安全区底部，内容可在其上方独立滚动；先按 `design-concepts` 中的首页参考图逐项校准首页标题、插画、卡片、字格、间距和导航的视觉比例，同时保留可读性和触控尺寸。其他页面的业务内容、数据与路由保持既有规则。

非目标：重做其余页面与弹窗、改变系统显示密度或字体倍率、修改认字任务分组和学习规则、修改共享模块、数据库或云函数。

## 约束与依赖

- 本需求只涉及 `kid-literacy-app` 的 Compose 布局与样式，不新增跨模块接口或部署依赖。

## 可验证的验收标准

1. 首页和“我的”的“认字 / 我的”导航始终位于可见屏幕底部安全区，页面滚动时保持可见；不挡住最后一张卡片、入口或操作。切换页面后选中态正确。
2. 首页任务组在所有支持的横屏窗口和字体倍率下始终每行两列，按原数据顺序从左到右、从上到下展示；少于两组或组数变化时不出现无意义占位。宽度不足时仅调整卡内字格列数、换行和内容高度，不把任务卡改为单列。
3. 在 BZT3-AL00 横屏、系统字体倍率 1.0 下，首页各元素与参考图的宽高比例逐项对照：正常数据的两行任务卡与固定导航可在首屏形成相同的整体结构；超出高度时内容顺畅滚动。汉字格仍至少 48×48 dp 可点击，文字不截断。
4. 加载、空任务、刷新、进入学习、返回顶部和“我的”六个入口保持可操作；浮动控件不与底部导航重叠。
5. 自动验证覆盖布局计算和关键页面行为；经用户确认后安装到指定设备，并由用户人工检查视觉比例和操作。

## 跨模块影响

仅本应用的 UI。沿用既有 `LiteracyHomeViewModel`、真实任务数据、`:shared` 登录以及服务端接口；其他应用、数据库与云函数均无改动。

## 人工测试期间的补充需求与缺陷（最终验收范围）

用户追加并最终验收通过以下补充需求：

1. 首页背景从顶部对齐，竖向只裁切底部；所有汉字使用系统默认字体；刷新按钮改为浅蓝半透明、白色描边胶囊；移除“识字任务”标题行。
2. 待认识卡使用当天任务快照日期，不显示“第1组”；页头扩宽，让常见三字昵称的欢迎副标题在目标 pad 保持一行，长昵称仍可换行。
3. 四张卡的标题与日期各占一行，已认识卡的两个收录日期完整显示；标题区在标准字体倍率下约 45 dp，右侧角饰可见底边贴齐标题与字格的分隔线。空间不足时内容增高，首页仍保持两列。

用户反馈并最终验收通过以下缺陷修正：四张卡使用珊瑚或浅绿外框、内层白线及浅色渐变；待认识标题左侧显示完整郁金香，已认识标题左侧显示完整嫩芽；右上角按阅读顺序使用四幅不同的嫩芽、白花 A、白花 B、粉花角饰，大小与参考图接近；底部导航未选中项改为蓝灰色。首次缺陷版本因四角饰相同而未通过，复修后用户明确确认通过。

以上均限 `kid-literacy-app` 的展示层及任务日期的 UI 映射，不改任务数据、接口、数据库、共享模块或云函数。最终人工验收以用户 2026-10-14 对主需求、补充需求和缺陷的整体通过确认为准。
