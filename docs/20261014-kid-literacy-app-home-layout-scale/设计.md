# 设计：柠檬认字首页布局与底部导航优化

> 版本：v3（含已验收的补充与缺陷结论），2026-10-14。范围：`kid-literacy-app`。主方案及后续各次修订均已获用户明确批准。

## 1. 问题分析

| 用户观察 | 当前实现 | 原因判断 |
| --- | --- | --- |
| 导航在页面底部，滚动后才见 | `HomeScreen` 和 `ProfileScreen` 都把 `LiteracyBottomNav` 放在 `LazyColumn` 的最后一个 item | 导航属于滚动内容，不属于屏幕固定层 |
| 首页只展示一列任务卡 | `HomeScreen` 对每个 `group` 单独生成一个列表 item，`LessonCard` 填满列表宽度 | 缺少任务组的双列行容器 |
| 首页元素整体比参考图大 | 首页卡片占满约 1000 dp 的窗口宽度；字格上限 132 dp，字固定 60 sp；面板内边距 20 dp、页面横向边距 28 dp | 单列宽卡放大了字格和留白。设备密度为 320 dpi、字体倍率 1.0，暂无证据表明系统视口倍率异常 |

参考图为 1586×992 像素，是视觉稿尺寸；Android 应按窗口 dp 与安全区布局。不能通过强改设备密度或给整页做统一缩放来适配一张图，否则会影响文字、触控和其他页面。

## 2. 方案目标与范围

在现有花园 UI 基础上，先校准首页认字页的元素尺寸与任务组排列，再调整首页及“我的”的固定导航。背景仍由 `GardenPageScaffold` 固定铺满安全区；底部导航独立于滚动内容；首页任务组始终为双列行。其余页面和学习弹窗保留既有字号与布局。真实分组、日期、完成态、学习入口和刷新逻辑不变。

## 3. 页面结构与交互

### 3.1 固定底部导航

- 在首页和“我的”的页面根容器内，将可滚动内容与 `LiteracyBottomNav` 分成上下两层；导航锚定可见安全区底部，背景保持当前居中胶囊样式。
- 主页内容的底部预留导航实际高度及安全间距，让最后一张卡片、空状态和“我的”最后一排入口均可滚动到导航上方完整查看。
- 导航不随列表滚动；页面滚动、刷新和切换 tab 时保持可点，选中态仍由当前 `Page` 决定。
- “返回顶部”按钮位于内容区右下侧，与导航保持间距；加载遮罩继续按现有规则拦截页面操作。
- 仅两个一级页展示导航；字库等二级页继续使用已有返回入口。

### 3.2 首页双列任务组

- 首页页头与“识字任务”标题仍跨全宽；任务组按原顺序两两组成一行。待认识组仍先于已认识复习组；常见四组形成两行两列，与参考图一致。
- 所有支持的横屏宽度均保持两张任务卡并排，包括系统字体放大时。目标 BZT3-AL00（约 1000×567 dp 应用窗口）每卡六个字格在一行；卡宽不足时卡内字格改为每行 3、2 或 1 个并增加卡片高度，仍保持任务卡两列。卡片标题可换行，不截字。
- 每组不足六字时字格保持同一尺寸，不将单个字拉大；标题和日期按真实数据展示。分组超过一屏时纵向滚动，不能为了贴合视觉稿裁掉内容。
- 各宽度共用同一点击与完成态逻辑，不引入新的任务分组或数据缓存。

### 3.3 首页尺度校准

- 首页双列卡根据可用卡宽计算六个字格的宽、高、间距和卡内边距；目标平板单格约 57×68 dp、间距约 5–6 dp，任务卡约 403×161 dp。字格点击区域始终不小于 48×48 dp；宽度不足时卡内换行，避免沿用现有 132 dp 大正方形。
- 首页汉字字号随字格尺寸限定在目标 36–42 sp 左右，并遵守系统字体缩放；首页卡片标题、页头与垂直留白按对照表逐项校准，让两排任务卡、顶部页头及底部导航在约 567 dp 高的应用窗口形成接近参考图的构图。
- 不更改应用全局 `Typography`、设备密度或字体倍率，避免其他七页和练习弹窗被一起缩小。
- 汉字、标题、日期及完成标记优先保证完整显示；内容高度增加时允许滚动。48 dp 触控下限、安全区和大字体可用性优先于像素级复刻。

## 4. 涉及文件、数据与接口

- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/LemonLiteracyApp.kt`：首页和“我的”的滚动层/固定导航层、双列分组、返回顶部位置、首页卡片尺寸参数。
- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/ui/components/GardenComponents.kt`：如需要，仅增加首页专用卡片/字格尺度入口或布局辅助；维持其他页面现状。

- 对应的布局单元测试：验证目标平板双列、窄窗口仍双列、卡内字格换行与最小触控尺寸；必要时补充 Compose 布局测试，验证导航固定与内容不被遮挡。
- 人工验收通过后同步 `kid-literacy-app/docs/UI-SPEC.md` 与 `kid-literacy-app/README.md` 中现有的“末尾导航 / 单列首页”描述。本需求文档保留决策与测试过程。

## 5. 风险与回滚

- 双列卡宽在 4:3、16:10、16:9 和大字体下不同，需按实际窗口宽度计算并验证；空间不足只调整卡内字格行数和内容高度，任务卡不切单列。
- 固定导航可能遮住长列表末项，必须预留底部空间并在首页与“我的”分别验证滚动到底。
- 导航固定后，加载遮罩与悬浮返回顶部的叠放关系需验证，避免遮挡或错误点击。
- 若设备实测显示两列字格仍偏大或偏小，优先调整首页局部尺寸常量；回滚时恢复原导航层和分组行布局，不涉及数据回滚。

## 6. 验收与后续流程

以 [`需求.md`](需求.md) 的五项验收标准为准。自动验证计划包括 `:kid-literacy-app:assembleDebug`、`lintDebug`、`testDebugUnitTest` 和关键布局测试。自动测试完成后报告结果并等待安装确认；安装到用户指定设备后等待人工测试结论。人工确认通过后再核对长期文档、提交和推送。

## 设计确认

- 当前结论：用户明确回复“批准，完成后直接安装到pad”；按本设计进入执行阶段。
- 待确认的设计决策：首页任何支持的横屏宽度均为两列，窄窗口只调整卡内字格行数；先按对照表逐项调整首页元素尺寸；导航仅在“认字 / 我的”两个一级页固定于安全区底部；不修改系统显示倍率及其他页面的全局尺度。
- 设计确认后已创建 `执行.md`；安装须在自动测试通过后进行。

## 7. 补充与缺陷的最终设计结论

原第 3 节中“识字任务”标题及标题日期同行等首版描述，以下列最终方案为准：

- 首页 `GardenPageScaffold` 的背景保持填充，顶部居中对齐，宽屏产生的竖向裁切落在底部；首页移除独立“识字任务”行，任务卡紧随页头。非紧凑页头标题列上限扩至 256 dp，并收回左侧额外留白；长昵称允许换行，不挤压刷新按钮或吉祥物。刷新使用约 96×41 dp 的浅蓝半透明、白色描边胶囊，保留至少 48 dp 触控高度及加载中禁用行为。
- 取消应用对 Ma Shan Zheng 的显式字体引用，首页字格、学习主字、通过记录及待认识字格均使用系统默认字体，移除应用内字体与许可证副本。设计原始资源不修改。
- 待认识分组的日期来自任务快照 `date`，解析失败不编造日期；已认识日期来自收录时间换算后的中国日期。四张卡统一将标题置于第一行、日期置于第二行；两个日期按从近到远以“10月13日 · 10月12日”完整展示。无日期的已认识组在第二行回退“第 N 组”。日期仅为 UI 展示，不改任务快照或接口。
- 标准字体倍率下卡片标题区约 45 dp：标题约 18 sp，日期约 13 sp，左侧图标约 40×45 dp。移除标题区到分隔线的 7 dp 间隔，仅在分隔线与字格之间保留必要间距。标题或日期在窄窗口和大字体下可自然换行，卡片增高但首页不降为单列。
- 任务卡使用白色外描边、珊瑚或浅绿外框、内层细白线及浅色纵向渐变。待认识卡左侧用完整郁金香，已认识卡用完整嫩芽；右侧四幅独立透明角饰按待认识嫩芽、白花 A、白花 B、粉花排列，已认识卡多于三张时循环后三幅。角饰约 118–126×50–53 dp，底边锚定分隔线，并补偿素材透明留白使可见花草落在线上；角饰不参与标题高度测量或字格点击。
- 底部导航未选中文字与图标使用蓝灰色 `#6D7A89`，选中项继续为蓝色。导航在首页和“我的”均固定于屏幕安全区底部。

用户分别批准初始补充设计、页头宽度修订、卡片标题与双日期修订，以及缺陷初版和四角饰复修方案；各轮均在自动测试通过后按对应授权安装。最终用户确认主需求、全部补充需求及缺陷均人工测试通过。完整过程、失败版本与最终测试记录见 [执行](执行.md)。回滚只需恢复本应用布局、样式与字体资源引用，无数据迁移。
