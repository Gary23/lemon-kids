# 需求：柠檬任务奖励图片展示

- 需求编号/目录：`20261004-kid-task-app-reward-image-display`
- 日期：2026-10-04
- 应用范围：`kid-task-app`；消费家长端流程新增的共享奖励图片字段和私有存储读取接口。
- 提出人：用户
- 原始需求描述：「新建一个任务端开发分支，开发柠檬任务app，在新分支新增一个需求，我大概描述一下我的要求，我想在柠檬任务的奖励模块新增一个功能，在家长端可以上传奖励的图片，在柠檬任务app奖励模块就直接展示设置的图片」

## 背景与目标

现有奖励页的大心愿和小心愿卡片按预设标识使用本地图片。家长设置了具体奖励图片后，孩子应在奖励模块直接看到对应图片，形成与家长目录一致的展示。

## 范围与约束

- 大心愿及小心愿卡片优先展示当前奖励的家长上传图片；无图或图片暂不可读时沿用现有预设封面。
- 图片必须来自当前家庭启用奖励，不能影响名称、说明、价格、积分、兑换和记录状态。
- 页面打开/刷新时读取最新奖励目录与短期图片访问地址；图片失败不阻断奖励目录和兑换操作。
- 依赖家长端图片上传流程提供 `rewards.image_path`、私有 Storage 权限和共享仓库签名接口。

## 非目标

- 不在孩子端上传、替换或移除图片。
- 不改变已兑换记录的文字与状态展示，也不为历史记录新增图片快照。

## 跨模块影响及其他应用

家长端上传、共享模型及 Storage 迁移由独立的[家长端需求](../20261004-parent-app-reward-image-upload/需求.md)处理，须先验证该依赖。本流程只实现任务端奖励页的读取与展示，并单独获得设计、安装及人工测试确认。

## 可验证的验收标准

1. 本家庭启用奖励若有上传图片，任务端大心愿或小心愿卡片显示该图；家长替换/移除后刷新可看到更新。
2. 旧奖励、无图奖励或图片加载失败时按当前预设封面展示，卡片和兑换功能仍可用。
3. 孩子不能从本页修改图片；其他家庭的图片不能通过当前孩子会话读取。
4. 自动测试通过后单独取得任务端安装确认，安装后等待任务端人工测试结论。
