- 应用范围：`parent-app`、`kid-task-app`；涉及 `shared` 与 `supabase` 的任务数据链路

- 实机缺陷原文：“取的颜色有点深了，我觉得应该再浅一些。”最终采用调浅配色。

## 背景与目标

当前任务库描述会在创建日程时复制到每天的任务实例，内容固定。家长需要为同一任务的不同日期分别发布具体内容。同时，孩子端首页待完成列表标题下的拖动提示占用空间，需移除。

## 范围与约束

- 任务库新建和编辑界面不再提供描述输入，也不再在任务库列表显示模板描述。新建日程的任务描述初始为空；已有任务实例的描述保留。
- 家长端首页今日任务列表和日历日期任务列表中，点击笔图标进入现有任务编辑页，查看并编辑该条任务当天的描述；点击列表项不打开描述弹窗。已有任务描述可预填、修改、清空；过去或已完成任务的描述只读，保存失败保留输入并提示。
- 每次保存只修改所点任务实例；同名模板、其他日期、其他孩子及同系列任务不受影响。描述继续写入现有 `tasks.description`，孩子端任务卡和朗读使用该实例的内容。
- 柠檬任务 App 首页待完成列表移除常态及拖动中显示的整行拖动提示；保留整卡长按拖动、排序保存、朗读、打卡及空列表状态。
- 今日任务待完成及过期卡片的分类标签与左侧竖条共用同一不透明分类色。采用基于 Stitch 项目 UI 色卡并经 Pad 反馈调浅的十色；同一天最多十个可见分类颜色互异，按稳定分类键分配且任务排序不改变颜色。超过十类可能复用颜色；可见分类集合增删可能使部分已有分类换色。
- 不改柠檬认字 App。原有未跟踪图片资源与本需求无关。

## 依赖影响

- `shared`：家长端调用的单条任务描述更新接口。
- `supabase`：新建任务不从模板复制固定描述，并提供受控的单条描述写入能力。数据库迁移先于新版家长端发布。
- `kid-task-app`：现有任务卡和朗读继续读取每条任务实例的描述；本需求只改首页拖动提示的可见文字。

## 验收标准

1. 当前工作分支是最新柠檬任务开发分支；用户原有未跟踪文件未被覆盖。
2. 任务库不再出现描述输入或描述展示；新日程各任务描述初始为空，旧任务实例的描述保留。
3. 首页今日列表和日历所选日期列表均通过笔图标进入所点任务的编辑页，预填并可保存或清空当天描述；列表项点击不打开描述弹窗。过去或已完成任务的描述只读。
4. 同模板跨日期、跨孩子的任务可保存不同描述；更新其中一条不覆盖其他条，重复日程也不会批量覆盖；保存失败不丢失输入。
5. 家长端列表及孩子端任务卡、朗读使用当天实际保存的描述，重开应用后仍可读取。
6. 孩子端待完成列表标题下不再显示拖动提示行；整卡拖动和空列表状态仍可用。
7. 今日待完成及过期卡片左侧竖条与分类标签背景同色；最多十个可见分类不撞色，最终配色较首版十色更浅，非深色或近白色；任务重排不改变同一分类的颜色，朗读、打卡和描述展示不受影响。
