# 需求：家长端为奖励上传图片

- 需求编号/目录：`20261004-parent-app-reward-image-upload`
- 日期：2026-10-04
- 应用范围：`parent-app`；共享奖励模型、仓库与 Supabase 奖励图片数据/存储迁移归入本流程，依赖影响见下文。
- 提出人：用户
- 原始需求描述：「新建一个任务端开发分支，开发柠檬任务app，在新分支新增一个需求，我大概描述一下我的要求，我想在柠檬任务的奖励模块新增一个功能，在家长端可以上传奖励的图片，在柠檬任务app奖励模块就直接展示设置的图片」

## 背景与目标

家长目前只能为奖励选择预设封面标识，无法上传具体奖品照片。增加图片选择、上传、替换和移除能力，让同一家庭的奖励目录保存可由孩子端读取的图片引用。

## 范围与约束

- 家长在“我的 → 奖励管理”的新增/编辑奖励流程中设置一张可选图片；保存后管理列表和再次编辑时能看到当前图片。
- 图片与奖励归属同一家庭，只有本家庭家长能写入；本家庭已登录成员可读取，其他家庭和匿名访问不得读取。
- 未上传图片的既有奖励继续使用预设封面；停用、积分价格、兑换和历史规则保持现有语义。
- 图片上传失败不得把奖励记录更新为一个无法读取的图片路径；替换或移除图片时应处理旧对象。
- 图片能力依赖 Supabase Storage 和 `rewards` 表迁移，部署前须验证实际环境和权限策略。

## 非目标

- 不在家长端管理孩子的兑换、使用或退星。
- 不提供多图相册、裁剪编辑器或图片审核后台。

## 跨模块影响及其他应用

本流程负责家长端上传入口、共享 `Reward.imagePath` 字段及上传/签名访问接口、奖励表和私有存储桶迁移。`kid-task-app` 的大小心愿卡片展示由独立的[孩子端需求](../20261004-kid-task-app-reward-image-display/需求.md)处理；两端需独立设计批准、测试、安装及人工验收。此处的共享字段和存储策略是孩子端的前置依赖。

## 可验证的验收标准

1. 家长可以在新增和编辑奖励时选择一张图片，保存后列表与编辑页显示该图片；可替换或移除图片。
2. 图片格式、大小或读取失败时给出明确反馈，失败保存不产生失效引用；无图奖励仍可正常保存。
3. 本家庭家长可管理图片，本家庭已登录孩子可读取；跨家庭和匿名会话不能读取或写入。
4. 旧奖励不需迁移图片且继续显示预设封面；停用和兑换数据不因图片修改改变。
5. 自动测试通过后单独取得家长端安装确认，安装后等待家长端人工测试结论。

## 人工测试中的缺陷与最终验收

首次安装后，用户反馈从系统相册选取图片提示“选择图片失败：无法读取图片”。原因是尺寸探测启用 `inJustDecodeBounds` 后正常返回空 Bitmap，代码将此误判为读图失败。修复目标是让有效 JPEG/PNG 图片进入预览和保存流程，同时保留真实打开流失败、无效图片和解码失败的提示。修复仅涉及家长端本地处理；原有格式、尺寸、大小、上传与权限规则保持有效。

用户于 2026-10-04 批准缺陷设计，修复版通过自动测试并在再次取得安装确认后安装到手机。用户随后明确要求“缺陷和本次需求都标记为完成”，作为本次人工验收确认；用户没有逐项回报每个操作的测试结果。
