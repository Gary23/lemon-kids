# 家长端本地业务结构补齐设计

## 只读检查结论

- 本地服务位于 `/Volumes/pan/lemon-kids-local-supabase`，容器环境位于 `/Volumes/LemonKidsContainer`；本次目标仅 `supabase_db_lemon-kids-local`。
- Docker 检查核心容器健康；Postgres public 仅四张表：families、users、binding_codes、tasks。
- 已有 RPC 仅家长注册建家庭、绑定码及权限辅助函数。设备日志确认当前包 task_templates 查询仍因缺表失败。
- 当前 tasks 仅基础字段，需与现有任务日历、成长领域、日描述、计时调用逐项核对。不能仅补空表而保留失效的写接口。

## 范围和实施方案

1. 新增本地增量迁移与验证脚本，不重置数据库；先做字段、约束、函数和数据数量预检。以独立临时数据库/事务验证迁移及权限，完成后才请求应用到现有本地库。
2. 任务/分类域：建立 task_templates、categories、category_task_templates；补齐 tasks 的重复日程、成长领域、计时等当前字段。按当前接口实现分类改名、原子替换任务包、选择来源创建任务、日描述更新、成长修正和预览/回填、取消/恢复及受限永久清理 RPC。复用经审查的历史定义，剔除历史批量清表与清积分语句，保持家庭隔离。
3. 用时域：补齐 task_timer_sessions、task_duration_records 及查询平均值、任务库明细、删除明细的接口，按已有计时设计核对关联/触发器和积分依赖；共享给孩子端的结构只做兼容验证，不代表孩子端流程已验收。
4. 奖励/勋章域：补齐 rewards、必要的积分/兑换依赖、badge_progress 和审计；核对现有奖励目录约束、私有 reward-images 存储策略、set_badge_progress 乐观版本冲突语义。不插入虚构兑换和成长记录。
5. 日志/统计：补齐 device_status_logs 以及家长实际读取的 app_usage 等依赖，并核对家庭/孩子权限。设备未上报时显示合法空结果。实际菜单调用若仍缺外部 SCF/Edge Function，单列前提，不把空结果冒充外部服务调用成功。
6. 对现有核心表只做必要增量扩展，保留已有家庭/账号/任务 ID、内容、积分和会话。设计不授权生产迁移、不复制生产密钥/数据，不执行现有数据重置脚本。

## 验证与应用门禁

- 静态 SQL 解析、依赖检查、临时环境从核心基线升级及重复执行验证。
- 真实本地 Auth/JWT 与 PostgREST/RPC 验证：当前家庭正常读取，两家庭隔离，匿名拒绝，孩子不能执行家长写接口。
- 任务来源创建、关联替换、取消恢复、用时空汇总、奖励/勋章读写与冲突、私有图片路径验证；原核心服务合成验证回归。
- 自动验证通过后，列出迁移清单、预检结果与数据保护措施，请用户确认应用到当前本地库；数据库模块无 APK 安装步骤，以该确认作为部署确认。
- 应用后重新打开现有家长端本地包人工验收；若需要客户端修正，回到独立 parent-app 缺陷流程及设计确认。

## 风险与回滚

历史 SQL 有宽泛 RLS 和破坏性语句，必须按依赖选取重写。迁移使用事务、命名前缀和前置检查；失败回滚事务。已成功应用的迁移不通过删除现有业务数据回退，必要时提供兼容性修正。发现会改写已有业务数据的情况，先列明具体影响后请求确认。
