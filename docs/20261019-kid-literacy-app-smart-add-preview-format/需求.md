# 智能添加识字预览格式兼容

- 需求编号/目录：`20261019-kid-literacy-app-smart-add-preview-format`
- 日期：2026-10-19
- 应用范围：`kid-literacy-app`；依赖 `cloud-functions/evaluate-reading/` 的预览接口
- 提出人：用户

## 原始反馈

“同样的 app 代码装在不同的 pad 上，一台在智能添加识字日志正常，另一台 pad 每次日志都有问题。”两台 Pad 使用同一个账号，字库相同。正常请求生成“春”的一条任务；异常请求连续十次记录“‘春’的句子必须包含 text”，最后返回 HTTP 422。

## 背景与目标

客户端调用 `preview_literacy_tasks`，云函数按当前孩子字库构建 DeepSeek 提示词，再校验生成结果。现有校验要求句子为带 `text` 字段的对象；当模型返回其他形态时，预览直接失败。

目标是让模型返回可判定的句子文本时仍可通过严格内容校验并显示预览；返回无法判定的内容时给出准确错误与有限重试，避免把格式错误误报成“字库范围”问题。

## 范围与约束

- 仅处理认字应用的智能添加预览接口及所依赖的评测云函数；不改变其他应用、数据库和识字保存规则。
- 保持目标字、允许字符、词语和句子的字库约束；不把无内容或无目标字的句子作为成功结果。
- 不在日志中记录孩子身份、完整生成词句或 DeepSeek 原始响应。
- 修改部署源码后，按仓库约定生成新的可部署 ZIP，核对 ZIP 根目录并更新云函数 README。部署、安装和人工验收遵守项目门禁。

## 可验证验收标准

1. 对“春”，当 DeepSeek 返回 `sentence: {"text":"春天来了"}` 或 `sentence: "春天来了"`，且其余内容合规时，预览都返回一条可编辑任务。
2. 空句子、缺少目标字、含非法字符或超过两个字库外汉字仍被拒绝。
3. 所有尝试只因格式错误而失败时，客户端收到与生成格式相符的错误，不再收到误导性的“字库范围”提示。
4. 现有词句生成、重试和保存相关自动测试通过；目标 Pad 的人工预览结果由用户确认。

## 跨模块影响

`kid-literacy-app` 的“智能添加识字”入口依赖 `evaluate-reading` Web 函数；本需求预计只改云函数解析、错误信息、测试和部署说明，客户端接口字段保持不变。

## 补充需求：精简添加认字弹窗提示

用户于 2026-10-19 提出：“添加认字的弹出层，删除以下提示：‘每个字生成词语和句子......’这段提示语；‘以下汉字已在字库中，仍已生成内容.....’这段提示语。”本补充仅涉及 `kid-literacy-app` 弹窗展示，不改变预览请求、生成规则、字库判定或保存。

补充验收标准：打开“我的 → 智能添加识字”后，输入区不再显示“每个字生成词语和句子”说明；预览字库已有字时，不再显示“以下汉字已在字库中，仍已生成内容”汇总提示；对应任务卡的字库标记、其他任务状态提示，以及编辑、删除、保存仍正常。用户于 2026-10-19 确认补充需求及主需求全部人工测试通过。
