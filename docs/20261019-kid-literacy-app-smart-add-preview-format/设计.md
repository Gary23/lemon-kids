# 设计：智能添加识字预览格式兼容

## 问题分析

`kid-literacy-app` 把目标汉字发给 `preview_literacy_tasks`。云函数读取当前孩子的 `known_characters` 并把“字库字 + 本次输入字”传给 DeepSeek。用户确认两台 Pad 使用同一账号、同一字库；在同一目标字“春”的请求下，字库差异不能解释这两次结果。`textForExample` 只接受带 `text` 字段的对象；日志中的“‘春’的句子必须包含 text”发生在这里，早于目标字和字库内容校验。现有日志未记录响应形状，故不能断定模型实际返回的是字符串、数组还是缺失值；DeepSeek 独立调用的输出差异是当前更符合证据的解释。

重试时会带入上一轮被拒绝的 JSON，可能继续诱导相同格式。十次失败后固定返回“未能生成符合字库范围的词句”，与此次实际校验原因不符。

## 方案

1. 在 `cloud-functions/evaluate-reading/index.js` 的生成结果入口，允许句子为非空字符串或现有 `{text: 非空字符串}`，统一归一化为 `{text}` 后复用原来的目标字、字符集和字库校验。词语格式保持现有契约，不放宽保存接口对客户端提交数据的校验。
2. 对无法提取文本的句子继续拒绝。记录仅含目标字、失败类别和响应字段类型的诊断摘要，不记录原始词句或孩子信息；修复提示明确要求句子使用 `{text: "..."}` 结构，避免重试继续重复错误形态。
3. 保留每个字至多十次生成、总预算 65 秒的现有规则。最后失败时根据最后一个有效校验原因选择响应文案：格式问题提示“生成内容格式不正确”；字库越界仍提示字库范围问题。客户端继续通过原有错误弹层展示。
4. 在 `cloud-functions/evaluate-reading/test/` 增加预览接口测试：对象句子、字符串句子、缺失句子、无目标字句子、非法字符及字库越界；验证返回对象结构与错误类别。运行云函数自动测试。
5. 按部署约定生成 `evaluate-reading-web-20261019-smart-add-preview-format.zip`，用 `unzip -l` 核验根目录并更新 `cloud-functions/evaluate-reading/README.md` 当前包名。用户确认后部署并在异常 Pad 上人工验证。

## 影响与兼容性

- 客户端和 Supabase 数据结构不变；返回成功时仍为原有 `sentence: {text: ...}`。
- 云函数修改会影响所有使用同一生成器的预览入口；共用校验和测试覆盖帮助记录无历史词句时的回退路径。
- 不记录原始响应，若异常由非字符串或缺失句子造成，诊断仍只能识别形状，不能还原文本。

## 风险与回滚

接受字符串句子可能让更多模型输出进入内容校验；目标字及字库规则保持原样，防止无效内容写入。若部署后出现回归，可恢复前一部署包；数据库无需回滚。

## 验收与文档

以[需求](需求.md)中的四项标准为准。自动测试后等待安装/部署确认，目标 Pad 人工测试通过后，再核对并更新 `kid-literacy-app/docs/LEARNING-RULES.md` 与云函数 README 中长期有效的行为和部署包说明。
