# 设计

## 方案

以横向主容器承载固定横屏壳层，始终使用左侧导航栏；四个一级入口保持“今日任务、任务日历、奖励兑换、我的成长”。统一替换主题色、字体层级、圆角、卡片边框/阴影和按压态，抽取可在后续批次复用的导航、儿童摘要、按钮、状态徽章与任务卡组件。

`MainActivity` 的 `android:screenOrientation` 设为 `landscape`，锁定系统定义的主横屏方向。保留已有 `configChanges`，不新增运行时强制方向逻辑。取消按屏幕方向或宽度切换到底部导航的分支，以及今日任务的竖屏单列布局和预览；横屏首页保持进度与双列任务区，内容较多时可纵向滚动。

第二次补充设计将左侧菜单由 226 dp 收窄至 184 dp，四入口和选中态不变；为保持摘要可读，侧栏底部连续天数与积分徽章纵向排列。今日任务的待完成/已完成列按 1.25:0.75 分配，进度卡成为页面首个内容区，移除顶部时段问候、说明文案及右侧两个标签；侧栏底部摘要、任务卡积分与进度仍保留。待完成和已错过任务卡只使用横向排版，信息区弹性占宽，右侧固定 52 dp 圆形对号按钮，分别提供“完成任务”和“补做任务”的可访问名称。

积分位置缺陷修复在 `HomeTaskCards.kt` 的 `PendingTaskInfo` 中，将真实 `rewardPoints` 星形图标及 `+n 积分` 放在分类标签后，再显示可选的“已错过”状态。分类标签可收缩并单行省略，优先保持积分可见。移除底部积分及截止时间整行，即使 `dueTime` 有值也不在今日任务待完成/已错过卡片显示；数据字段和其他页面仍保留，不添加未来信息的占位内容。

首页读取现有 `HomeViewModel` 的真实 `todayTasks`、完成进度、积分、连续打卡和同步状态。任务卡按状态分组并保留确认完成、撤销、乐观更新、积分动效与全量完成庆祝；只增加视觉层和必要的 UI 派生状态，不改变仓库接口。

## 涉及模块

- `navigation/KidTaskNavGraph.kt`：固定横屏主壳层、184 dp 侧栏和入口文案。
- `ui/theme/`、`ui/components/`：设计令牌与复用组件。
- `feature/home/`：今日任务进度、两列任务区及已有交互的视觉承载。
- `ui/components/HomeTaskCards.kt`、`KidTaskShellComponents.kt`：任务卡圆形完成按钮、分类后的积分位置和窄侧栏底部摘要。
- `AndroidManifest.xml`：主活动的横屏方向声明。
- `src/test/`：方向声明和横屏任务布局验证。

## 数据与交互

`TaskRepository → HomeViewModel → TaskUiItem.rewardPoints → 今日任务卡顶部积分 → 右侧对号`；点击完成先展示确认，确认后沿用既有完成接口与乐观状态。已错过任务沿用原补做路径。奖励星数、连续天数来自现有状态，并保留在侧栏底部摘要；首页顶部不重复展示。设计稿中的盲盒仅在无真实解锁规则前以“即将开放”静态入口呈现，不写入任何数据。

## 风险与回滚

壳层改动可能影响导航状态保存；锁定横屏还可能影响登录/绑定、权限弹窗，以及被系统强制进入窄窗口时的可用性。184 dp 侧栏可能使入口文字拥挤，增宽待完成列会压缩已完成列；长分类名和“已错过”状态可能挤压积分。Pad 全屏人工检查四入口、两列、长标题与分类、积分、圆形按钮触控及确认弹窗。自动测试覆盖方向声明与布局数据。若不可用，可回退方向、侧栏宽度、列权重和卡片布局并重新验证。真实任务流程保持原 ViewModel 与仓库调用链。
