# 需求：柠檬认字大屏 Pad 布局适配

- 需求编号：`20261019-kid-literacy-app-large-pad-layout`
- 日期：2026-10-19
- 应用范围：`kid-literacy-app`
- 提出人：用户
- 原始需求：“柠檬认字 app 在不同尺寸的 Pad 展示的元素占比不同；大屏幕 Pad 上元素有点小。”经讨论，用户希望新增需求，按 Android 常规布局方案处理；以可用宽度合理调整元素尺寸，纵向内容可滚动，无须专门实现类似 CSS `rem` 的全局单位。

## 背景与目标

当前页面以固定 dp/sp 和内容宽度上限排版。首页内容上限 815dp、底部导航上限 342dp、字格宽度上限约 57dp；多个子页和弹窗也有限宽。窗口继续变宽时，新增空间主要成为留白，前景元素占比下降。

目标是在保留现有标准 Pad 视觉和操作的基础上，让更宽的横屏 Pad 上主要内容、汉字字格、卡片、页头、导航和弹窗适度变大，并保持清晰的排版与可操作性。

## 范围与约束

- 覆盖本应用首页、我的、待认识、已认识、字库、帮助记录、通过记录，以及本应用内的学习和业务弹窗；不修改共享模块提供的登录界面。
- 根据应用可用窗口宽度调整布局和尺寸；纵向内容可滚动。窄窗口继续使用当前换列、换行、滚动规则，大字体继续遵守系统字体设置。
- 保留真实数据、学习规则、操作流程和目前固定导航、固定练习槽位等交互约束；不修改接口、数据库、云函数及其他应用。
- 原有标准 Pad 约 1000×567dp 应用窗口作为初始基准；偏小的大 Pad 的实际窗口数据和截图用于校准最终放大幅度。
- 2026-10-19 已读取用户连接的大 Pad `HEY2-W19`：横屏物理分辨率 2560×1600px、密度 340dpi，系统窗口配置约 1205×721dp，字体倍率 1.0；首页截图已现场核对，任务区在窗口中显得偏窄。
- 遵循 [`docs/README.md`](../README.md) 门禁：设计明确批准后改代码；自动测试后取得安装确认；人工测试确认前不推送或标记完成。

## 验收标准

1. 与原标准 Pad 相比，大 Pad 上首页任务卡、字格、页头及底部导航的视觉占比明显改善，内容仍完整显示；任务卡保持既有双列规则，字格和按钮可点。
2. “我的”及五个独立子页的主要卡片、字格、列表和操作区在大 Pad 上同步适配，内容居中且不出现局部元素明显失衡。
3. 学习及业务弹窗在大 Pad 上大小合适；字词句练习的固定槽位、录音状态与操作位置保持稳定，关闭和确认操作可达。
4. 标准 Pad 的现有构图与主要尺寸基本保持；较窄窗口、系统大字体、长文案和较多数据可换行或滚动，不裁切关键操作；触控目标不低于 48×48dp。
5. 自动测试和构建通过后，在用户指定设备上分别核对标准 Pad 与大 Pad 的首页、我的、子页和弹窗，由用户人工确认。
6. “我的”五个独立子页（已认识、待认识、字库、帮助过的内容、通过记录）均可正常打开并返回，页头标题正常显示，不因布局缩放闪退。

## 人工测试中的缺陷归并

小 Pad 首次安装后，用户反馈“我的页面的子菜单，点击后闪退了”。设备日志两次记录 `IllegalArgumentException: Cannot perform operation for Unspecified type`，指向共用页头 `GardenTitle` 对未指定行高做倍率乘法。缺陷仅影响本应用的页面标题绘制；修复后应保持标题字号随宽度适配、未指定行高自动排版，并在小 Pad 与大 Pad 验证子页与返回操作。用户已确认本次需求及缺陷全部测试通过。

## 跨模块影响

仅修改 `kid-literacy-app` 的布局、组件和应用文档；不修改 `shared`、其他应用或数据服务。
