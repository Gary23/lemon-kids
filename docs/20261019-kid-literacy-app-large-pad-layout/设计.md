# 设计：柠檬认字大屏 Pad 布局适配

## 问题分析

Compose 的 `dp`/`sp` 保持元素的逻辑尺寸，不会自动随屏幕尺寸同比放大。现有首页 815dp 内容限宽、342dp 底部导航限宽和约 57dp 字格上限，以及“我的”与子页 632～790dp 等限宽，让大屏增加的宽度主要成为留白。背景图使用 `Crop` 铺满窗口，进一步放大了前景元素偏小的观感。现有设计按约 1000×567dp 应用窗口校准过，因此需保留该窗口的既有构图。

2026-10-19 实测大 Pad `HEY2-W19`：横屏 2560×1600px、340dpi，系统窗口配置约 1205×721dp，字体倍率 1.0。已查看当前首页截图：四张任务卡居中排成两列，内容区两侧有明显留白，下方到固定导航之间也有较大空白。首页 815dp 的限宽仅占该窗口宽度约 68%；在约 1000dp 基准窗口中则约占 82%。342dp 导航在这台设备上约占窗口宽度 28%。截图仅用于布局比例核对，具体安全区由运行时 Compose 约束确定。

## 方案目标与范围

以应用安全区内的可用宽度作为主要输入，为本应用定义“标准、宽、大”三个布局范围；标准范围沿用当前尺寸，宽和大范围逐步提高各页面的内容宽度上限，并适度提高字格、卡片、页头插画、导航和弹窗等主要元素尺寸。具体阈值和增幅先按基准窗口推导，再用用户提供的目标大 Pad 实际窗口和截图校准，避免只凭物理英寸或像素分辨率估算。纵向溢出使用现有滚动容器承载。

不改变横屏方向、全局设备密度、系统字体倍率或共享登录界面；不对整页施加统一 `graphicsLayer` 缩放。保持页面结构及真实数据展示。

## 布局规则

1. 在安全区内测量实际可用宽度，以约 1000dp 为标准 Pad 基准。宽度不足基准时维持现有换列、换行和滚动逻辑，不额外缩小触控目标。宽于基准时采用有上限的连续增长或分档尺寸；初始目标倍率为 `(可用宽度 / 1000dp).coerceIn(1.0, 1.35)`。该倍率是主要尺寸的设计参考，不是整个页面的强制统一变换。按大 Pad 约 1205dp 的窗口宽度粗算倍率约 1.20，首页内容上限可从 815dp 提高到约 980dp，导航从 342dp 提高到约 410dp，字格上限从 57dp 提高到约 69dp；最终以安全区测量及卡片实际可用宽度为准。
2. 首页内容上限、任务卡内部字格上限、页头和底部导航共同随宽度增长；首页仍始终两列，单卡最多六字且不足六字不拉伸。卡片内边距、文字和插画按内容实际容纳情况调整，避免只增大外框。
3. “我的”资料卡、统计卡、六个入口以及五个独立子页分别放宽当前内容上限，并同步调整卡片或字格的内部元素。列数按可用内容宽度和系统字体倍率判断；长内容仍滚动。
4. 学习弹窗及其他应用内弹窗按可用宽高限制外框和内部尺寸。练习行共用的星位、文字、按钮和提示槽同步调整，保证各朗读状态不改变布局；内容超过可用高度时在既有区域滚动，关闭和底部操作保持可达。
5. 尺寸下限遵守 48×48dp 触控目标；文字继续使用 `sp` 并尊重系统字体缩放。背景图片继续铺满窗口，必要时只调整对齐或裁切，不拉伸原图。

## 涉及文件与影响

- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/LemonLiteracyApp.kt`：各页内容上限、卡片、字格、页头、导航及业务弹窗尺寸。
- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/ui/components/GardenLayout.kt`：提取和测试宽度档位与尺寸计算。
- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/ui/components/GardenComponents.kt`、`StudyDialogFrame.kt`、`StudyPracticeRow.kt`：共享页壳、页头、弹窗和练习行适配。
- 必要的本应用布局单元测试，以及人工验收后 `kid-literacy-app/README.md`、`kid-literacy-app/docs/UI-SPEC.md` 的现行布局说明。

数据流、接口、权限、存储与其他模块均不变。

## 风险、验证与回滚

- 过度放大可能使某些横屏 Pad 首屏内容变少；保留纵向滚动，验证 4:3、16:10、16:9、窄窗口和大字体场景。
- 字体与容器增长幅度不同可能造成截字；按容器可用空间测量，检查长姓名、长词句及操作按钮。
- 弹窗内部固定槽位若只改部分尺寸会产生位移；练习行在准备、录音、评测和结果状态下核对布局稳定性。
- 自动验证包括尺寸计算单元测试、`:kid-literacy-app:assembleDebug`、`:kid-literacy-app:lintDebug`、`:kid-literacy-app:testDebugUnitTest`；安装和实机比较遵守项目门禁。
- 回滚仅恢复本应用布局尺寸和组件参数，无数据迁移。

## 人工测试缺陷修复设计与结论

小 Pad 首次实机测试发现“我的”子菜单闪退。原因是 `GardenTitle` 将主题未指定的 `lineHeight`（`TextUnit.Unspecified`）直接乘以布局倍率。经用户明确批准，修复为只缩放已指定行高；未指定行高保留给 Compose 自动排版，标题字号仍随倍率缩放。核查其余新增文字倍率计算，没有同类未指定行高算术。修复范围仅为 `GardenComponents.kt`，不改变布局档位、数据或页面入口。修复版在两台 Pad 安装后，用户确认本次需求及缺陷全部测试通过。

## 待用户确认的设计决策

- 大 Pad 的主要内容随可用宽度适度增大，初始倍率上限 1.35；当前 `HEY2-W19` 的首页截图支持先按约 1.20 倍校准宽度与主要元素。实现后如实机显示仍偏小或过大，在执行中以该设备校准，不改变“标准 Pad 基本保持”的原则。
- 覆盖本应用全部主要页面和应用内弹窗；共享登录界面不在此次范围。
- 纵向内容增加时允许滚动，保留既有导航和弹窗操作可达性。
