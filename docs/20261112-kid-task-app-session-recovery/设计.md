## 代码分析

1. `shared/.../SupabaseModule.kt` 已配置自动加载、保存及 `alwaysAutoRefresh`，但不能据此保证 SDK 在系统休眠、刷新失败后永远维持有效业务会话。
2. `SupabasePomodoroRepository` 三个读写接口直接请求，无请求前有效性门禁，认证失败也不通知 `SessionRecoveryCoordinator`。所以「点击重试」可能反复沿用无效认证。
3. `SupabaseTaskRepository.completeTask/undoCompleteTask` 直接 RPC；`isSessionValid()` 只判断 session 非空而不判断过期。`refreshTasks()` 无条件手动刷新、吞失败后继续通知拉取，没有将失败接到任务端根层恢复。
4. `AuthViewModel` 与任务端根层已经具有恢复弹层及本机 task 绑定码恢复能力，但任务/番茄链路运行中未接入恢复通知。
5. `HomeViewModel.confirmTaskDone` 在写入前增加积分并播放成功动画，失败只回滚状态和积分，不设置 actionError；日历失败也缺少可见原因。这是独立且已从代码确认的反馈缺陷。
6. `SupabaseAuthRepository.restoreSession` 有自己的 Mutex，但手工 refreshTasks 刷新不共锁；应减少无条件刷新，并将本次新增请求恢复统一去重，不能宣称应用 Mutex 可以约束 SDK 内部所有刷新。

## 修复目标与范围

仅处理柠檬任务的两条故障链，复用现有登录恢复 UI；不重新设计视觉、不改数据库、计时语义或积分事务。

### A. 任务端请求认证门禁

- 在共享层增加可注入、可测试的任务端请求会话保护/恢复封装，由任务端包名（包含 local）精确启用；其他应用维持原有行为。Task/Pomodoro Repository 接入，不将 Supabase 数据访问搬进 UI。
- 请求前等待初始化，检查会话存在与有效期；临近过期/已过期时受互斥保护刷新，再重新检查当前身份和认证状态。普通有效请求不无条件刷新。
- 多个并行请求复用同一次恢复结果；设置有限超时，不无限阻塞加载，也不跨账号恢复后重放旧账号操作。
- 请求被明确的 JWT 过期/无效认证错误拒绝时，至多尝试一次受控恢复并重试；区分普通权限拒绝、业务错误、网络错误，不对任意 401/403 做无限刷新。
- 先自动检查并尝试恢复会话；缺失会话、刷新凭证不可恢复或恢复后仍认证失败时通知现有 `SessionRecoveryCoordinator`，完全沿用柠檬认字的根层恢复机制：不可被返回键/点击外部关闭的弹窗，两个主操作为「重试刷新」「使用绑定码登录」。普通离线故障不强迫孩子重新绑定。
- 「重试刷新」调用共享 AuthViewModel.retrySessionRefresh，显示进行中状态并禁用重复操作；成功关闭弹窗并刷新业务数据，失败保留弹窗及可理解的错误信息，允许再次尝试。
- 「使用绑定码登录」与认字端一样调用 restoreSavedBindingCodeFromDialog，使用本机保存且已验证的 task 绑定码静默重新登录，不增加实际输入页。失败时保留恢复弹窗提示原因。不卸载、不清除应用数据、不删除番茄待同步队列。
- 参考 `kid-literacy-app/.../LemonLiteracyApp.kt` 的根层 SessionRecoveryDialog 与共享 AuthViewModel，但不修改认字端。2026-11-12 23:43 用户明确要求「完全按照柠檬认字app的恢复逻辑」，取代上一版真实输入流程决策。
- 所有路径传播 CancellationException；取消、退出或账号变化后不继续旧请求。
- `refreshTasks()` 在任务端使用相同门禁，避免每次回前台都无条件轮换 token；不擅自更改其他端刷新策略。

### B. 认证恢复后的数据重拉

- 同一孩子恢复成功后重新拉取任务与番茄数量，并重试本机待上传记录；不能仅清除弹层却留下旧错误。
- 保持番茄现有 sessionId 幂等、上传回执核验及聚合归并规则；保留现场 3 条未同步记录，不删除或伪造已同步标志。
- 检查恢复弹层层级，确保番茄弹窗打开时仍能操作登录恢复；只做必要的状态/层级接线，不重做界面。

### C. 任务失败反馈与成功时机

- 首页与日历的完成/撤销都展示脱敏、可理解的失败提示，复用已有错误展示能力。
- 保持乐观卡片反馈，但失败恢复准确的原状态与积分；成功得星效果只在确认写入成功后触发。实际确认入口按 taskId 防重复提交，finally 清理进行中标记；多任务并发时不能用某个操作的旧总积分快照覆盖其他成功结果，失败后补拉权威任务/积分。
- `complete_task` 并非可任意重放的写入：只有明确认证拒绝、请求未进入业务 SQL 时才允许上述一次重试；超时、响应丢失和普通服务错误不盲目重试。必要时只读核验任务状态，不能重复加星。

## 预计涉及文件/模块

- `shared`：新增任务端会话保护及测试；SupabaseTaskRepository、SupabasePomodoroRepository、SupabaseAuthRepository；AuthViewModel 仅补任务端启动刷新清空 session 后仍保留恢复弹窗的判断。沿用 ChildBindingStore 包名判断与 SessionRecoveryCoordinator。PomodoroRepository 三接口增加 expectedChildId 作为本地请求归属校验，不改变 RPC 参数；仅任务端调用该接口，其他应用不新增行为。
- `kid-task-app`：HomeViewModel、CalendarViewModel，及必要的 PomodoroViewModel/PomodoroHost、根层恢复完成接线；对应单元测试/设备测试。
- 长期文档：人工验收后更新 `kid-task-app/README.md` 的认证恢复、任务失败反馈与番茄同步行为，以及 `shared/README.md` 的任务端恢复边界。无新数据库部署时不改 SQL 文档。

## 自动测试计划

- 有效 token 不刷新；过期/缺失会话；明确 JWT 拒绝后只恢复及重试一次；恢复失败通知根层。
- 并发恢复去重、超时、离线、权限/业务错误不误判、取消传播、切换账号不重放。
- 番茄读取/上传/核验三个接口均经过门禁，恢复后待同步队列仍按 sessionId 合并，不重复计数。
- 首页及日历完成/撤销：成功更新、失败提示及状态积分回滚、不播放假成功效果。
- 执行 `GRADLE_USER_HOME="$PWD/.gradle-system" ./gradlew :shared:testDebugUnitTest :kid-task-app:testDebugUnitTest :kid-task-app:assembleDebug`；按最终共享签名影响补充依赖应用编译。
- 无法通过单元环境覆盖的真实 SDK/系统驻留行为记录为设备人工项，不把模拟测试当作已完成长驻实测。

## 设备人工验收（安装须另行许可）

1. 保留应用数据覆盖安装到已连接平板，查看读取错误是否消失，3 条历史待同步是否真实入库；若仍被暂停兼容约束拒绝，则另报真实服务错误，不宣称全部恢复。
2. 用户选择一项实际需完成的任务打卡，刷新及重开后仍在已完成，积分只增加一次；日历同样验证。
3. 长驻前台跨凭证有效期、锁屏/后台恢复后读取与完成正常；断网写入有提示，联网可重试。
4. 模拟不可恢复会话时在番茄弹窗上仍可进入恢复；账号切换后不沿用前一孩子状态。

## 风险与回滚

- 共享代码影响其他应用：以精确包名隔离及依赖编译防回归，不打包安装其他应用。
- 网络错误误判为登录失效：只用明确认证状态/错误类型，不用任意字符串或全部 403 触发重登录。
- 并发/切换账号导致重复写：有限重试、身份校验、保留服务端幂等与只读核验，不对未知响应重放。
- 回滚只回退本次代码与 APK，不回退/删除孩子任务、积分、本机待同步记录；安装和降级均须用户批准。
