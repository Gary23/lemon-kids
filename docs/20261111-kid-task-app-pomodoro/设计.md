## 2. UI 参考与视觉规格

### 2.1 参考来源及限制

遵循[应用 UI 参照约定](../../kid-task-app/README.md#L60-L62)：优先 Stitch MCP。本会话未提供该工具，无法获取新的目标截图与 HTML；以现行 Compose 页面和本地 UI 参考制作原创番茄钟设计稿，**不是 Stitch 输出**。本地 UI 与现行应用布局冲突时以现行横屏应用为准；该例外已获用户执行指令确认。

### 2.2 今日任务入口

- 原神秘盲盒位置整体替换为白底圆角胶囊按钮：左番茄图标，右两行“番茄钟”“今日收获 N 个”，末尾进入箭头。
- 入口触控范围不小于 48 dp。统计用珊瑚红，不把番茄数和任务完成率、积分混为一谈。
- 运行中第二行替换为“专注中 · mm:ss”或“休息中 · mm:ss”，同时保留小号“今日 N 个”标签；等待下一轮显示“休息完成 · 开始下一轮”。
- 任务为空或任务加载失败不阻塞番茄钟入口，番茄数据独立加载。

### 2.3 近全屏弹层

- 遮罩覆盖包括左侧导航在内的整个应用，禁止穿透点击。横屏参考 1024×768，弹层约可用宽 94%、高 92%，四周至少 16 dp 安全距离，圆角 32 dp；尊重系统安全区。
- 顶栏：番茄图标 +“番茄钟”+“一次专注，一点成长”；右侧浅红“今日收获 🍅 N 个”统计胶囊、同步状态、关闭按钮。
- 主体为整幅倒计时区域，不再左右双栏。圆环随可用空间放大，表盘内删除番茄及其他装饰图标，仅显示当前“任务时间”或“休息时间”及 mm:ss；阶段说明与动作放在表盘外。
- 时长设置默认隐藏，顶栏“时长设置”按钮打开覆盖计时主体的面板；面板包含两组快捷选项和“完成设置”按钮，完成后隐藏并返回计时视图，不启动计时。等待下一轮时调整设置仍保留等待状态。运行中设置入口禁用，提醒未停止时先处理提醒；面板开启时阻止操作下层计时控件，关闭后恢复焦点。选中项有文字/勾选及实色背景，不仅靠颜色区分。
- 默认专注 25 分钟、休息 5 分钟。快捷项分行排列，统一显示分钟单位；配置按账号保存在本机，下轮沿用最近设置。
- 计时区主按钮：准备态“开始专注”；专注/休息运行时提供次操作“结束本轮”。一轮休息也结束后，轮次动作仅保留“下一轮”，不显示且不允许触发“结束本轮”；时长设置仍通过顶栏入口打开，到点提醒仍有独立停止按钮。
- 提醒条位于计时区下方且保持可见，文案区分“专注完成，已开始休息”和“休息结束，准备好再出发”；醒目按钮“停止响铃和震动”。按钮停止两个提醒通道，不停止休息也不自动开始下一轮。
- 收起、返回键只隐藏弹层，不结束计时；若正在响铃，关闭动作会先停止声音和震动再关闭，不把提醒留到后台继续响。遮罩点击不关闭。
- 可用高度不足时主体滚动或缩小表盘，顶栏关闭、提醒停止和核心动作保持可达；设置始终为覆盖层，不退回并排或常驻下方布局，不新增竖屏产品形态。
- 圆环进度按真实经过时间连续绘制，不以每秒离散比例直接跳变；数字按秒更新且等宽，阶段切换重置圆环不造成错误倒放。尊重减少动态效果偏好；读屏只在阶段变化播报，不逐秒打断。提醒、状态、未同步均有文字，避免仅依赖颜色。

- 加粗圆环：SVG 240×240 坐标下描边由 8 调整为 14，背景轨道同宽。专注按剩余比例着色：>50% 舒缓绿 `#20b271`；25% < 比例 ≤50% 提醒黄 `#d9a400`；≤25% 紧张红 `#f2564f`。进度与时间数字共用颜色变量，颜色以 250ms 同步过渡，减少动态效果时取消过渡；阶段文字同步提示，不只靠颜色。休息及等待使用海洋蓝 `#1a8fd1`。整套配色按用户“更浅、更鲜亮”要求调亮：绿、黄为纯色相中白底可读的较浅档，黄在纯亮黄会失去对比度，故取金黄的折中；数字为 52–86px 粗体，绿/黄对比度约 2.7/2.3，红/蓝约 3.4/3.6；若预览觉得发虚，优先加深黄档而不是加大字号。
- 等待态“下一轮”不再因提醒置灰；点击显式开始下一轮时顺便停止旧提醒。独立停止按钮仍只停提醒。无提醒时隐藏提醒条，避免无效灰色按钮。
- 原型只展示产品界面，删除演示台、加速/暂停控件、页脚说明、演示提示及虚构已同步标记；使用正常 1 倍时间。原型仍为内存样例，无数据库、真实音振和后台保证；正式应用已接入真实计时、同步状态和前台服务。

### 2.4 日历

- 日期格保留左上日期及右上状态点；底部左侧增加 12 dp 番茄图标 + 10–11 sp 数字，右侧保持得星。
- 0 个时不显示番茄角标，日期详情仍显示“当日番茄 0 个”；未知/读取失败不得假装 0。
- 计数超过两位用“99+”，选中日期摘要显示完整数量；必要时把格子增至 72 dp，窄列让番茄与星星分两行，不重叠。
- 日期选择、月份切换和“今天”行为不变；无任务但有番茄的日期也显示计数，不改变原任务完成状态点。
- 日期详情标题下增加浅红“🍅 当日番茄 N 个”。月度统计的既有演示数据不作为番茄来源。
- 月历查询包含网格可见的月初/月末补位日期；补位格维持现有不可点行为，降低透明度，不把别月计数算入当前月。

## 3. 交互状态机与计时语义

以 `phase`（设置/专注/休息/等待下一轮）和独立 `alert`（无/专注结束/休息结束）建模，避免把提醒停止误当作阶段切换。

| 当前状态 | 事件 | 行为及下一状态 |
| --- | --- | --- |
| 设置 | 开始专注 | 固化本轮时长和唯一 ID；当前轮仅保存在内存，不写本机快照，进入专注 |
| 专注 | 到点 | 原子生成一次完成事件；立即转休息；启动铃声与震动，提醒类型为专注结束 |
| 休息 + 专注提醒 | 停止提醒 | 同时停音与停振，仅清除提醒；休息仍按原截止点继续 |
| 休息 | 到点 | 进入等待下一轮；停止旧提醒资源后启动休息结束提醒，不能两个铃声叠加 |
| 等待 + 休息提醒 | 停止提醒 | 停音停振，仍等待；“下一轮”一直可用，不因提醒禁用 |
| 等待（有/无提醒） | 下一轮 | 始终可点；先停音停振并清除旧提醒，再生成新轮 ID，进入专注；重复点击不重复开轮 |
| 准备/等待 | 打开、完成时长设置 | 打开覆盖面板，完成后隐藏；保留原阶段和历史数，不自动开跑；等待态仍显示“下一轮” |
| 等待 | 结束本轮 | 无此入口；状态机拒绝此事件，因为本轮已经结束 |
| 专注/休息 | 结束本轮 | 二次确认；停音停振及调度，返回设置；未完成专注不计数，已完成番茄不删除 |
| 任意 | 收起/重新打开弹层 | 不更改内存中的计时阶段和截止时刻；显示同一轮，不重复创建 |
| 任意 | 退出 App（返回键/划掉任务/进程结束） | 当前轮随进程结束，不保存、不恢复、不补算、不补响；重开为准备态 |

### 时间与进程边界

- 计时以本机 UTC 截止时间为事实，每 200ms 的 tick 只刷新展示并触发阶段推进；不使用 `AlarmManager` 精确闹钟。
- 休息起点固定为专注的计划结束时刻，而不是用户点停止或应用恢复时刻，保证 25+5 的轮次在开始后 30 分钟结束休息。
- 收起弹层、切换 Tab、切后台、锁屏不重置计时；前台服务只用于让后台计时和响铃尽量自然继续，系统冻结或回收时自然停止，不做补偿。
- 当前轮只存在于内存，不写入本机存储；退出 App 即结束当前轮。重新打开只读取设置、已完成记录和数量缓存，不恢复阶段、不补记完成、不补响。
- 系统时间被手动修改会影响按 UTC 截止时间计算的剩余时长；本轮不额外拦截系统改时。
- 关闭 App 前已经完整结束的专注属于历史记录，保留在本机和远端，不因退出回滚。

### 提醒

- 两个阶段结束均触发本地铃声循环与震动模式。应用内及通知上提供同一“停止响铃和震动”动作，幂等释放音频、振动及通知提醒资源；通知仍可保留阶段状态。
- 在用户停止前维持提醒，但受 Android 后台、音量、勿扰、硬件能力约束；不绕过勿扰或伪称能必然发声。
- Android 13+ 在应用启动时请求通知权限；拒绝后前台服务通知可能不可见，应用内提醒和计时仍可用，不把权限拒绝显示为数据库或提醒已成功。
- 如果专注结束提醒一直未停止，休息仍按时结束，提醒切换为休息结束，保留一个停止按钮。

## 4. 计数与数据库设计

### 4.1 统计口径（已确认）

完整专注结束即 +1，与休息是否完成、任务打卡和积分无关。`completed_at` 按专注计划结束时刻，不按上传时刻；`completed_date` 使用 `Asia/Shanghai`。23:50 开始的 25 分钟专注归次日；23:55 专注完成而休息跨日则归前日。

数据库是已同步记录的事实来源，本地只保存已完成记录作为离线待上传队列，不保存进行中的计时。今日/选中日的“展示总数”是已同步唯一记录与本机待同步唯一记录的并集；界面显示待同步数量。网络确认后不再加一次。

### 4.2 数据契约（已部署）

新增 `pomodoro_completions`，一段完整专注一条，不保存可由客户端任意修改的累计数。

| 字段 | 约束/用途 |
| --- | --- |
| child_id | 当前孩子 UID；引用 users，由服务端从 auth.uid() 确定 |
| session_id | 客户端生成 UUID，一轮固定；与 child_id 组成唯一键 |
| family_id | 服务端从用户资料推导，不接受客户端任意传入 |
| focus_minutes | 只能为 10/15/20/25/30/35/40 |
| break_minutes | 只能为 3/5/10/15 |
| started_at / completed_at | timestamptz；专注开始/计划结束；约束时长一致、不能将未来完成写入 |
| completed_date | 服务端按 completed_at 转上海日期生成 |
| received_at | 数据库收件时间，离线补传仍保留原完成日期 |

索引 `(child_id, completed_date)`，按日聚合 `count(*)`。不直接改 `tasks`、积分表和既有任务 RPC，不与旧计时表共用生命周期。

已部署 RPC：

- `record_pomodoro_completion(session_id, focus_minutes, break_minutes, started_at, completed_at)`：校验已登录孩子身份、白名单时长、起止一致及未来时间；幂等插入。重复相同载荷返回同一记录，重复 ID 不同载荷报冲突，不覆盖原记录。
- `get_pomodoro_daily_counts(from_date, to_date)`：读取本人日期区间的每日计数，限制单次范围不超过 62 天；返回权威日期和数量。客户端请求不可指定其他 child_id。
- 客户端上传后重新拉取日期区间聚合；只有聚合成功才把已被服务端接受的记录标为已同步，避免“上传成功但拉取失败”时数量先增后减。

权限：RLS 默认拒绝；孩子只能读取本人记录，客户端不能直接 insert/update/delete；写入仅经受控 RPC。函数固定安全 search_path、限定 execute 授权并校验 auth.uid() 角色，匿名/家长/其他孩子不可代写。新增接口不默认向家长端开放。离线端上计时属于客户端上报事实，不作为防作弊证据，故不接入积分奖励。

### 4.3 本机持久化与离线

本机按“孩子 + 环境”隔离保存设置、已完成记录和远端数量缓存；进行中的计时只存在内存，不写快照、不做 outbox 之外的恢复。完成记录与设置写在同一个 JSON 文档中，写入使用同步提交；上传采用同一 `session_id` 重试，服务端唯一键保证重复提交不重复计数。

- 加载：显示“加载中/—”，不先展示 0。
- 成功无数据：今日和弹层显示 0，日历角标隐藏。
- 离线：保留最近数量缓存，显示待同步数量，仍可开始新计时。
- 查询失败：保留旧数并显示同步错误；无缓存时不显示虚假 0。
- 上传失败：保留本机记录并显示待同步，允许刷新重试，不阻塞计时。
- 退出 App：当前轮结束，未完成专注不计数；已完成记录留在本机，后续登录同一账号继续补传。
- 账号/环境切换：待同步记录留在原命名空间，不提交到新账号；已同步记录重新登录后可恢复。
- 卸载/清除数据会丢失未同步记录；已同步记录以数据库为准。
- 多设备各自独立轮次，不承诺互斥；合并统计以 `session_id` 去重，进入页面、完成后或手动刷新时拉取，不承诺实时同步。

## 7. 风险、兼容与回滚

- Android 提醒能力受权限、厂商电源管理和勿扰影响；后台只按系统能力自然运行，不保证所有机型准点。
- 生命周期或重复回调可能重复入账：本地 `session_id` 去重 + 服务端唯一键双重保护。
- 新客户端依赖新 RPC：数据库不可用或网络失败时显示“记录服务未就绪/待同步”，本机数量仍展示，不假装已入库。
- 采用加法迁移，旧客户端不受影响；回滚客户端时保留已完成记录表，停用番茄入口及服务，不删除历史数据，不恢复旧任务计时系统。
- 生产数据和权限以部署时目标环境审查为准。

## 10. 执行实现说明（2026-11-11）

- 计时以内存中的 UTC 截止时间为事实，前台 `specialUse` 服务保持进程，每 200ms 刷新展示并推进阶段；未接入 `AlarmManager` 精确闹钟。设备深度休眠或厂商强制停止时提醒可能延后。
