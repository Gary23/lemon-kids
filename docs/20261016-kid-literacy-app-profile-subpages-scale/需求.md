# 需求：柠檬认字“我的”入口页面尺寸对齐

- 需求编号：`20261016-kid-literacy-app-profile-subpages-scale`
- 日期：2026-10-16
- 应用范围：`kid-literacy-app`
- 提出人：用户
- 原始需求：“柠檬认字app，从‘我的’页面的菜单入口进入的页面，这些页面进入后页面要素的尺寸全部与效果图不对应，看上去比效果图大了很多，你需要调整一下这些页面的尺寸”

## 背景与目标

此前“我的”主页已单独校准，但从该页进入的二级内容仍使用较宽的通用布局和偏大的固定尺寸。按仓库现有 A02–A06 效果图及逐页元素清单，逐页校准标题、统计与工具区、内容容器、字格或记录卡、按钮及留白，让标准 Pad 上的视觉比例接近效果图。

## 范围与约束

- 范围：五个独立页面“待认识的字”“已认识的字”“字库”“帮助过的内容”“通过记录”；第六个菜单入口“智能添加识字”为弹窗，按 A07 检查其外框及主要元素尺寸并纳入同一应用流程。
- 保留真实数据、查询、排序、导出、删除、置顶、发音标注、智能添加及返回行为；不变更接口、云函数、数据库和其他应用。
- 标准 Pad 以 1536×1024 效果图与现有实机安全区换算为依据；窄窗口、大字体、长内容允许自适应和滚动，点击区域须可用。
- 遵循 [`docs/README.md`](../README.md)：设计获明确批准后才能改代码；自动测试后取得安装确认；人工测试确认前不推送或标记完成。

## 验收标准

1. 从“我的”进入五个独立页面，主要元素的宽高、间距和首屏信息密度与各自 A02–A06 效果图接近，不再显得整体放大。
2. “智能添加识字”弹窗对照 A07 核对并校准外框、标题、输入和操作区的比例；内容可滚动且键盘出现时可操作。
3. 各页面的真实数据、空态、错误态和原有操作仍正常；长文字、字体放大及较窄窗口不裁切关键信息或操作。
4. 自动验证完成后按门禁安装到用户指定设备，由用户逐页对照效果图人工确认。

## 跨模块影响

仅涉及 `kid-literacy-app` 的界面代码与其文档；没有跨应用或数据依赖修改。

## 人工测试期间的补充需求与缺陷
