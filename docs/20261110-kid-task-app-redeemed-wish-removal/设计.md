# 设计：兑换后移除正在攒星星的心愿

## 问题分析

RewardScreen 直接用 snapshot.rewards.firstOrNull { it.isFeatured } 选出大心愿，并将其余奖励放入小心愿区。服务端兑换只生成记录、扣星，不删除目录，因此已兑换心愿会持续出现。只隐藏大卡而不调整小心愿筛选，还可能使该心愿落入小心愿列表。

## 方案及数据流程

1. 在 kid-task-app 的 reward 功能目录提取可单测的展示筛选逻辑，输入 RewardSnapshot。
2. 对 isFeatured 大心愿，当前孩子存在同 rewardId 的 HELD 或 USED 记录时不展示，CANCELLED 不计入；此规则不依赖 repeatable，保证配置为可重复的大心愿也不会持续出现。
3. 对非 repeatable 的大心愿，同时检查 unavailableOneTimeIds，覆盖家庭其他孩子及既有一次性名额占用。
4. 从未被排除的大心愿中选取展示对象；小心愿列表仅取非 isFeatured 奖励，已隐藏的大心愿不得降级进入小心愿区。没有可见大心愿时，标题和卡片整体不渲染。
5. RewardScreen 使用统一筛选结果；RewardViewModel 的 confirmRedeem 同步拒绝已移除的大心愿，避免旧页面事件再次触发兑换。
6. 沿用兑换后重新读取服务端快照的逻辑，不乐观删除数据。刷新或重启重新依据快照计算。取消后快照不再存在有效占用时自动恢复展示。
7. 兑换历史不筛除，原有使用、取消、扣星和退星行为保持不变。可重复的小心愿兑换后继续展示；非大心愿的一次性奖励保持原有展示与禁用规则。

## 交互、兼容与非目标

- “删除心愿”仅指移除兑换区展示，不做家庭目录的物理删除或停用，避免丢失历史及影响其他孩子。
- 不改变视觉样式、尺寸、配色、图片和导航，本次仅修复数据可见性，不开展视觉重设计；不需要新增 Stitch 屏幕设计。
- 旧版流水没有可靠关联时，不根据标题猜测；一次性占用沿用现有服务端名额事实。
- 不新增实时订阅，其他设备变化在现有刷新时机生效。

## 验证方案与验收

- 单元测试：未兑换大心愿可见；HELD/USED 后隐藏；仅 CANCELLED 时恢复；家庭一次性名额占用时隐藏；可重复大心愿在本人兑换后隐藏；可重复小心愿始终保留；被隐藏大心愿不落入小心愿区；无大心愿及多条记录边界。
- 计划命令：`./gradlew :kid-task-app:testDebugUnitTest :kid-task-app:assembleDebug`，执行后记录真实结果。
- 自动测试后停止询问是否安装到指定设备，不提前安装。
- 安装后人工验证兑换、刷新重进、重复小心愿、历史使用与取消恢复；用户明确验收通过前不推送、不标记完成。
- 具体验收标准见需求.md。

## 风险与回滚

- isFeatured 与 repeatable 是独立字段，需按展示角色判断大心愿，而非单凭一次性字段。
- 服务端快照失败时沿用原有错误和重试机制，不把请求成功猜测为完整事实。
- 页面隐藏不改变服务端兑换权限；本次不把可重复大心愿改为服务端一次性奖励。
- 回滚孩子端展示筛选及其调用即可恢复原行为，服务端无数据变更。
