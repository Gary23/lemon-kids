# 需求：兑换后移除正在攒星星的心愿

- 需求编号：20261110-kid-task-app-redeemed-wish-removal
- 日期：2026-11-10（Asia/Shanghai）
- 应用范围：kid-task-app（柠檬任务）
- 提出人：用户
- 开发分支：fix/lemon-task-redeemed-wish-20261110，基于本地 develop 创建。

## 原始需求

> 基于develop分支创建一个柠檬任务开发分支，分支名结尾标注今天日期，解决一个问题，兑换奖励页面，正在攒星星的心愿兑换后应该删除这个心愿，不要持续存在，随时可兑换的小心愿才需要一直存在

## 背景与目标

奖励页目前直接显示目录中的大心愿，兑换后仍然持续出现。目标是已兑换的大心愿不再出现在兑换区，可重复兑换的小心愿继续展示。

## 约束、依赖与非目标

- “删除”拟解释为从孩子端兑换区移除，不删除家庭奖励目录、图片、积分流水或兑换历史，待用户设计确认。
- 复用 shared 提供的 RewardSnapshot、本人兑换记录及家庭一次性奖励名额；不修改共享接口、家长端或数据库。
- 不调整界面样式、布局、扣星退星事务或权限。
- 保留当前未使用兑换可取消、取消退星后恢复一次性名额的规则。
- 遵循设计确认、自动测试、安装确认及人工验收门禁。

## 验收标准

1. 大心愿兑换成功并取得服务端快照后，不再显示卡片及其所属空标题，也不会落入小心愿区。
2. 待使用和已使用的有效兑换均阻止该大心愿继续展示；刷新、离开再进入和重启后规则一致。
3. 对配置为可重复兑换的大心愿，也按当前孩子的有效兑换记录移除；家庭一次性大心愿被其他孩子兑换后，同样不展示。
4. 取消未使用兑换后，若没有其他有效兑换且目录仍启用，心愿恢复展示；已使用记录不可取消。
5. 可重复兑换的小心愿兑换后继续展示，积分足够时可再次兑换；普通一次性奖励仍保留原有名额限制，不扩展本次范围。
6. 兑换记录及使用、取消入口继续正常工作；兑换失败或结果未确认时不凭本地猜测移除心愿。
7. 自动测试覆盖筛选边界，构建通过；安装和人工验收分别取得明确确认。
