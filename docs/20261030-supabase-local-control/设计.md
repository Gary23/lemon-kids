# 本地控制台改造设计

## 问题分析

`scripts/service-control.py` 固定 `PROJECT='local-supabase-service'`，Supabase 命令在通用项目根目录运行。`web/index.html` 的入口仍使用 54321–54324。`command()` 丢弃 stderr，超时和异常统一返回 None；`status()` 用布尔值把这些情况归为未运行。前端每五秒发起检查，单页面虽有限流，后端多个请求仍可重复创建检测进程。

## 管理目标与文件范围

- 后端：`/Volumes/pan/lemon-kids-local-supabase/scripts/service-control.py`。
- 前端：同目录下 `web/index.html`、`web/app.js`、`web/style.css`。
- 测试：在外接盘项目中新增控制台专用测试目录，避免依赖真实启停或数据库写入。
- 文档：`本地控制台-使用说明.md`；核对 `apps/lemon-kids/README.md` 中控制台入口及服务管理说明，仅同步有效使用方法。
- 双击入口路径和 8765 端口保持不变；如无需修改入口脚本则保持原文件。

## 启停流程

1. 固定 `PROJECT='lemon-kids-local'` 和专用工作目录 `ROOT/apps/lemon-kids`，启动前核对配置中的 project_id。所有 Supabase 启停命令显式传入该工作目录，避免依赖控制程序当前目录。
2. 启动顺序保持外接盘检查、挂载映像、按需启动 Colima、等待 Docker 就绪、按需启动 Lemon Kids；不得启动通用项目。不使用查询超时推断 Colima 已停止；不确定时等待有限重试，仍不确定则结束操作并展示原因，不自动强制停止虚拟机。
3. Supabase 启动命令完成与健康检查通过分开展示。已有容器 running 但 unhealthy 时明确显示异常，不标记整体正常。
4. 停止时只对 Lemon Kids 运行 Supabase stop，不传不保留数据参数。随后检查 Docker 内是否还有其他运行容器：没有时停止 Colima；存在时保留共享运行环境，并说明；无法检查时也保留 Colima、报告状态未知。
5. 后端保持单一启停任务互斥；动作完成后触发新探测。明确的命令失败、超时分别记录，不把历史缓存用于跳过必要检查或继续不确定的停止操作。

## 状态接口与缓存

`/api/status` 增加固定项目元信息、每项结构化状态、查询错误和最近成功观察。现有页面是唯一已知调用方，前后端同步更新；若保留布尔字段，未知时使用 null，前端不得将 null 当 false。

| 状态 | 含义及证据 |
| --- | --- |
| 检查中 | 尚未完成首次检测或新检测正在进行 |
| 运行中/就绪 | 当前成功查询证明已运行，Supabase 的预期容器均就绪 |
| 未运行/未挂载 | 成功查询明确证明停止、缺失或未挂载 |
| 启动中/部分运行/异常 | 成功查询得到真实容器状态，例如 health starting、unhealthy 或部分退出 |
| 状态未知 | 查询超时、执行失败、解析失败、控制台断连或上游无法确认 |

- 每项保存当前探测状态、检查时间、最近成功观察状态和时间、错误分类与简短详情；容器列表也保留最近成功快照。
- 成功观察包括明确停止、异常及不健康的真实查询结果，“成功”指查询成功，不等于服务健康。
- 历史观察只在页面作为“上次确认：…（时间）”展示；当前未知时不会继续显示绿色运行中。首次失败显示尚无成功记录。
- 查询失败时不清空已有容器快照，标注其历史时间；某项恢复成功后更新该项快照、移除该项错误。
- 上游未知时，下游显示无法确认；上游成功证实停止时，可明确显示下游不可用并说明依赖。
- 缓存在控制台进程内，不落盘保存密钥或状态；重启后重新建立历史记录。
- 用单一后台探测/受锁保护的共享刷新合并并发查询，检测周期不重叠；HTTP 请求返回已有快照和检查中标志。保留现有约五秒刷新体验，但不让多窗口轮询重复生成检测任务。
- 命令检测有明确超时，Docker 容器查询仅针对精确项目后缀；非零退出不能一概解释成未运行，结合可识别的停止信息判断，否则报未知。

## 页面与诊断

- 页面标题和容器区域明确“Lemon Kids 本地服务”，入口改为 54423/54424，API/DB 改为 54421/54422。
- 保留外接盘、运行映像、Colima、Docker 概览，标明 Colima/Docker 为共享环境；只列出 Lemon Kids 容器。
- 状态卡分别显示当前状态、最近成功观察和时间；未知使用提示色。增加查询诊断区域，按组件列出原因和检查时间。
- 启停执行记录保留独立区域，标明动作及结束时间；旧操作失败不代表当前服务失败。
- 捕获命令退出码、stderr/必要 stdout 摘要和超时类型；限制展示长度，过滤令牌、密钥、密码和连接串等敏感内容。不运行会输出完整密钥的 supabase status 命令。
- 前端 fetch 设时限并防重入，断连时显示未知但保留最近数据；操作状态未知时禁止可能冲突的操作，重新取得有效状态后恢复按钮。
- 保留仅本机监听、Host/Origin/令牌校验、CSP、固定命令和 textContent 渲染，不增加任意命令执行入口。

## 测试与交付

- 后端模拟子进程验证正确工作目录和项目、通用服务不被操作、停止不删除卷、其他容器存在/查询失败时保留 Colima、超时不触发强制重启。
- 验证首次失败、成功后超时、上游未知、恢复、健康状态变化、缺失容器、错误输出脱敏及缓存并发行为。
- 前端验证未知/历史状态、查询错误与操作错误区分、正确链接和按钮行为；语法检查及隔离端口下页面预览。
- 自动测试不得实际启停现有服务或写入业务数据。通过后向用户报告结果并取得替换正在运行的控制台/重启控制台确认。
- 获准后重启控制台使修改生效，先做只读实时核对；由用户人工验证页面与启停行为，确认前保持测试阶段，不提交推送或标记完成。

## 风险、回滚与非目标

- 外接盘 USB 断连仍会导致服务不可用，本次正确报告原因，不迁移映像或调整硬件、电源设置。
- Colima 为共享资源，停止流程避免误停其他运行容器；不管理、不迁移通用项目的数据。
- 外接盘源码不在 Git 仓库内，实施前备份将修改的文件到时间戳目录，记录路径；回滚恢复这些文件并经确认重启控制台，不回滚数据库。
- 不加入自动 force-stop、自动重建、自动删除、数据库迁移或自动重启循环。
- 不修改各 Android 应用业务功能；控制台项目名称和端口从固定元信息一致生成，避免页面与命令再次分离。

## 设计确认

- 用户已于 2026-10-30 明确批准：“批准，开始执行，执行完之后告诉我手动测试步骤”。按本设计实施；替换运行控制台前仍需交付确认。
