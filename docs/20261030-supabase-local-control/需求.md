## 背景与目标

一套 Colima/Docker 环境内存在两个独立 Supabase 项目。Lemon Kids 使用 `lemon-kids-local`，API 端口为 54421；通用项目为 `local-supabase-service`，API 端口为 54321。通用项目当前已停止，其容器和数据卷保留。

现有控制台的容器筛选、Supabase 启停命令和页面入口仍指向通用项目。后端把命令超时和异常转换为 false，前端据此显示未运行；执行操作时又丢弃错误输出，无法判断实际原因。

本次统一控制台管理对象为 Lemon Kids，正确表达运行、停止、异常、检查中和未知状态，保留带时间的最近成功观察结果，显示可用于排障的错误。

## 约束与依赖

- 控制台地址保持 `http://127.0.0.1:8765`，维持仅本机访问及现有 Host、Origin、令牌校验。
- 使用外接盘现有 Colima、Docker 和 `apps/lemon-kids/supabase/config.toml`，不创建第三套服务。
- 不改动数据库业务结构、账号、客户端配置，不删除任何项目容器或数据卷，不迁移磁盘。
- 通用项目不得由控制台启动或执行 Supabase 停止命令；Colima 是两套项目共享的运行环境，停止它会影响其他运行容器，界面和操作应体现此边界。
- 查询缓存仅作为历史观察，不能冒充实时结果或作为不确定状态下强制重启的依据。
- 自动测试完成后，更新正在运行的控制台前需取得交付/重启确认，仍须用户人工验收，不自动推送。

## 验收标准

1. 启动全部服务只使用 Lemon Kids 工作目录，通用项目保持停止；重复点击或重复请求不创建并行启停任务。
2. 状态和容器列表只包含 Lemon Kids 项目，页面明确项目名和 API 54421、DB 54422、Studio 54423、邮件 54424。
3. 停止操作只对 Lemon Kids 执行 Supabase 停止命令并保留数据；停止共享 Colima 前检查其他运行容器，存在其他容器或无法确认时保留 Colima 并解释原因。
4. Colima、Docker、容器查询超时或执行异常时显示未知及具体原因；仅有明确停止证据时显示未运行，不将上游未知传播为下游已停止。
5. 某项查询失败时保留其最近成功观察与时间，并标注历史；首次查询失败说明没有成功记录。查询恢复后显示当前结果并清除对应查询错误。
6. 健康检查 starting/unhealthy、容器缺失、部分停止和全部停止能够区分；容器已运行不等于整体健康。
7. 展示查询错误与启停错误，并带时间；命令失败能提供经脱敏、截断的诊断输出，历史操作失败不覆盖当前服务状态。
8. 多次轮询不叠加大量检测子进程；后端探测和前端请求均有时限，网页断连也不抹去历史状态。
9. 自动验证覆盖目标隔离、状态转换、缓存、错误显示和启停边界；人工验证控制台状态、入口及启停流程。

## 跨模块影响

只修改外接盘的控制台及其说明和测试。Lemon Kids 各 Android 应用、共享模块、云函数、业务数据库均不改动。本仓库本目录保存该独立模块的需求流程材料。
