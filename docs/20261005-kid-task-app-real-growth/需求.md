# 需求：柠檬任务“我的成长”演示数据真实化

- 需求编号：20261005-kid-task-app-real-growth
- 日期：2026-10-05
- 应用范围：`kid-task-app`
- 提出人：用户

## 原始需求

> 柠檬任务app在我的页面有很多演示数据，现在需要把这些演示数据变为真实数据，但是现在从需求到后台都没有方案，需要你先给我一个具体方案这一块如何实现，主要侧重点在产品这一块内容如何设计

> 关于勋章，你设计一下一般小学生都需要哪些勋章，给我设计一个体系名称，勋章在不同等级阶段应该也有不同名称

> 高频勋章每月约 20–25 次，次高频勋章每月约 10–15 次；去掉运动、艺术，科学改为数学思维。孩子当前一年级，希望总等级与勋章约在五年级到顶，覆盖小学六年；每天约 10 个任务，同时勋章升级不能过慢。

> 四个太阳能否再合成一个什么标志？

> 2026-10-05 补充：重新规划勋章，认字和默写各 3000 字、成语 256 个、英语单词 1800 个、迪诺英语 437、古诗词 155 首、思维启萌 211；阅读、数学讲题、数学计算、写作、劳动与自理按小学六年的指定频率设置阶段；英语阅读按 A～Z 的逐级指定数量升级。「这些勋章都取消关联任务库的任务，改为我手动输入修改。」高效英语与思维火箭暂不制定等级。

## 背景与目标

“我的成长”当前混合真实资料、真实星星余额和固定演示统计、等级、勋章、里程碑。先明确孩子能理解、家长能核对、服务端能稳定计算的产品规则，再按批准的设计实施真实数据接入。所有成长成果只属于当前绑定的孩子账号。

## 本次方案范围

- 真实展示成长摘要、按任务实际得星换算的经验值、覆盖小学阶段且五年级前后可由四太阳合成终点标志的总等级，以及由家长手动维护进度的分级勋章；各勋章线有独立门槛与阶段名称。保留头像、昵称、计划、使用限制、切换账号。
- 本批次完整实现等级、勋章和成长足迹的数据及展示；勋章先用与各勋章线对应的临时本地图标，同一勋章线的各等级复用图标，由真实等级名称和进度区分。
- 规定完成任务、撤销、家长驳回、奖励使用、无数据、加载失败和账号切换时的显示规则。
- 设计 `kid-task-app` 使用的共享数据读取接口及 Supabase 聚合能力，记录其依赖影响。

## 非目标

- 不把口算正确率、晨读内容、整理书包、专注时长、班级、家长点赞等未采集行为声称为已完成。
- 不让经验值成为可兑换货币，不发放额外星星，不改变现有任务和奖励规则。
- 家长端手动录入由独立的 `parent-app` 补充流程处理；本流程不改日历页或其他应用。其他页面的演示数据如需真实化，另立需求与设计确认。
- 本批次不制作各等级专属勋章图片，也不接入 Supabase 勋章图片存储与加载；后续生成图片并放到 Supabase 的方案另立需求。

## 验收标准

1. 当前孩子的资料与星星余额保持真实；其余数值都能按文档规则由当前孩子的服务端记录复算。
2. 完成、撤销、驳回任务后，任务摘要和 EXP 按任务事实更新；手动勋章只随家长录入/更正更新；已取消奖励不计入有效成就。
3. 没有历史数据时展示零进度和引导，不出现预置的等级、勋章或故事；加载失败不得以 0 冒充真实结果。
4. 切换账号后不残留前一个孩子的数据；任何读取只允许访问本人数据。
5. 15 条勋章线显示对应的临时图标，等级、名称和进度来自真实规则与记录；临时图标不表示某一级已有专属图片。
6. 设计批准、自动测试、安装确认、人工测试和文档同步分别遵循 `docs/README.md`。

## 依赖与跨模块影响

任务端依赖 `:shared` 仓库接口、Supabase 家长端受控写入及孩子端只读策略。家长端勋章进度写入归入 `parent-app` 补充流程，孩子端读取与展示归入本流程；双方分别设计确认、测试和验收，部署顺序先家长端数据能力、后孩子端成长页。已有任务领域数据不会作为勋章进度来源。

## 人工验收后的最终补充与缺陷结论

2026-10-06 用户明确要求本需求、全部补充需求和缺陷均改为已完成，作为本次人工验收通过结论。下列最终规则覆盖前述较早的展示验收描述：

1. 顶部四张统计卡只显示标题和真实数量，数值不带单位；姓名不可在成长页编辑。头像使用孩子资料，圆形头像置于黄色圆角座中，并有等级角标。姓名旁显示当前等级称号，下面显示当前勋章称号及今日任务打卡情况。侧栏底部姓名左侧也使用当前孩子头像与等级角标。
2. 等级卡上方显示黄色 `Lv.N`、当前等级图标和名称，以及单行“当前成长值 X / Y EXP”；真实进度条位于其下，“下一级：Lv.N 名称（还差 N 经验升级）”位于进度条下方。满级不虚构下一等级；成长纪念卡入口已移除。
3. 勋章馆每个有正数累计进度的勋章类型最多显示一张等高卡，零进度类型不展示；有进度但未达到首级的类型仍可见。类型卡展示升至下一门槛的进度条，保留分类筛选。顶部与馆内数量按已获得的**等级阶段枚数**统计，一条六级勋章线满级计六枚。卡片不显示“已点亮”文案；点击类型卡后弹层列出该类型全部等级的名称、门槛、临时图标及已获得/未获得状态。逐等级专属图片及 Supabase 图片托管仍留后续需求。
4. 最近成长足迹最多取 10 条，默认显示 3 条，可用箭头展开剩余最多 7 条及收起。当前页面足迹日期按上海时区显示为 `yyyy-MM-dd`；勋章类型卡和详情不显示更新时间，因此不会暴露原始时间串。时间解析规则仍支持合法带偏移时间，无法解析时不回退原始值。
5. 成长页整体视觉按 Stitch 的“平板横版：我的成长与成就中心（灵动微交互版）”调整，顶部外层为白色卡片，黄色用于头像座和等级标志等局部装饰。以上调整仅影响 `kid-task-app`，不改变家长端录入、服务端门槛及接口。
