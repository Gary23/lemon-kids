# 需求：柠檬认字花园风格 UI 重构

- 需求编号：`20261013-kid-literacy-app-garden-ui-redesign`
- 日期：2026-10-13
- 提出人：用户
- 应用范围：`kid-literacy-app`，Android 孩子端柠檬认字 App。
- 原始需求：根据 `/Users/yupengjun/lemon-kids/kid-literacy-app/design-concepts` UI，重构柠檬认字 App 的 UI 样式，先出设计。

## 背景与目标

现有应用采用浅色 Compose 卡片，启动页锁定竖屏。参考目录已提供十张横屏效果图、v3 交付说明、分层画板、场景背景、插画、控件和字体资源。本次需要形成可实施的 UI 重构方案，确认后将现有界面统一为参考稿的花园、麦田、书架场景风格。

目标：

1. 以横屏平板为主，统一场景背景、柠檬吉祥物、奶油白面板、大汉字、彩色立体按钮及双入口导航。
2. 覆盖认字首页、我的、待认识、已认识、字库、帮助记录、通过记录，以及智能添加、发音标注、朗读练习和结果状态。
3. 补齐源稿中没有单独交付的认字首页设计及真实加载、空数据、失败、键盘和长内容状态。
4. 保留真实数据、学习规则和接口行为，保证朗读状态切换不跳位、满星即时隐藏操作且保留槽位。
5. 本轮交付需求、设计和状态文档及首页布局示意，等待用户明确批准设计。

## 范围与非目标

- 范围：本应用的主题、页面、弹窗、资源接入、布局组织和横屏适配。共享登录界面沿用共享模块；本应用的加载和会话恢复外壳统一样式。
- 非目标：新增学习能力、调整星数或学习周期、变更缓存/分页协议、修改接口或数据表、重做共享登录模块、其他应用 UI、云函数部署、修改 App 图标。
- 本轮不创建执行待办，不改应用代码，不构建安装，不提交推送。

## 约束、依赖与数据边界

- 遵循 [需求开发流程](../README.md)：设计批准后才能执行；自动测试后取得安装确认；安装后等待人工测试结论；验收前不得推送或标记完成。
- 视觉依据为 [安卓 UI 交付稿](../../ui-design/kid-literacy-app/design-concepts/安卓UI交付稿.md) 和 [开发资源 v3](../../ui-design/kid-literacy-app/design-concepts/安卓UI开发资源/README.md)。文字、数字、星数、日期及按钮必须用原生组件绑定真实状态。
- 业务依据为 [学习规则](../../kid-literacy-app/docs/LEARNING-RULES.md) 与已实现的数据流。旧 [UI 规范](../../kid-literacy-app/docs/UI-SPEC.md) 中与代码不一致的字库分页描述，在设计中明确列出，人工验收后同步纠正。

## 验收标准

1. 应用以横屏平板呈现，16:10 主验收，同时检查 4:3、16:9、窄横屏和字体放大。
2. 十张参考画面的对应页面/状态及补齐的首页统一采用设计主题；背景、吉祥物和主面板关系与参考一致。
3. 所有完整页面和业务弹窗可纵向滚动且无可见滚动条，末尾操作可达，弹窗拦截底层触摸，键盘不遮断保存/添加动作。
4. 所有按钮触控目标至少 48×48 dp；长姓名、长词句、大数量及安全区不会遮挡必要操作。
5. 认字任务分组、点击学习、点读求助、星数、手动通过、置顶与存库保持既有规则；录音、评测、错误、满星等状态不改变练习项槽位和滚动位置。
6. 字库保留本地缓存读取、手动全量更新、当前缓存搜索与按序号导出；发音标注保留逐资产保存；通过记录保留各学习项快照、撤销、删除及清空。
7. 自动验证覆盖构建、静态检查和关键布局/交互；取得安装确认及人工测试通过后，按最终验收更新应用文档并推进完成。
