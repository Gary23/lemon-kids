# 家长端“我的”菜单加载异常处理设计

## 问题分析

当前分支为 feature/lemon-task-development。静态检查发现：

- SupabaseTaskTemplateRepository.observeTemplates、SupabaseCategoryRepository.observeCategories / observeCategoryTaskTemplates 在查询失败时记录日志后重新抛出异常。
- TaskTemplateManageViewModel 初始化直接 collect 模板流，未处理异常。
- CategoryManageViewModel 并行 collect 分类、模板、关联流，均未处理异常；任一子任务失败可能取消同级加载，并传播至未处理的 ViewModel 协程，引起进程退出。
- RecycleBinViewModel、DeviceStatusLogViewModel 也存在直接收集数据流的入口，需要纳入同类检查。
- supabase/LOCAL_REVIEW.md 明确本地基线并非完整业务 schema，因此缺表、缺 RPC 是可能的触发条件；网络、权限和反序列化失败也可能触发。

目前 adb devices 未发现连接设备，未取得真实崩溃堆栈。上述是已确认的异常处理缺口，具体运行时触发错误仍待核实，不能将缺表作为已证实根因。

## 方案与交互

1. 在家长端 ViewModel 的加载边界处理上游 Flow 异常和身份加载异常，正确传播 CancellationException；不用全局吞异常的方式掩盖问题。
2. 任务库增加独立的列表加载错误状态及重试入口；列表请求与平均用时请求隔离，平均用时失败不阻止模板列表显示。
3. 分类管理为分类、模板、分类关联分别记录加载和错误状态，隔离并行失败。已获取数据继续展示；初次加载失败不展示“还没有分类”。依赖模板或关联尚未成功时，不允许配置任务包或执行需要完整关联数据的操作。
4. 无有效用户/家庭时停止加载并显示家庭信息不可用提示。失败提示使用简明文案，详细异常保留在日志；服务不完整时明确反馈加载失败，不伪造空数据或成功状态。
5. 重试取消并替换对应加载 Job，重新订阅数据；避免重复轮询和事件订阅。退出页面沿用 ViewModel 生命周期取消任务。
6. 检查“我的”页其他菜单的入口加载链，只修复同类未处理异常及必要的错误/重试展示，不扩大业务范围。

## 涉及文件与兼容性

- parent-app/.../feature/profile/TaskTemplateManageScreen.kt：ViewModel 加载与页面状态。
- parent-app/.../feature/profile/CategoryManageScreen.kt：并行加载、依赖可用性和页面提示。
- parent-app/.../feature/profile/RecycleBinScreen.kt、DeviceStatusLogViewModel.kt、DeviceStatusLogScreen.kt 及其他经检查存在同类问题的 profile 入口：异常处理与恢复。
- parent-app/src/test/：异步加载失败、取消、并行隔离和重试测试；必要时增加协程测试依赖。
- parent-app/README.md：人工验收后核对菜单的数据加载失败、重试和本地服务依赖说明。

沿用现有仓库接口和数据模型，不修改共享实现、不修改数据库、不改变权限规则。发现必须补齐数据库能力时，单独建立 supabase 流程。

## 验证

- 使用可控失败数据源验证请求失败不会成为未处理异常，加载状态终止且错误可见。
- 验证并行某项失败不会取消已正常加载项，重试可恢复，连续重试不重复订阅，取消不显示错误。
- 运行家长端单元测试及本地测试包构建；连接设备后只读取并核对真实崩溃日志。
- 获安装确认后测试正常进入、断网进入、服务能力缺失、恢复重试和返回；最终等待用户人工验收。

## 风险与回滚

异常处理不能补齐缺少的业务表和 RPC，服务不完整时对应功能仍可能不可用，但应明确提示。多数据源恢复可能引入重复订阅，需通过 Job 管理和测试约束。回滚仅撤销本缺陷新增的家长端改动，保留已有计时管理及其他未提交修改。
