# parent-app 本地 Supabase 登录与家庭接入需求

- 日期：2026-10-22
- 应用范围：`parent-app` 的本地调试接入；受影响共享 Auth/DI 和 Supabase 基线归入本流程，其他 Android 应用另行处理
- 提出人：用户
- 原始需求：执行通用 Supabase `TODO.md` 的 App 接入章节，接入本机 Lemon Kids；本流程是首个应用的登录、家庭、孩子绑定码路径

## 目标与边界

在明确选择的本地调试构建中，家长端只连接 `lemon-kids-local`，可用合成账号注册、登录、创建家庭并生成孩子绑定码。发布构建继续使用线上配置；不向 APK 放入高权限密钥。家长端其余任务、奖励、闹钟、诊断页面的业务迁移和完整使用另开同应用后续流程，不能把核心 Auth 验证解释成全应用完成。

## 依赖与约束

- 依赖 `docs/20261022-supabase-local-lemon-kids-integration/` 的独立本地项目、核心基线与合成验证。
- `shared/di/SupabaseModule.kt` 和 `SupabaseAuthRepository.kt` 当前固定线上 URL/key；共享模块改动影响五个应用的构建，必须验证无参数构建与发布构建仍指向线上。
- 家长端现有注册、建家庭操作分步调用；本地 RLS 必须防止用户自行修改角色、家庭和积分。
- 不覆盖工作树中其他任务的未提交变更；自动测试后、安装前须再次获得安装确认，人工验收前不推送或标记完成。

## 验收标准

1. 明确的本地调试构建参数生成 `parent-app` APK，静态检查其 Supabase URL 和公开客户端 key 均来自 `lemon-kids-local`；无参数及发布构建仍使用既有线上项目。
2. 模拟器 `10.0.2.2:54421` 或指定真机局域网地址可访问本地 Auth/REST；注册、登录、创建家庭、生成与查询绑定码成功，重启 App 后会话仍可恢复。
3. 家长不能通过客户端修改自身角色、积分或加入未知家庭；匿名、孩子和跨家庭访问按本地 RLS/RPC 拒绝。
4. 安装和人工测试按本仓库门禁逐步确认；其他业务页面未接入状态在交付说明中明确。

## 当前人工验收范围

用户明确选择固定使用已有演示账号，本轮不要求人工测试新账号注册、创建家庭和添加孩子；这些路径不作为本轮人工验收通过项。用户另明确不测试绑定码生成，固定使用已有绑定码 `334752`。保留本地登录、会话恢复、演示家庭与孩子查询、已有绑定码查询及本地地址配置的验收；生成操作不记为人工测试通过。

## 本地服务地址设置：需求归并记录

### 家长端本地测试包可设置服务地址

- 日期：2026-10-23
- 应用范围：`parent-app` 本地调试包；共享 Supabase 环境读取归入本应用流程
- 提出人：用户
- 原始描述：「但是电脑的wifi也不一定是每次一样，我认为应该在测试包增加一个输入ip:端口的输入框来设置」

## 背景与目标

当前真机测试包使用 `127.0.0.1:54421`，需要 ADB 反向转发。电脑在不同 Wi-Fi 下可能获得不同 IP。让测试人员在手机上填写电脑当前的 `IP:端口`，通过同一 Wi-Fi 直接连接本地 Supabase，地址变化时可重新设置。

## 范围与约束

- 输入框仅出现在显式 `localSupabase=true` 构建的家长端；普通 debug 和 release 保持线上配置及既有包名。
- 只接收本机回环或私有局域网 IPv4 地址及合法端口，输入转为 `http://IP:端口`；公开 anon key 仍由构建配置提供，不在手机上编辑。
- 地址保存在本地调试应用的私有存储；切换时必须使 Supabase SDK、仓库和会话使用同一新地址，不得出现新旧地址混用，也不得回退线上。
- 依赖电脑与手机网络互通、宿主机端口可达；本地数据库迁移及其他应用不在本次范围。

## 验收标准

1. 本地测试包启动时可查看和编辑 `IP:端口`，输入错误有明确提示；保存后使用输入地址请求 `lemon-kids-local`，重启 App 后地址仍在。
2. 在同一 Wi-Fi 下，不连接 USB 且不执行 `adb reverse`，用 `demo@local.test` / `12345678` 登录本地账号，并能读取其家庭及基础数据。
3. 电脑 IP 改变后可重新输入并继续连接；目标服务不可达时给出网络错误，不切换线上。
4. 普通 debug 和 release 的地址、密钥及现有登录流程保持不变；手机安装和人工测试继续遵循主流程门禁。


## 登录页地址设置入口：需求归并记录

### 登录前无法重新打开本地服务地址设置

- 需求编号/目录：`20261022-parent-app-local-auth/缺陷`
- 日期：2026-10-23
- 应用范围：`parent-app` 本地 Supabase 调试包；沿用已批准的共享环境地址配置
- 提出人：用户
- 原始反馈：「从我的页面打开，岂不是如果没有设置正确就无法登陆了，无法登陆怎么到我的页面」

## 背景与目标

当前本地测试包每次启动先显示地址设置页，但进入登录页后，只有登录成功才能从「我的」再次打开。若登录时发现地址需要修改，只能退出并重启应用。应在登录前直接提供重新设置地址的入口，使测试者能从登录失败状态恢复。

## 范围与约束

- 本地调试包的家长登录页显示「本地服务地址」入口，点击后返回现有地址设置页。
- 地址校验、健康检查、持久化、切换时清除旧会话和重启进程沿用已批准的补充设计。
- 普通 debug、release 登录页不出现该入口；不修改生产环境配置、数据库或其他应用。
- 该缺陷在补充需求的测试阶段发现，完成自动测试后需重新取得安装确认与人工测试结论。

## 验收标准

1. 本地包在未登录、登录失败时均能从登录页打开地址设置页并修改地址。
2. 地址不可达时仍可修改重试；改为可达地址后能返回登录页并登录。
3. 本地包重启后仍可从启动页编辑地址；普通 debug 和 release 不显示该入口。

## 跨模块影响

复用 `shared` 已有的 `SupabaseEnvironment` 地址配置与客户端重建流程；无新增共享模块改动或其他应用改动。
