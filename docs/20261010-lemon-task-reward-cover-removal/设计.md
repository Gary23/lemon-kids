# 设计：奖励取消预设封面

## 问题分析

家长端 `RewardManageScreen.kt` 在奖励列表、编辑器和保存草稿中使用六种 `coverKey` 选项，`RewardManageViewModel.kt` 对所选键做校验并保存。柠檬任务端 `RewardScreen.kt` 按 `coverKey` 选择预设图片，无对应图片时显示礼物表情。`rewards.cover_key` 是非空且有限定值的现有字段，直接删除会破坏保存链路及旧客户端兼容性。

## 目标与实现方案

### 家长端

1. 删除新增、编辑弹窗的“预设封面”标题及六个选项。草稿不再包含 `coverKey`，移除“请选择有效的封面”校验。
2. 新奖励写兼容值 `gift`；编辑奖励沿用既有 `coverKey`。共享 `Reward`、仓库 DTO 与数据库约束保持原样。
3. 列表图片区优先显示上传图片；无图片、地址待签名、签名失败或解码失败时显示固定大小的浅灰色背景，不绘制预设图标。失败时保留“图片重试”。
4. 编辑弹窗继续显示本地选中图片及已保存图片。图片读取失败时改为“当前图片读取失败”，保留重试；没有图片时不显示预设封面，可用浅灰色预览区域标识图片位置。

### 柠檬任务端

1. 大心愿和小心愿共用的 `RewardImage` 底层统一为 `#F2F2F2` 浅灰色背景；删除预设图片和礼物表情分支，不再按 `coverKey` 选图。
2. 上传图加载成功后覆盖背景，继续用现有内存 `Painter` 保持同图片路径刷新时的画面。路径变化或移除时清空旧画面，由浅灰色背景承接；签名或首次加载失败时也显示该背景。
3. 保持卡片尺寸、圆角、角标、名称、价格、兑换按钮和历史记录布局。现有签名与刷新行为原则上沿用；若实现中发现新旧路径状态不匹配，再在本需求内修正。

## 涉及文件与跨模块依赖

- `parent-app/src/main/java/com/lemonkids/parent/feature/profile/RewardManageScreen.kt`：移除选择入口、调整列表及编辑预览。
- `parent-app/src/main/java/com/lemonkids/parent/feature/profile/RewardManageViewModel.kt`：草稿、校验与兼容字段保存；相关草稿测试按新结构调整。
- `kid-task-app/src/main/java/com/lemonkids/kidtask/feature/reward/RewardScreen.kt`：大小心愿卡片调用点与共用图片区。
- `RewardViewModel.kt`、`shared` 与 Supabase 数据结构预计无需修改。两个应用都依赖现有 `Reward.imagePath`；`cover_key` 继续存储，但不再用于新版界面展示。

## 风险、兼容与回滚

旧客户端仍可能根据 `cover_key` 展示预设封面；新记录写 `gift` 保证数据库和旧客户端兼容。无上传图的旧奖励在新版柠檬任务端显示浅灰色，这是预期变化。同路径刷新保留已成功加载图片以避免闪灰；换图或移除立即丢弃旧画面。回滚两个应用界面即可恢复旧入口和展示，不涉及数据迁移。
