# 需求：创建任务时选择任务包内的任务，并修复锁屏后来源不可选

- 需求编号/目录：`20261010-parent-app-task-package-selection`
- 日期：2026-10-10
- 应用范围：`parent-app`；依赖 `shared` 任务仓库接口及 `supabase` 创建任务函数
- 提出人：用户

## 原始需求

> 家长端优化一个创建任务时候的功能
> 1. 创建的时候选择完分类任务包的时候，展开任务包里的任务作为一个列表，横向平铺可换行展示
> 2. 每个任务项都有一个选择框，默认是全选的，可以手动去勾选取消或选中
> 3. 最终保存的时候只保存勾选选中的任务
> 4. 遇到一个缺陷，在任务页面停留很久手机锁屏，解锁后创建任务页面的分类和单个任务选择的表单项都是置灰的不能点击

## 背景与目标

当前选中分类任务包后只显示任务标题摘要，保存时服务端创建包内全部任务。家长需要在创建前看到全部任务，并只创建勾选项。任务页在锁屏较久后可能因进程重建与会话异步恢复出现来源数据未加载，选择框持续置灰。

## 范围与约束

- 仅改变家长端新建任务流程；已有任务编辑、任务库管理、孩子端展示不改变。
- 分类包与单个任务仍是二选一来源。切换分类包时，新包内任务默认全选；选择单个任务时不使用包内勾选状态。
- 分类包无有效任务或全部取消勾选时不可保存，避免生成空任务。
- 保存时仅创建选中模板在所选日期内对应的任务，保留现有重复日程、去重、分类快照、积分和成长领域规则。
- 共享仓库接口和数据库函数变更归属本家长端流程；旧客户端的创建请求应继续可用。数据库迁移需要先于新版家长端部署。
- 不修改其他应用或云函数。

## 验收标准

1. 选择有任务的分类包后，任务项以横向排列、空间不足时换行的列表展开；每项有可操作的选择框，初始均选中。
2. 取消和重新勾选任意项后，保存仅生成当前勾选项；未勾选项不会因本次保存被创建或修改。日期区间、重复日程均遵循这一规则。
3. 切换分类包后按新包重新全选；切换到单个任务后按原有单任务规则创建；全不选时不能保存。
4. 任务页长时间锁屏后解锁，即使应用进程被重建，创建页的分类和单个任务选择仍能在会话恢复后加载并点击；加载失败有可见提示和重试途径。
5. 旧客户端不传勾选列表的请求仍按原规则创建包内全部任务。
