# 设计：任务包内选择与锁屏恢复

## 问题分析

`TaskEditScreen` 当前只把包内任务标题串成摘要；`TasksViewModel.createTask` 仅传分类 ID，数据库函数 `create_tasks_from_selection` 据此创建该分类下全部模板。创建页的分类和单任务控件分别在 `categories`、`taskTemplates` 为空时禁用。`TasksViewModel.loadData` 初始化时只取一次 `observeCurrentUser().first()`，而 `SupabaseAuthRepository` 异步恢复会话；若锁屏后进程重建，这次读取可能得到初始 `null` 并退出，之后没有重新加载来源数据。网络失败也缺少创建页可见的重试入口。

## 方案与范围

1. `TaskEditScreen` 为选中分类维护模板 ID 集合。选择或切换分类后，以该分类当前有效模板初始化为全选；模板数据稍后到达时完成初始全选；用户手动修改后不因普通重组而覆盖选择。任务项以可换行布局横向排列，每项显示选择框及标题，整项可点击。清空选择时禁用保存，并显示提示。选择单个任务时清空分类选择；单任务入口保留原交互。
2. `TasksViewModel` 将分类 ID 和选中模板 ID 列表传到 `TaskRepository`。仓库调用服务端创建函数，在一次数据库事务内生成选中项的全部日期任务。服务端校验非空、无重复的选择、模板属当前家庭且确实属于所选分类；模板数量上限按实际选择计算。筛选在 `INSERT ... ON CONFLICT` 之前进行，未选模板不触发更新。单任务路径维持原规则。
3. 新增数据库迁移，扩展 `create_tasks_from_selection` 的能力，同时保留原七参数入口供旧客户端调用。旧入口按包内全选行为委托新逻辑；新版请求明确传入选中 ID 列表。保留当前家庭权限、500 条上限、分类快照、任务领域、重复系列和冲突更新规则。迁移先于新版 APK 部署。
4. `TasksViewModel` 初始化先等待会话恢复结果，再加载孩子、分类、模板及关联。加载失败设置明确错误，不让页面无限等待；创建页在回到前台时针对未成功加载的来源重试，并提供手动重试入口。加载中的控件显示加载态，恢复后可选择。正常已有数据时避免无谓清空当前表单选择。

## 涉及文件与数据流

- `parent-app/.../feature/tasks/TaskEditScreen.kt`：可换行选择列表、选择状态、来源加载/重试提示、保存校验。
- `parent-app/.../feature/tasks/TasksViewModel.kt`：会话恢复与数据重试、创建参数。
- `shared/.../repository/TaskRepository.kt` 与 `shared/.../repository/impl/SupabaseTaskRepository.kt`：选中模板参数与 RPC JSON。
- `supabase/sql/20261010_parent_task_package_selection.sql`：服务端原子创建及兼容旧入口。
- 测试：针对选择状态、服务端选择校验与兼容行为添加必要验证；运行家长端自动测试和构建，校验迁移 SQL。

数据流：用户选分类 → 分类关联与模板交集显示为勾选项 → 保存传分类 ID、选中模板 ID、日期和孩子 → 服务端校验权限及关联 → 只为选中模板生成任务 → 返回创建结果供页面刷新。

## 接口、兼容性与风险

- 新版客户端依赖数据库新入口，部署顺序为先迁移、后安装新版应用；旧客户端七参数请求保持有效。
- 若任务库在创建页打开期间发生增删或关联变化，界面以当前可用模板更新显示；服务端再次校验归属，防止越权或过期选择。服务端拒绝时显示原有创建失败提示，不产生部分任务。
- 锁屏问题由静态代码显示的会话竞态推断；人工测试需覆盖“页面长时间锁屏后直接返回”及“进程被系统重建后重新进入”。若另有设备特定触发条件，按测试现象继续定位。
- 回滚应用可恢复旧 UI；数据库保留兼容入口与新增函数，不回退已创建任务。若需回滚数据库，仅在确认无新版客户端调用后移除新入口。

## 待用户确认的设计决策
