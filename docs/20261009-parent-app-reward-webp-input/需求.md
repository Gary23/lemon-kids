# 需求：家长端奖励图片支持 WebP 选择

- 需求编号/目录：`20261009-parent-app-reward-webp-input`
- 日期：2026-10-09
- 应用范围：`parent-app`；沿用现有共享仓库、Supabase Storage 与孩子端图片展示能力，不改变其接口或存储格式。
- 提出人：用户
- 原始需求描述：「家长端新增一个需求，奖励管理的奖励图片，要支持webp格式的图片，另外你分析下用这个格式的图片柠檬任务app端是否需要修改」

## 背景与目标

奖励管理目前只接受 JPEG/PNG 输入，选择 WebP 会提示“请选择静态 JPEG 或 PNG 图片”。家长需要能选择 WebP 图片并完成预览、保存、替换与再次查看。

## 范围与约束

- 在家长端“我的 → 奖励管理”的现有单图流程中增加静态 WebP 输入。
- 沿用现有解码、方向处理、最长边 1600 像素和输出不超过 5 MB 的规则；保存前仍统一转成 JPEG。
- 图片仍按家庭私有权限存储，旧奖励、旧 JPEG/PNG 输入和无图兜底行为保持现有语义。
- 动画 WebP 的动画播放不在本需求范围；奖励图片按静态封面使用。

## 非目标

- 不增加 `.webp` 对象、WebP 原文件直传或新的数据库字段。
- 不调整孩子端奖励页布局、刷新或兑换规则。

## 跨模块影响与孩子端结论

当前共享上传接口校验 JPEG 字节并生成 `.jpg` 路径；Supabase `reward-images` bucket 只允许 `image/jpeg`；孩子端通过签名 URL 交给 Coil 展示。新增 WebP 输入若在家长端转成 JPEG，孩子端收到的仍是原有 JPEG 对象和路径，故本方案无需修改 `kid-task-app`、共享仓库或 Supabase。若将来要求保留 WebP 文件本身，则须另立跨应用流程，分别评估共享路径校验、存储 MIME/权限、旧版客户端和孩子端实际解码验证。

## 可验证的验收标准

1. 家长在新增和编辑奖励时能选取静态 WebP，显示预览，保存后在管理列表与再次编辑时正常显示；替换或移除正常。
2. JPEG/PNG 输入、无图奖励、尺寸和 5 MB 限制维持现有行为；损坏或无法解码的 WebP 有明确错误，不能写入失效路径。
3. WebP 输入保存后仍以 JPEG 对象和 `.jpg` 路径供孩子端读取；柠檬任务 App 的大小心愿卡片按现有链路显示该图片，无需发布新的孩子端代码。
4. 自动测试通过后取得家长端安装确认；安装后等待人工测试结论，结论确认前不推送或标记完成。
