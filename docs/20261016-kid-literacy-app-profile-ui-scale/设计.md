# 设计：柠檬认字“我的”页面尺寸校准

> 版本：最终归并，2026-10-16。应用范围为 `kid-literacy-app`；第 5 节记录人工测试期间获批的补充与缺陷结论，覆盖上文已过时的页头、头像尺寸和背景裁切决定。

## 1. 复核依据与问题

参考图为 1536×1024 px；目标 BZT3-AL00 物理屏幕为 2000×1200 px、320 dpi，上一轮记录的应用安全区约 1000×567 dp，字体倍率 1.0。按可用高度计算，参考图 1 px 约等于 0.55 dp。这是视觉比例基准，不是统一缩放系数；文字、可点区域与安全区仍按 Android 规则处理。设备当前处于锁屏状态，尚无本轮真实页面截图，因此以下“现状”来自代码和窗口参数，最终需与实机截图复核。

| 元素 | A01 效果图尺寸及换算 | 当前实现 | 结论 |
| --- | --- | --- | --- |
| 页面主内容宽 | 六个入口覆盖 x=130–1409，约 1279 px → 约 709 dp | `ProfileScreen` 在约 1000 dp 窗口只留两侧各 24 dp，内容约 952 dp | 两列入口整体明显过宽；本页需居中限制内容宽 |
| 页头 | 标志 y=66–186，约 120 px → 约 66 dp；参考图标题无副标题 | 通用 `GardenPageHeader` 含 100 dp 吉祥物和额外副标题，行高再加上下边距 | 本页页头过高，结构也与参考图不同 |
| 资料与累计数 | 信息卡 612×195 px → 约 339×108 dp；统计卡 232×195 px → 约 128×108 dp | 头像 96 dp，面板内边距 20 dp；统计卡宽 220 dp、数字 48 sp | 头像尺寸基本合适，但面板留白与统计卡宽度过大 |

该页的显著尺寸差异可由页面本身的固定 dp 和通用组件布局解释，暂没有系统 density 或字体倍率异常的证据。参考图 3:2 与目标 Pad 约 16:10 的画幅不同，背景裁切及横向空白不能逐像素复刻。

## 2. 页面方案

- 在“我的”页引入页面专用的居中内容宽度，标准 Pad 目标约 710–740 dp；内容较窄时用可用宽度，保留至少 24 dp 安全边距。维持六入口两列三行；大字体或窄窗口沿用现有单列规则。
- 将本页页头改为与 A01 接近的紧凑标题，展示柠檬标志与“我的小麦仓”；去掉参考图中没有的标题副说明。吉祥物放入资料区右侧的独立位置，空间不足时重排或隐藏装饰，不遮挡真实信息。
- 资料卡、累计数卡以参考图约 108 dp 高为标准窗口目标，控制内边距；保留 96 dp 左右头像的视觉比例，并让长姓名/大字体时卡片自行增高。累计卡以约 128–145 dp 宽为标准目标，数字字号按卡宽调整；无缓存时资料区重新占宽，不伪造累计数。
- 六张入口卡以约 84–92 dp 高、约 350 dp 宽为标准窗口目标，行间距约 8–10 dp、列间距约 8–10 dp；插画保持原图比例，文字按可用宽度布局，箭头独立保留。长文案和大字体允许入口增高，不截断，整张卡可点击且目标尺寸始终大于 48 dp。
- 固定导航继续锚定屏幕安全区底部，标准宽度向参考图约 303 dp 靠近，但点击项保持至少 48 dp 高；滚动区末项能够完全滑到导航上方。背景固定，按当前 `ContentScale.Crop` 处理 Pad 画幅。
- 仅增加“我的”页专用样式与尺寸入口，避免通用 `GardenPageHeader`、`GardenPanel`、`GardenMenuCard` 被其他子页连带缩小。

- 人工验收后核对并最小化更新 `kid-literacy-app/docs/UI-SPEC.md` 的“我的”章节和 `kid-literacy-app/README.md` 的页面说明，保持长期文档与最终行为一致。

## 4. 验证、风险与回滚

- 自动验证计划：`./gradlew :kid-literacy-app:assembleDebug :kid-literacy-app:lintDebug :kid-literacy-app:testDebugUnitTest`；若新增独立布局计算，用有实际判别力的尺寸边界验证。自动测试完成后报告并等待本轮安装确认。
- 安装到用户指定 Pad 后，对照 A01 效果图核对标准字体下首屏构图，再检查无缓存、长姓名、字体放大和滚动末项。设备当前锁屏，截图与交互核对须在可见状态完成。
- 主要风险是过度压缩导致中文截断或点击困难，故标准窗口以参考比例为目标，窄窗口与大字体允许增高滚动；不强改系统密度或整页缩放。
- 如实机比例与设计不符，仅回滚/调整本页 Compose 样式；不涉及数据回滚。

## 5. 最终补充与缺陷设计

### 补充：删除独立页头

用户要求移除“我的小麦仓”及柠檬图标。已获批从 `ProfileScreen` 的滚动列表删除页头及仅供它使用的组合函数，顶部内容留白改为约 24dp；资料卡、统计卡、吉祥物和六个入口自然上移。底部导航仍固定，窄屏及大字体仍可滚动，原数据和点击规则不变。

### 缺陷 v1–v3：视觉及头像位置

- `Page.PROFILE` 的背景用 `ContentScale.Crop` 与 `Alignment.TopCenter`，完整显示顶部，竖向超出只裁底部；其他页面背景规则不变。
- 六个入口按 A01 配色绘制渐变底，最外层为连续白色描边，内侧为各卡颜色的描边；前景文字、插画及整卡点击范围保留。箭头使用对应颜色的无描边实心圆底，内部仅一枚深色右箭头，不叠加白环。
- 资料卡使用奶油渐变、外白内暖色描边，底部左右叠加花草素材，姓名旁显示黄色光芒；装饰不能遮挡真实头像、姓名或欢迎语。头像不可用时仍回退现有孩子插画。
- 缺陷 v3 将头像圆形区域由 96dp 缩至 84dp，保留 3dp 麦黄色圆边；头像和文案所在行在资料卡内垂直居中，左侧留 16dp。标准 108dp 卡高时上下均有可见间隙；内容较大时卡片可增高。

上述方案只修改 `LemonLiteracyApp.kt` 的“我的”页呈现及本页花草 PNG，不改 ViewModel、接口或数据。自动验证仍为 `assembleDebug`、`lintDebug`、`testDebugUnitTest`；按用户授权安装 BZT3-AL00 后对照 A01 与实机画面。可只回退本页样式，无数据迁移。人工验收后已核对 `kid-literacy-app/docs/UI-SPEC.md` 和 `kid-literacy-app/README.md` 的长期规则。
