# 设计：已认识字置顶即时更新

## 问题分析与目标

`RecognizedCharactersViewModel.topCharacter()` 在接口成功后只用 `map` 替换目标记录的 `recognizedAt`，未调整 `characters` 的顺序。列表组件按 `characters` 原顺序展示，因此要重新进入页面、重新从仓库读取按时间倒序的数据后，才能看到该字置顶。

目标是在接口成功返回后即在当前页面看到目标字排第一，同时保持服务端时间为最终数据，并处理请求失败。

## 方案与交互

1. 点击“置顶”且没有其他置顶请求时，仅设置处理中状态，保持列表顺序和收录时间不变。
2. 沿用现有 `top_recognized_character` 请求。成功后，在同一次状态更新中把服务端返回的 `recognizedAt` 写入目标字并移到列表首位，清除处理中状态并显示成功提示；其他字维持相对顺序。重新进入页面仍按仓库现有的服务端倒序读取。
3. 请求失败后，仅清除处理中状态并显示失败提示，列表顺序及收录时间保持不变。
4. 列表使用现有稳定 ID 作为卡片 key。置顶期间继续阻止重复置顶请求；其他页面操作维持现有行为。

## 涉及文件、数据与兼容性

- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/feature/recognized/RecognizedCharactersViewModel.kt`：调整本地列表状态的置顶、成功和失败处理。
- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/LemonLiteracyApp.kt`：现有列表直接消费 ViewModel 状态，预计无需改动。
- 服务端接口、`recognized_characters` 表和共享 Repository 均不变；云端返回的时间继续作为权威值。无迁移或部署依赖。

## 风险、验证与回滚

- 请求耗时期间目标字仍在原位置；卡片按钮显示处理中。成功后只更新仍在当前列表中的目标字，避免恢复期间已移除的记录。
- 验证请求期间列表不移动、成功后日期和位置更新、失败不改变列表、连续点击保护及退出重进后的顺序。自动测试至少执行认字端编译，并针对列表变更逻辑做可行的单元测试或明确记录替代验证。
- 回滚可撤销本次 ViewModel 调整；服务端及数据结构未变化。
- 用户已授权自动测试通过后直接安装到当前 Pad；安装后等待用户人工测试结论，之后才提交推送并标记完成。
