# 需求：已认识字置顶后立即移动到列表顶部

- 需求编号/目录：`20261010-kid-literacy-app-recognized-top-immediate`
- 日期：2026-10-10
- 应用范围：`kid-literacy-app`
- 提出人：用户
- 原始需求：创建认字端开发分支，优化“已认识的字”页面；点击置顶后，字立即到置顶位置，当前要退出页面再进入才能看到生效。

## 背景与目标

“已认识的字”按收录时间倒序加载。现有置顶请求成功后只更新目标字的收录时间，当前页面列表顺序保持不变；重新进入页面后，云端倒序结果才显示正确位置。

目标是在置顶接口成功返回后，当前页面立即将目标字显示在列表第一位，无需退出或刷新；云端收录时间仍决定后续进入页面及首页三天学习周期。

## 范围、约束与依赖

- 只调整认字端“已认识的字”页面的本地列表状态与反馈。
- 沿用现有 `top_recognized_character` 接口，不修改共享仓库、数据库或云函数。
- 保持“查看”“存库”及首页复习规则不变。接口请求期间列表不移动；失败时保持原列表状态并提示失败。
- 本流程不处理其他应用。

## 验收标准

1. 在“我的 → 已认识的字”中，对非首位字点击“置顶”，请求期间该字保持原位置并显示处理中；接口成功后在当前页面立即移动到第一位，无需退出再进入。
2. 置顶成功后显示服务端返回的新收录日期；退出再进入，列表顺序与云端一致，首页继续按新日期计算三天学习周期。
3. 置顶请求失败时，列表顺序及收录时间保持不变，显示失败提示并允许重试；重复快速点击不会发起同一时刻的并发置顶请求。
4. 其他字的相对顺序和内容不因本次置顶改变，“查看”“存库”仍可正常使用。

## 补充需求归并

用户在首次安装后的人工测试期间提出“置顶接口反馈成功后再在页面置顶，而不是先置顶再去调用接口”。2026-10-10 批准补充设计及直接安装；新版安装后，用户确认本次需求测试通过。以上验收标准以补充后的最终交互为准。
