# 设计：家长端任务成长领域标注

## 最终生效方案与设计确认

本设计最初的任务领域标注、补标与更正入口已被用户批准的手动勋章进度补充方案替换。现行家长端在“我的 → 勋章进度”按孩子录入 13 条专项累计数；英语阅读按 A～Z 分段输入。共享 `BadgeCatalog` 定义阶段门槛、名称、单位、上限和中文英语阅读级名。固定上限由客户端与数据库双重校验，六年频次项目等级封顶后仍可继续累计。家长可调低纠错，受控 RPC 使用版本检查并写审计；RLS 保证家庭隔离，孩子只读本人。保存后客户端重读服务端，已提交但响应异常时识别为成功，真正冲突提示最新值并保留输入，错误提示不暴露请求头。两条习惯勋章继续按任务事实统计；高效英语、思维火箭暂不定级。数据库保留旧 `growth_domain` 字段、历史数据和旧 RPC 兼容，但家长端不再显示该领域、补标和更正入口，专项计算也不使用这些字段。

旧领域菜单字号不一致曾按已批准缺陷设计统一为主题文字层级；由于最终移除入口，该改动仅作为开发过程记录，不是当前可见功能。认字 1071 字保存后误报由写后核对及安全文案修复。用户于 2026-10-05 确认本单补充与缺陷均完成，作为最终人工验收。

以下章节保留最初经批准的设计与演进背景，其任务领域驱动专项的规则已不再生效。

## 问题与目标

当前 `TaskTemplate` 只有标题、说明和积分；`categories.name` 是家庭自由文本，任务模板可以加入多个分类。直接用标题关键词或分类名生成学科勋章会误判。例如“英语绘本”同时含英语和阅读，“数学游戏”不一定是计算练习。由家长明确选择一个**主要成长领域**，孩子端只根据任务实例里的稳定领域快照计数。

## 产品规则与页面

在“我的 → 任务库 → 新建/编辑任务”表单的积分字段附近新增“成长领域（用于孩子勋章）”单选，按孩子端「柠檬成长勋章馆」分组展示，列表可滚动但只允许选一个主要领域：

| 分组 | 家长端可选领域 | 孩子端对应勋章线 |
| --- | --- | --- |
| 学科探索 | 阅读、计算、默写、英语、写作表达、数学思维 | 阅读探险家、数字解谜家、字词收藏家、英语探索家、故事创作者、思维探险家 |
| 生活实践 | 劳动与自理 | 生活实践家 |
| 不计专项 | 综合/不计专项 | 仍计入总等级、任务担当者和坚持足迹 |

新模板默认“综合/不计专项”；旧模板的空值显示“未设置（不计专项）”，引导家长明确选择。说明文案：“完成任务后，对应勋章积累一次；每个任务只能选一个主要领域。综合任务仍计入总经验和成长习惯。”任务库列表以小标签显示领域。任务领域只表示家长认定的任务性质，不代表孩子达到的能力水平；具体七条专项勋章线及阶段名称见独立的孩子端设计。运动和艺术创作如有家庭任务可选择综合，不生成专项勋章。

领域是任务性质而非正确率：家长选择“计算”仅表示孩子完成计算类任务，不能证明全对。“口算 20 题”建议归计算；“找图形规律、数独、逻辑推理”建议归数学思维；普通数学应用题由家长按主要训练目标二选一。一个“英语绘本”任务也由家长选择其更希望计入的主要领域；首版不支持同任务同时为两枚专项勋章加进度，避免双重计数。允许家长日后调整模板领域，调整只影响后续创建的任务。

编辑模板后若已有同模板任务且领域为空，表单保存成功后可以显示独立操作：“为未归类的历史任务补标”。进入确认页先给出匹配的任务实例数量、其中已完成数量、目标领域，并说明只更新当前家庭、`source_template_id` 对应、`growth_domain` 仍为空的实例，不改标题、完成状态、完成时间、积分或已归类任务。家长明确确认后执行一次性受控补标；失败可重试，重复请求幂等。已归类历史任务若选错领域，首版通过家长端历史任务的专门“更正成长领域”入口逐项更正并记录操作人、时间和原/新领域，不随模板编辑批量覆盖。

任务创建使用模板当前领域生成 `tasks.growth_domain` 快照。批量创建和重复任务的每个日期实例都各自保存快照；后续模板改名、变更领域、从分类移除或删除，不改变已创建实例。编辑尚未完成的单个/未来任务时允许家长改领域，并只影响所选范围；已完成任务只能走受控更正入口，不通过普通编辑更改领域。未标注实例在孩子端正常计入总任务/总 EXP 和成长习惯勋章，但不计专项勋章。

## 数据和调用链

- `task_templates.growth_domain`：可空；旧模板保持 `null`，新建模板由家长端明确写入默认 `other`；允许 `reading/calculation/dictation/english/writing/math_thinking/life/other`。
- `tasks.growth_domain`：可空，作为创建时快照；旧实例保持 `null`，新实例从模板读取并将模板空值作为 `other` 写入。`null/other` 都不计专项。现有旧任务不自动从标题或家庭分类推断。
- 更新 `create_tasks_from_selection` RPC，使新任务从当前模板复制领域；既有“按孩子+日期+模板去重”冲突更新时不覆盖已经存在任务的领域，避免重新安排任务改变历史。旧客户端直接创建/编辑任务但未传领域时默认为 `other`。
- `:shared` 的模板/任务模型、仓库新增读取/写入字段；家长端表单和任务编辑页使用该字段。历史补标与逐项更正通过仅家长可调用、验证家庭归属的 RPC，不能使用客户端通用更新绕过审计。
- 历史更正写审计记录：任务 ID、家庭 ID、原/新领域、操作人、时间；仅记录领域更正，不改任务完成事实或积分流水。孩子端聚合只读取 `tasks.growth_domain` 当前值，因此确认补标或更正后勋章重新计算。

## 兼容性、风险与回滚

必须先部署兼容旧客户端的数据库字段及 RPC，再发布家长端。旧客户端不传 `growth_domain` 时应继续成功创建任务，并标为 `other`。模板可能在多个家庭自定义分类中，成长领域始终取模板字段；历史补标必须按家庭和模板双重限制。受控更正记录不能被孩子写入。回滚家长端表单后，新字段与旧任务仍可读；不能清除已有领域快照或审计记录。

## 验收与待确认决策

自动测试覆盖模板保存、分类多对多不影响领域、批量创建快照、旧客户端默认值、历史补标只改空值、跨家庭拒绝与更正审计；人工测试核对新旧模板、已有任务及已完成任务在补标前后的领域变化。

待确认：每个任务**只选一个主要成长领域**，候选领域由阅读、计算、默写、英语扩展为七个（新增写作表达、数学思维、劳动与自理）；新模板默认综合，旧模板保留未设置状态；历史补标需先预览数量再由家长单独确认，且只处理 `growth_domain IS NULL` 的旧实例；已归类历史任务只允许逐项更正并留审计。孩子端的七条专项勋章线依赖该领域快照，在独立流程中确认。
