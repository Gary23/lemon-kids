# 设计：统一底部导航尺寸并移除按压灰色反馈

## 问题分析

`LiteracyBottomNav` 在同一个组件里用 `current == Page.PROFILE` 选择 310dp，否则选择 342dp。两个主页面均调用这个组件，故切页时导航外框宽度发生变化；高度和内边距目前共用同一套参数。

字卡、菜单、导航项使用 `Modifier.clickable`，按钮及刷新等使用 Material 3 的 `Button`、`IconButton` 或可点击 `Surface`。默认按压 indication 会在控件表面绘制灰色或半透明反馈。需要在应用界面入口统一抑制这类按压覆盖，同时覆盖 Compose Foundation 和 Material 3 的点击组件。

## 方案与范围

1. 移除 `LiteracyBottomNav` 按当前页切换宽度的分支，统一使用“认字”页现有的最大宽度 342dp。保留 `fillMaxWidth`、48dp 最小点击高度、内边距、选中样式和底部安全区适配。
2. 在 `LemonLiteracyTheme` 或应用顶层提供与当前 Compose 版本兼容的无可见按压反馈配置，使本应用页面与弹窗中的可点击字卡、按钮、导航项和入口卡不再绘制灰色按压遮罩。若 Foundation 与 Material 3 使用不同的反馈来源，分别在相应作用域关闭。只抑制按压反馈绘制，不改变 `onClick`、`enabled`、选中语义或业务状态颜色。
3. 不调整页面内容尺寸、字卡布局、颜色体系、业务数据或其他应用。系统输入法、系统导航手势和第三方 SDK 自带界面不在此方案内。

## 文件与交互影响

- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/LemonLiteracyApp.kt`：导航宽度的统一入口；如需在应用根部提供按压反馈配置，也在此处接入。
- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/ui/theme/LiteracyTheme.kt`：若统一反馈配置放在主题内，在此设置。最终只保留一个清晰的配置位置。
- 无接口、存储或兼容性迁移。切页与控件点击的回调保持原样。
- 人工验收后核对 `kid-literacy-app/README.md` 和 `kid-literacy-app/docs/UI-SPEC.md`，仅同步仍长期有效的导航和交互规则。

- 风险：全局关闭按压反馈会减少触摸瞬间的视觉提示；控件本身的选中、禁用及业务状态标识保留。若某个 Material 组件仍绘制覆盖，针对该组件补充局部配置，再经同一门禁复验。
