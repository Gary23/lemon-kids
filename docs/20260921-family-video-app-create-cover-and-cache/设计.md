# 设计

## 问题分析

当前 `CollectionEditor` 将封面放在目录之前，并通过系统选图上传至 Supabase Storage。目录选择接口 `browse` 只返回文件夹，无法发现约定封面文件。`VideoProfileViewModel.load()` 每次进入组合界面都调用 `connection_status`，即使当前设备已刚刚取得过相同结果。

## 方案目标与范围

### 新建条目封面

仅当 `CollectionDraft.id` 为空（新建）时，界面顺序调整为：名称 → 类型 → 云盘目录 → 封面。选择具体目录后：

1. Android 调用新的 `folder_cover` 操作，并传入已选目录 ID。
2. Edge Function 复用该目录的直接文件列表，筛选文件名完整匹配 `folder.(png|jpg|jpeg)`（大小写不敏感）；若意外存在多个，以 `.png`、`.jpg`、`.jpeg` 的优先级选择一个。
3. Edge Function 通过 123 `download_info` 取得短期下载链接，仅返回该临时链接给已鉴权且有家庭的调用者；不写数据库、不持久化链接或 token。
4. Android 将链接只保留在 ViewModel 草稿状态，由 Coil 预览。未找到、请求失败或预览加载失败时显示原因并使保存不可用。
5. 保存仍将临时链接作为条目的 `cover_url` 写入当前表结构；该链接会失效，因此实现时会将“保存封面”改为：由 Edge Function 返回封面二进制流/或客户端读取链接并上传至 `video-covers`，数据库只写入长期 public URL。**这是实现前需确认的关键接口细节：优先采用 Edge Function 代理封面二进制并由 Android 立即上传，避免把临时链接写入数据库。**

已存在条目继续展示并可从手机选择、上传封面，保持现有兼容行为；本需求不自动替换旧封面。

### “我的”与连接状态缓存

1. 将底部导航标签“家长”改为“我的”，页面标题“家长小站”改为“我的”，描述改为面向个人的云盘与动画库管理。
2. 在 `SupabaseEdgeCloudDriveProvider` 内以 Android `SharedPreferences` 缓存 `DriveConnection` 的状态、账号提示、根目录信息、缓存时间和当前 Supabase 用户 ID。缓存不包含任何凭据或临时 URL。
3. `connection()` 先读取当前用户且未超过 24 小时的本地缓存；缓存命中直接返回，未命中才调用 `connection_status` 并写回缓存。`connect()` 成功后立即覆盖缓存。
4. 使用 Supabase 用户 ID 隔离缓存，防止切换账号后显示另一个账号的状态。缓存只代表最近一次服务器登记状态；用户点击“重新连接”仍会发起实际请求并刷新缓存。

## 接口、兼容性与安全

- 新增 `folder_cover` action；现有 action 与数据库 schema 不变。
- Edge Function 必须在返回任何封面数据前通过已有 `authenticatedFamily()`；客户端不得直接获得 123 token 或密钥。
- 本地缓存使用应用私有存储，不保存密钥、密码、token 或临时下载 URL；24 小时后自动回源刷新。
- 若新端尚未部署 Edge Function，客户端将显示封面读取失败，不能新建条目；已存在功能不受影响。

## 风险与回滚

- 123 临时链接可能到期，因此不能写入 `cover_url`；上传到既有 `video-covers` 是持久化封面的回退与兼容方案。
- 文件名约定可能不符合实际目录。缺少匹配文件时明确提示，不猜测其他图片。
- 缓存可能短暂陈旧；用户可用“重新连接”主动刷新，24 小时自动失效。
- 回滚时移除新客户端调用并停止使用新 action；既有媒体库数据、Storage 封面和原有连接记录都不需要迁移或清理。

## 已合并的部署缺陷修复

首次安装后的问题不是实现逻辑错误，而是客户端和服务端版本不一致：APK 已经发出 `folder_cover`，已部署的函数却还没有这个 action。2026-09-21 已使用 Supabase CLI 将当前函数部署到 `ebiikfxehhcrtrkioxqa`（版本 11），并核验函数为 `ACTIVE`、未携带 `Authorization` 的 `folder_cover` 请求返回 HTTP 401。无需再次安装 APK。

## 已合并的可靠性与封面归属设计

后续补充需求和缺陷将所有 123 只读交互统一为受限恢复模型：服务端优先复用 Edge 内存和 `video_drive_token_cache` 中仍有效的应用级 access token；只有实际到期或认证拒绝才重新授权。网络异常、超时、HTTP 429/5xx 最多重试一次，认证拒绝只刷新 token 并重试当前业务读一次。`connect`、`browse`、`folder_cover`、`playback_url` 使用 85 秒服务端预算和 95 秒 Android 等待；`sync_collection` 使用 55/65 秒，并在失败时保留上次成功的视频。播放器首次错误仅重新签发一次临时播放链接。

目录选择采用单页 `browse(cursor)` 协议，Edge 以目录和游标缓存页面五分钟并合并相同并发请求；Android 按登录用户缓存成功目录页 24 小时，提供“加载更多目录”及绕过两级缓存的“刷新目录”。完整视频同步不使用这些目录页缓存。

封面查询优先精确检索约定文件；搜索结果必须可验证其父目录等于请求目录，否则最多退化为目标目录普通列表第一页。服务端的封面缓存和并发合并键包含家庭和目录，成功结果返回绑定家庭、目录、文件、名称和有效期的签名归属凭据。Android 的 `cover.v2` 缓存只保存该凭据及定位元数据，旧版裸文件 ID 缓存不读取。切换目录、关闭编辑、打开其他条目、手动上传或保存时取消旧自动任务；函数响应、图片下载和 Storage 上传回写前均检查当前草稿的目录和选择序号。

## 验收设计

1. 在含有 `folder.jpg` 的目录新建条目，确认选择目录后即可显示该图片，保存后重新打开条目封面仍有效。
2. 分别验证 `folder.png`、`folder.jpeg` 及无匹配文件的目录；无匹配时有提示且保存按钮不可用。
3. 确认编辑已有条目时旧的本地选图/上传封面方式仍可用。
4. 登录后第一次进入“我的”读取状态；离开并再次进入，在 24 小时内观察不发生 `connection_status` 请求；重新连接后状态与缓存更新；切换账号不复用原账号缓存。
5. 自动执行 `./gradlew --no-daemon :family-video-app:assembleDebug`。

## 待确认的设计决策

- “folder 文件”按精确文件名 `folder` 加 `.png`、`.jpg` 或 `.jpeg`（不区分大小写）处理；如同时存在，优先 `.png`、再 `.jpg`、最后 `.jpeg`。
- 新建页不再提供手机本地选图；目录封面会上传到现有 `video-covers`，以保证保存后长期可用。
- 连接状态缓存有效期为 24 小时，并以当前 Supabase 用户 ID 隔离。
