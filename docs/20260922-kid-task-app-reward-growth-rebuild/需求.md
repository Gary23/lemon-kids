## 原始需求

作为柠檬任务全面 UI 重构的一部分，按 Stitch 的星星银行/心愿奖励、我的成长/成就中心落地奖励与成长域；尚未实现的功能先完成 UI，可使用假数据。

## 本批目标

重构奖励兑换为星星银行与心愿奖励中心，并把“我的”升级为成长与成就中心；新增心愿池、兑换申请、等级成长、勋章、里程碑的演示 UI，同时保留已有账号设置入口。

## 非目标

- 不在本批新增心愿、兑换审核、经验值、勋章、成长足迹的后端表或家长端审核流程。
- 不更改真实积分余额与既有奖励兑换的接口契约。

## 约束与依赖

- 视觉实现必须先通过 Stitch MCP 获取对应屏幕的实际截图与 HTML，以 MCP 实际效果为主要依据；仅在 MCP 缺失或不明确时参照本地下载的 `ui` 目录。本规则适用于本次及后续柠檬任务 UI 修改。奖励与成长主参考为对应“灵动微交互版”屏幕，本地 `_2`、`_4` 仅补充内容和状态细节。
- 依赖批次一的公共壳层和设计令牌。
- 现有 `RewardViewModel` 当前无真实奖励源时，示例奖励仅为本地演示，不得扣减真实积分或持久化兑换。

## 验收标准

1. 奖励页展示真实积分余额（如可取得）及与之视觉隔离的演示心愿/兑换历史。
2. 演示小心愿支持本地申请成功反馈，不发起服务端写入；无数据能力均明确标为演示。
3. 成长页包含等级进度、勋章分类/筛选和里程碑的完整横屏 UI，并保持账号资料/计划入口可达。
4. 既有头像、昵称、账号切换和计划入口不丢失。

## Pad 测试缺陷与最终验收口径

2026-09-30，用户在首次 Pad 测试中指出侧栏名称、银行上方多余标题、“投递新愿望”入口等内容偏离 Stitch，并要求完整对照 MCP UI。经批准后，奖励与成长两页以 Stitch MCP 项目 `10281478774604750732` 的奖励屏幕 `bd269692341947c9b0224c2268a38c27`、成长屏幕 `6ff6887e7e8b404da82a782db18194ab` 的截图和 HTML 重新校准。

最终验收包括：侧栏名称为“今日任务 / 任务日历 / 奖励兑换 / 我的成长”；奖励页从问候行进入“我的星星银行”，依次展示大心愿、三列小心愿、兑换与奖励记录及页尾，没有额外的“星星银行与心愿奖励”标题或“投递新愿望”入口；成长页采用资料与等级同卡、勋章分类及四列网格、里程碑布局。真实积分及账户操作沿用现有数据，心愿申请、等级、勋章和记录保留明确的演示边界，不通知家长、不扣真实星星。

用户于 2026-09-30 在修复版安装 Pad 后明确要求将本次缺陷与本次需求均标记完成，本流程据此记录人工验收通过。
