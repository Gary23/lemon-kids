# 设计

## 问题与视觉依据

当前奖励页使用未接入数据源的 `RewardViewModel`，默认积分为 0、奖励列表为空，旧 `redeemReward()` 还会在内存中直接扣分。当前“我的”页提供头像、改名、计划、使用限制和切换账号，但没有成长内容。第 01 批公共侧栏和主题已交付，第 02 批也已完成。

2026-09-29 已通过 Stitch MCP 获取以下屏幕的**实际截图与 HTML**，以“灵动微交互版”为主要依据：

| 页面 | Stitch 屏幕 ID | 采用的结构 |
| --- | --- | --- |
| 星星银行与心愿奖励中心 | `bd269692341947c9b0224c2268a38c27` | 黄色银行横幅、余额双卡、大心愿进度、小心愿卡片、兑换记录 |
| 我的成长与成就中心 | `6ff6887e7e8b404da82a782db18194ab` | 个人资料与统计、等级进度、勋章分类网格、成长里程碑 |

Stitch 的兑换弹窗写有“已通知家长”“已划扣星星”，与本批纯演示的要求冲突。实现时保留卡片和反馈的视觉形式，文案改为“演示申请已记录在本页；未通知家长，也未扣除星星”，且不生成真实兑换记录。班级、经验、勋章数、里程碑等没有现有数据来源的内容明确标为“演示”。

## 目标与范围

仅改 `kid-task-app` 的奖励与成长页面及导航入口，沿用第 01 批固定横屏、侧栏、颜色和圆角组件。奖励页按“顶部问候 → 真实可用积分与演示月累计 → 演示大心愿 → 演示小心愿 → 演示兑换记录 → 页尾”排列；成长页按“真实资料与演示等级同卡 → 演示勋章 → 演示里程碑 → 设置与账户”排列。页面可纵向滚动，横屏下卡片使用多列布局。

不建立心愿、申请、审核、经验值、勋章或里程碑的后端表；不改 `RewardRepository` 接口，也不增加家长端流程。现有头像上传、修改昵称、计划导航、使用限制展示和切换账号继续使用现有逻辑。

## 涉及文件与数据边界

- `feature/reward/RewardScreen.kt`、`RewardViewModel.kt`：重排奖励页；以独立 `RewardDemoUiState` 提供静态心愿和演示记录。本地按钮状态只显示演示反馈，不调用旧 `redeemReward()`，不修改积分。
- `feature/profile/ProfileScreen.kt`、`ProfileViewModel.kt`：重排成长页；以独立 `GrowthDemoUiState` 提供等级、勋章和里程碑。保留真实资料与设置操作。勋章筛选只在 Compose 本地状态执行。
- `feature/home/HomeViewModel.kt`：在首次收到真实积分流结果后标记积分已加载，避免把初始默认值 0 当成已核实余额；原有任务与侧栏逻辑继续共用此状态。
- `navigation/KidTaskNavGraph.kt`：侧栏奖励入口沿用 Stitch 名称“奖励兑换”，成长入口为“我的成长”；将现有 `HomeViewModel` 的实时积分传给奖励与成长页，保证和侧栏一致；为“查看任务日历”提供现有路由回调。
- 第 01 批公共壳层与主题令牌：按需复用，不修改跨应用共享模块。
- `ui/components/KidTaskShellComponents.kt`：侧栏积分在真实积分首次返回前显示读取状态，避免和新页面的余额说明不一致。
- `res/drawable-nodpi/reward_*.jpg`：从上述 Stitch 奖励屏幕 HTML 对应的生成素材保存本地卡片图，页面离线也可呈现主要视觉。

真实积分来自 `HomeViewModel` 已订阅的 `RewardRepository.getCurrentPoints()`，只显示在标注为“当前可用星星”的区域。首次积分流结果到达前显示“读取中”，若始终无法取得则显示“暂不可用”，不把默认 0 当作已确认余额。成长页昵称、头像沿用 `ProfileViewModel`。若“本月赚取”无法从既有可靠记录计算，则标为“演示数据”。演示心愿的价格只说明示例目标，不决定真实账户能否申请。

## 页面与交互

### 星星银行

1. 顶部问候行后直接展示黄色“我的星星银行”横幅和双余额卡；真实可用积分与演示月累计在各自卡内区分，演示属性使用原有胶囊或角标呈现。
2. 大心愿卡展示示例目标、示例进度和“查看任务日历”；进度旁标“演示进度”，不以真实积分计算。
3. 小心愿沿用 Stitch 的三列五卡、图文卡和圆角按钮。按钮写“立即申请兑换”；点击后显示对应心愿名称及本地演示成功反馈，关闭后不改变余额、不新增真实记录。页面不提供“投递新愿望”入口。
4. 兑换记录用静态示例，区块和条目均标明“演示”，不写“妈妈已兑现”等真实状态断言。若保留真实积分流水，须另列“积分记录”，不得混入演示记录。

### 我的成长

1. 个人头部显示真实头像、昵称和实时积分；Stitch 的班级、任务完成数、达成率等未接入字段标演示或省略。头像与昵称保留编辑入口。
2. 等级卡展示示例 Lv.4、经验进度和下级目标，明确标“成长等级演示”；升级奖励只作为示意，不赠星或改变头像。
3. 勋章分为“全部勋章、自律打卡、习惯培养、学习进步、心愿达成”；点击筛选只改变当前可见的示例勋章。解锁状态仅为演示。
4. 里程碑卡标“演示记录”，不用容易被误认为真实发生时间的相对日期。
5. 页尾保留“设置与账户”：计划、使用限制、修改昵称、更换头像和切换账号。计划使用现有路由；切换账号保留二次确认。

## 兼容性、风险与回滚

演示数据只在任务端 UI 层存在，不影响数据库、云函数或其他应用。旧 `redeemReward()` 的本地扣分实现应移除或确保不可达。真实余额与演示内容使用不同状态、标题和标签，自动测试覆盖“申请后积分不变”和勋章筛选。若目标 Pad 上布局拥挤，可单独回退这两页和导航文案，不影响公共壳层与第 02 批。

## 验收标准

1. 固定横屏 Pad 上，星星银行完整展示银行横幅、大心愿、小心愿和演示兑换记录；真实积分与侧栏一致，演示内容清楚标识。
2. 点击演示小心愿有本地反馈；不发起服务端写入、不通知家长、不扣减真实积分，也不生成真实兑换状态。
3. 我的成长展示真实头像、昵称和积分，以及明确标为演示的等级、勋章筛选、里程碑；筛选有效且可恢复全部。
4. 头像上传、昵称修改、计划入口、使用限制展示、切换账号仍可达；今日任务和日历导航不受影响。
5. 自动测试与 Debug 构建通过；经用户确认安装后，在目标 Pad 完成人工验收。

## Pad 缺陷修订：按 Stitch MCP 校准
