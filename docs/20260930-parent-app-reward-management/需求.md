# 需求

- 需求编号：20260930-parent-app-reward-management
- 日期：2026-09-30
- 应用范围：`parent-app`（含本应用依赖的 `shared` 奖励模型/仓库及 Supabase 奖励数据变更）
- 提出人：用户

## 原始需求与补充

> 柠檬任务app，分析一下我要建立奖励系统，页面现在已经有了，需要在家长端设置奖励，在柠檬任务重查看和兑换奖励，先分析设计一下

> 奖励要分一次性奖励和常规奖励，其中常规奖励可兑换多次，还需要孩子能看到自己已经兑换的奖励，使用后由任务端去执行删除操作，已经兑换的奖励也可以在任务端进行取消归还星星，家长端基本只负责待兑换奖励的维护

用户已确认：孩子兑换时直接扣积分；同一家庭的孩子共用奖励清单；一次性奖励全家总共可兑换一次，未使用前取消后恢复名额。

## 背景与目标

家长端“我的 → 奖励管理”目前只有不可点击的卡片；孩子端奖励页是本地演示。家长端负责维护家庭共用的待兑换奖励目录，一次性奖励仅允许兑一次，常规奖励允许重复兑换。已兑换奖励的使用与取消由孩子端处理。

## 范围

- 家长创建、编辑、停用奖励，配置名称、积分价格、一次性/常规类型、可选说明/图标及大心愿展示。
- 列出本家庭启用及已停用奖励；一次性奖励兑出后在孩子端不可兑换，取消后在家长仍启用时恢复可兑换。
- 建立家庭范围的奖励目录字段与写入权限，由共享仓库封装。

## 非目标

- 不在此流程改动 `kid-task-app` 页面及其兑换交互；该部分单独见 [孩子端需求](../20260930-kid-task-app-real-rewards/需求.md)。
- 不在家长端处理孩子已兑换奖励、确认使用、取消退款或兑换历史；这些能力由孩子端独立流程负责。
- 本期不做图片上传、外部商品购买、推送通知或家长预先审批。
- 不修改成长等级、勋章或任务积分规则。

## 约束与依赖

- 一次只覆盖 `parent-app`；本流程只承接目录模型、家长端仓库操作与目录迁移。孩子端流程承接兑换记录、退款事务和孩子端 UI，依赖关系在两份设计中注明。
- 当前 `rewards` 已有 `repeatable` 字段，可映射常规/一次性；`is_active` 需仅表示家长启停，不能与一次性奖励“已兑出”混用。
- 旧产品说明中的“家长后续兑现”与本次新要求不同，以用户最新要求为准。

## 验收标准

1. 家长可以进入“奖励管理”，创建合法奖励并编辑、停用/启用；其他家庭或孩子账号无法修改。
2. 奖励名称非空、价格为正整数；保存失败可见原因，不产生半条数据。
3. 奖励类型明确区分一次性与常规；家长端不出现已兑换奖励的使用、取消或退款操作。
4. 家长停用奖励不影响孩子此前已兑换的权益；一次性限兑与取消后的恢复由孩子端流程验证。
5. 自动测试、安装和人工测试按 `docs/README.md` 单独完成；设计未获批准前不改业务代码。

## 跨应用影响

孩子端消费本流程提供的目录字段与读取接口；`kid-task-app` 自己的流程负责兑换记录、原子扣分/退款及使用后移出列表。目录迁移先于孩子端事务迁移和真实功能启用。
