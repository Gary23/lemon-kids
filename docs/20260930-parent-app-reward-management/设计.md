# 设计：家长端待兑换奖励维护

## 问题分析

`ProfileScreen.kt` 的“奖励管理”卡片没有点击动作，也没有管理页。共享 `RewardRepository` 和 `rewards` 表已有标题、价格、`repeatable` 与 `is_active`，但仓库只取启用奖励，失败被静默吞掉且按五分钟轮询；家长无法管理停用项。

用户最新要求家长端基本只维护**待兑换奖励**；孩子已兑换后的使用、取消和退星都由任务端处理。旧产品说明中的家长兑现流程不纳入本次设计。

## 方案目标与范围

沿用“我的 → 奖励管理”入口，增加家庭共用的奖励清单与编辑表单。家长可设置名称、正整数价格、类型（**一次性**或**常规**）、可选说明、预设封面/图标，以及是否作为大心愿展示；同一家庭最多一个启用的大心愿。家长可编辑、停用/启用奖励，停用保留历史。

“一次性”使用现有 `repeatable = false`；“常规”使用 `repeatable = true`。`is_active` 只代表家长是否开放，不因孩子兑换而自动改变。一次性奖励是否可兑由兑换记录判定：兑出且未取消时不可兑；孩子取消后且家长仍启用时恢复可兑；标记已使用后永久占用该一次性奖励。

## 目录数据与接口

1. `rewards` 保留现有主键、`family_id`、`title`、`cost`、`repeatable`、`is_active`，新增可空 `description`、有默认值的 `cover_key`、默认 false 的 `is_featured`。增加标题非空、价格大于零及每家庭单个启用大心愿约束。迁移保留既有数据；已有奖励使用默认封面。
2. 收紧写入权限：家长仅可为自己的家庭创建、编辑或停用奖励；孩子只可读取本家庭启用奖励。防止跨家庭创建和修改 `family_id`。孩子端兑换迁移上线后，奖励一旦有兑换历史，其一次性/常规类型不可修改；若要变更规则，应新建奖励。重新启用也不重置一次性奖励的已兑状态。
3. 共享仓库提供家长端“全部奖励”读取与创建、编辑、启停操作；列表/保存失败有明确错误状态，成功后主动刷新。孩子端读取可兑换状态时还须结合兑换记录和服务端事务，不能只看 `is_active`。
4. 目录迁移属于本流程；兑换记录表、扣分/退款/标记使用 RPC 与积分流水扩展属于[孩子端流程](../20260930-kid-task-app-real-rewards/设计.md)。两份迁移按目录先、兑换后顺序部署。

## 页面与交互

- `parent-app/.../feature/profile/ProfileScreen.kt`：奖励管理卡片可点击，不展示待使用数或退款操作。
- `ParentNavGraph.kt`：新增奖励管理路由，返回后保留“我的”上下文。
- 新增 `RewardManageScreen.kt` 和 ViewModel：清单显示名称、价格、一次性/常规、启停及大心愿标识；新增/编辑表单；停用二次确认。家长端不展示孩子“我的已兑换”，也不提供使用、取消或退款按钮。
- 家长列表只展示类型和家长启停状态，不依赖孩子端兑换记录；孩子端负责判断一次性奖励是否仍可兑。
- 首次加载、空家庭、无奖励、网络失败分别展示明确状态；提交期间禁用按钮，成功后立即刷新。预设封面两端共用 `cover_key`，本期不做图片上传。

## 依赖、兼容与风险

- 影响 `shared/model/Reward.kt`、`RewardRepository.kt`、`SupabaseRewardRepository.kt` 与一份目录迁移；孩子端消费同一目录字段，详见[孩子端设计](../20260930-kid-task-app-real-rewards/设计.md)。
- 一次性奖励的“兑出/取消/已使用”只由孩子端受控事务改变，家长编辑不能重置。兑换历史出现后的类型禁改规则由孩子端迁移在数据库侧补齐，避免旧客户端绕过界面限制。
- 先检查线上 `rewards` 的实际结构和旧数据，再执行可重复的目录迁移。回滚应用时保留真实目录，不删除历史。

## 验收标准

1. 本家庭家长能创建、编辑、停用和重新启用奖励；无权限用户及跨家庭请求失败。
2. 大心愿至多一个；奖励类型、启停状态和价格显示准确，既有兑换不会因改价而被重写。
3. 家长端只维护目录；孩子已兑换奖励的使用、取消与退款操作不可在家长端执行。
4. 家长编辑和停用只改变目录，不处理已兑换奖励；一次性限兑及取消后恢复在孩子端独立流程验收。
5. 自动测试通过后再请求设备安装确认，安装后等待家长端人工测试结论。

## 已确认的业务规则与设计确认项

已确认：孩子确认兑换时直接扣分；家庭共用奖励清单；奖励分一次性和可重复兑换的常规；家长端只维护待兑换目录；孩子使用后移出持有列表并保留历史；只有使用前可取消退星。一次性奖励**全家总共可兑换一次**；取消未使用的兑换后释放名额，标记已使用后不再释放。

业务取舍均已确认，仍需用户明确批准本应用设计，才能进入执行阶段。
