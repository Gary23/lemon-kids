# 前台独立进程重启设计

## 根因与证据

2026-10-29 19:25:08，测试包 PID 24591 在 LocalServerScreen.kt:137 主动结束进程。19:25:13 系统启动记录仍为 BAL_BLOCK；日志明确显示 balAllowedByPiCreator=BSP.ALLOW_BAL、callerStartMode=MODE_BACKGROUND_ACTIVITY_START_ALLOWED，但创建方进程已不存在，发送方未允许后台启动。上次授权修改已进入安装包，真机仍未通过；不能继续依赖 AlarmManager 在进程结束后拉起页面。

## 方案

1. 在 parent-app 新增不对外导出的本地重启 Activity，运行于独立的 :local_restart 进程，显示“正在切换服务”页面。仅本地构建允许执行重启路径。
2. 地址页完成探测、清除旧会话及同步保存地址后，在自身仍为前台时启动重启页面，不立即结束原进程。
3. 重启页面进入前台后才结束传入的旧主进程；校验目标为本应用主进程，避免误杀辅助进程或其他应用。
4. 确认旧进程退出后，由可见的重启页面直接启动明确指定的 MainActivity。新主进程重新创建 Hilt 单例和 Supabase 客户端；随后关闭重启页面并回收辅助进程。正常应用启动不初始化辅助进程的业务客户端。
5. 不再使用 AlarmManager/PendingIntent 拉起。辅助页面启动失败时，原设置页显示错误并允许重试；进程退出超时或 MainActivity 启动失败时，辅助页面保留错误提示与重试入口，不无限等待或静默退出。
6. 保留相同地址直接继续、不可达不保存且不重启等现有分支。

## 文件与影响

- LocalServerScreen.kt：将闹钟重启替换为前台重启页面接管。
- 新增本地重启 Activity 与必要的重启状态辅助逻辑。
- parent-app AndroidManifest.xml：声明非导出独立进程 Activity，避免出现在最近任务列表。
- 不变更共享模块、数据库和其他应用；普通包受本地构建条件保护。
