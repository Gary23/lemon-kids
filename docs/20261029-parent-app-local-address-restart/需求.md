# 家长端本地服务地址切换后无法重新打开

- 日期：2026-10-29
- 应用范围：`parent-app` 本地调试包。
- 提出人：用户。
- 原始反馈：输入本机 IP 后连接直接闪退。
- 关联流程：`../20261022-parent-app-local-auth/` 的本地服务地址补充需求；本目录独立记录本次缺陷，保留原有登录页入口缺陷文档。

## 问题与目标

地址健康检查和保存成功后，应用调用 `Process.killProcess`，通过 AlarmManager 的 PendingIntent 重新打开应用。手机日志显示系统拒绝后台启动：`Background activity launch blocked`、`balRequireOptInByPendingIntentCreator: true`、`BAL_BLOCK`。本次目标是恢复已批准的受控重启流程，保证切换后使用统一的新地址。

## 范围与约束

只修复本地测试包地址切换重启的系统兼容性；保留地址健康检查、私有 IPv4 校验、清除旧会话及进程重建规则。不修改正式包配置、数据库或其他应用，不要求额外系统权限。

## 验收标准

1. 输入不同且可达的局域网地址后，保存成功并重新打开测试应用，不停留于桌面或其他应用。
2. 重新打开后显示已保存地址，继续后能登录；SDK 与 RPC 均使用新地址。
3. 相同地址直接继续；不可达地址留在设置页并提示错误，不退出进程。
4. 正式包保持原样；修复通过自动测试并取得安装确认后，仅更新 `.local` 测试包，等待用户人工验收。

## 缺陷归并与验收结论

首次 PendingIntent 授权修复在真机仍被系统拦截，最终方案改为前台独立进程接管重启。2026-10-29 用户明确确认“关于闪退的缺陷你可以标记为完成了”，地址切换退出缺陷人工验收完成。该确认仅覆盖闪退缺陷，不替代原本地认证主需求中的登录、注册、家庭和绑定码等其他验收。

最终补充验收要求：辅助页面接管后才结束旧主进程；仅可结束同 UID、名称为本包的主进程；超时或启动异常显示可恢复提示。
