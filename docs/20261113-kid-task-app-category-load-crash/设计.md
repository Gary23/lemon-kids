# 设计：分类流失败容错与重试

## 问题分析

`observeCategories` 以 `callbackFlow` 封装一次 `fetch()`：失败时先 `Log.e` 再 `throw e`，导致 flow 以异常终止。孩子端 `HomeViewModel.loadData()` 在 `viewModelScope.launch` 中直接 `collect`，异常沿协程层级上抛到 `Dispatchers.Main.immediate`，进程终止。父端调用点均有 `.catch`/`loadSource` 包裹，故未暴露。

即便忽略崩溃，当前交互也有缺陷：分类首次请求失败时 `initialCategoriesLoaded` 永远为 false，首页要等 8 秒超时兜底才渲染。

## 方案

在孩子端内部新增一个“失败不断流”的收集器，把异常转成“保留旧数据 + 提示 + 退避重试”，不改仓库层语义。

### 新增文件

`kid-task-app/src/main/java/com/lemonkids/kidtask/feature/home/ResilientFeed.kt`

```kotlin
internal fun feedRetryDelayMs(failureCount: Int): Long   // 1→15s，2→30s，其余→60s

internal suspend fun <T> Flow<T>.collectKeepingLastValue(
    onValue: suspend (T) -> Unit,
    onRecovered: suspend () -> Unit,
    onFailure: suspend (Throwable, Int) -> Unit
)
```

行为：

- `collect` 内每个元素交给 `onValue`；收到元素且此前有失败时回调一次 `onRecovered` 并清零失败计数。
- 捕获 `CancellationException` 并重抛（协程取消语义不变）。
- 其它异常：失败计数 +1，回调 `onFailure(error, count)`，按 `feedRetryDelayMs(count)` 延迟后重新订阅。
- 上游正常结束（`collect` 返回）则直接返回；函数永不向调用方作用域抛业务异常。

选型理由：`retry`/`retryWhen` 只能重试上游 flow，无法在重试期间保留 UI 状态与失败计数展示；手写循环最直观，且不引入新依赖。

### HomeViewModel 改动

- `HomeUiState` 新增 `categoriesLoadFailed: Boolean = false`。
- 分类订阅抽成私有方法 `startCategories(familyId)`，用 `categoriesJob` 记录，重入前先 `cancel()` 旧 job（手动重试不产生并发订阅）。
- 收集改用 `collectKeepingLastValue`：
  - `onValue`：保持原逻辑（过滤空名称、计算 `isInitialDataReady`），并清 `categoriesLoadFailed`。
  - `onFailure`：`initialCategoriesLoaded = true`（首屏不再等 8 秒），置 `categoriesLoadFailed = true`，`isLoading`/`isInitialDataReady` 按现有规则重算。
  - `onRecovered`：清 `categoriesLoadFailed`。
- 新增 `fun retryCategories()`：记录 `familyId` 后可被 UI/前台恢复调用。
- `refreshAfterForeground()` 中若 `categoriesLoadFailed` 为 true 则调用 `retryCategories()`（回到前台自动补一次）。
- 失败提示文案不暴露 URL、familyId 等内部信息。

### UI 改动

- `HomeDashboard` 增加参数 `onRetryCategories: () -> Unit = {}`，在 `isInitialDataReady` 分支顶部（`ProgressHero` 之前）渲染提示条：
  - 文案：“分类暂时无法加载，任务仍可正常使用”
  - 右侧“重试”文本按钮 → `onRetryCategories()`
  - 样式沿用 `StrawberrySoft`/`Strawberry` 边框 + `SlateInk` 文本，圆角 28dp，与其他提示卡一致。
- `HomeScreen` 传入 `viewModel::retryCategories`。

### 测试

- `kid-task-app/build.gradle.kts` 增加 `testImplementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.10.1")`，与 `parent-app/build.gradle.kts:95` 保持一致。
- 新增 `kid-task-app/src/test/java/com/lemonkids/kidtask/feature/home/ResilientFeedTest.kt`：
  1. 首次订阅抛异常：不逃逸、失败计数为 1、无数据发出；推进 15s 虚拟时间后重新订阅并收到数据，`onRecovered` 触发一次。
  2. 先成功再失败：已发出的数据保留（不产生空列表覆盖），失败后继续按退避重试。
  3. `feedRetryDelayMs`：1→15000、2→30000、3→60000、10→60000。
  4. 上游抛 `CancellationException`：不被吞掉，协程正常取消且 `onFailure` 不触发。
- 不新增 `HomeViewModel` 单测：其构造即读取 `SharedPreferences`（`HomeTaskOrderStore`）并触发 `TaskReminderScheduler`/`TaskWidgetProvider`，纯 JVM 无法构造，项目也未引入 Robolectric；改用“收集器 + 纯函数”覆盖核心逻辑，UI 行为由人工测试确认。该取舍记录在 `执行.md`。

## 风险与回滚

- 风险：退避重试在长时间断网时每 60s 打一次请求，频率低于原有 10s 超时重试感受，可接受。
- 风险：手动重试取消旧 job 时若正在 `delay`，取消即时生效，无并发订阅。
- 回滚：还原上述 4 个源文件与 1 个构建文件、删除新增测试与 `ResilientFeed.kt` 即可，无数据副作用。
