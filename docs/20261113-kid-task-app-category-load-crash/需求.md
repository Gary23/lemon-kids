# 需求：孩子端首页分类请求超时导致闪退

- 需求编号/目录：`docs/20261113-kid-task-app-category-load-crash/`
- 日期：2026-11-13
- 应用范围：`kid-task-app`（孩子端）
- 提出人：用户
- 原始需求（2026-11-13 19:55）：柠檬任务 app 在 19:42 左右闪退一次，此前还有一次未记录时间的闪退；pad 已连接，要求连接设备排查原因。取证结论汇报后，用户于 20:07 批准修复并要求完成后安装到当前连接的 pad。

## 背景

设备取证（`.local-diagnostics/20261113-crash/dropbox.txt:353-400`、`dropbox.txt:378-400`）显示两次 `data_app_crash`：

- 2026-11-13 19:34:45，PID 18158，Lifetime 1606s，Foreground Yes
- 2026-11-13 19:41:37，PID 19642，Lifetime 404s，Foreground Yes

两次堆栈一致：

```text
FATAL EXCEPTION: main
io.ktor.client.plugins.HttpRequestTimeoutException: Request timeout has expired
  [url=https://ebiikfxehhcrtrkioxqa.supabase.co/rest/v1/categories?family_id=eq.88a063c5-...&order=created_at.asc.nullslast&select=%2A, request_timeout=10000 ms]
  at io.ktor.client.plugins.HttpTimeout$Plugin$install$1$1$killer$1.invokeSuspend(HttpTimeout.kt:165)
```

同一崩溃在 2026-11-11 13:44:03（主机无法解析）、21:10:41、23:50:48 也出现过，均为同一个 `categories` 请求。

崩溃链路：

1. `shared/src/main/java/com/lemonkids/shared/repository/impl/SupabaseCategoryRepository.kt:39-57` 的 `observeCategories` 在 `fetch()` 失败后 `Log.e(...)` 再 `throw e`，`callbackFlow` 以异常结束。
2. `kid-task-app/src/main/java/com/lemonkids/kidtask/feature/home/HomeViewModel.kt:110-121` 的 `viewModelScope.launch` 内直接 `collect`，没有 `catch`，异常冒泡到主线程。
3. 家长端两处调用（`TasksViewModel.kt:157` 的 `.catch`、`CategoryManageScreen.kt:104` 的 `loadSource`）已有容错，因此只有孩子端首页会闪退。

结论：请求超时本身是网络/服务端问题，现有日志无法进一步区分；但**一次读取超时不应该结束进程**，这是孩子端必须修复的缺陷。

## 目标

- 分类流任意一次失败都不再导致闪退或退出首页。
- 失败时保留已经展示的分类与任务，给出可感知提示，并支持自动重试与手动重试。
- 修复必须可被自动化测试覆盖，并安装到当前连接的 pad 供人工验收。

## 非目标

- 不调整 10 秒请求超时时长，不改 Supabase/网络配置。
- 不改 `SupabaseCategoryRepository` 的异常语义（父端已各自 `catch` 并有测试依赖该语义）。
- 不处理任务流、积分流等其他数据源的容错（本次仅分类流；如后续出现同类崩溃另开需求）。
- 不改桌面小组件（`TaskWidgetProvider.kt:317-325` 的 `first()` 仅在后台刷新路径，异常已被上层 `runCatching` 覆盖）。

## 约束与依赖

- 遵循 `docs/README.md` 流程：设计批准后才改代码；自动测试通过后需安装确认；人工测试通过前不推送、不标完成。
- 改动涉及 `kid-task-app`；`shared` 不改动，因此不影响家长端、小组件等其他模块。
- Android/Gradle 命令一律使用 `GRADLE_USER_HOME="$PWD/.gradle-system"`。

## 验收标准

1. 构造分类流抛出 `HttpRequestTimeoutException`（或任意非取消异常）时，应用不崩溃，首页仍可操作，已加载的分类与任务保持展示。
2. 失败后首页顶部出现提示条“分类暂时无法加载，任务仍可正常使用”，并提供“重试”入口；点击后立即重新订阅；恢复成功后提示条自动消失。
3. 自动重试按 15s / 30s / 60s（上限 60s）退避，不产生重试风暴；首次加载失败时不再等待满 8 秒才渲染首页。
4. 新增单元测试覆盖“异常不逃逸”“失败保留上一次数据”“退避间隔”“取消异常不被吞掉”，且既有单元测试无回归。
5. debug APK 可覆盖安装到当前连接的 pad（`72CNU20930100436`），供人工验证。
