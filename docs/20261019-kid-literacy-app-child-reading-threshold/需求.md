# 需求：儿童词句朗读评分放宽

- 需求编号：20261019-kid-literacy-app-child-reading-threshold
- 日期：2026-10-19
- 应用范围：`kid-literacy-app`；依赖 `cloud-functions/evaluate-reading` 的失败诊断规则版本。
- 提出人：用户
- 原始描述：「我认为现在的60分有点太高了，我想评分还是宽松一些，我认为对于字的要求60可以，但是词语和句子60分有点高了，特别是对于儿童」。
- 后续明确数值：「词语50分，句子30分就可以」；单字仍为60分。
- 后续明确前提：「之前说的分数都是基于MatchTag=0前提下，如果这个字段值不是0那就不能通过了」。

## 背景与目标

当前单字、词语、句子均以逐字 `PronAccuracy < 60` 判为未通过；有分数时即使 `MatchTag` 非 0 也可能通过。词句由儿童朗读时容易因个别字分数偏低被标红。目标是保留单字要求、放宽词句分数，同时要求匹配标记为 0，让诊断原因及规则版本与实际判定一致。

## 非目标与约束

- 不改变腾讯的评分、`MatchTag` 含义、参考文本、评测模式或录音流程。
- 不改变已产生的学习记录或历史诊断日志。
- 本流程只修改认字应用及其云函数依赖；家长端说明文字如需同步，按独立应用流程处理。
- 按 `docs/README.md` 完成设计确认、自动测试、安装确认与人工测试确认。

## 验收标准

1. 每个映射到目标汉字的腾讯逐项结果必须 `MatchTag=0` 才可能通过；非 0 或缺失不能通过，高分也不例外。
2. 在 `MatchTag=0` 前提下，单字、词语、句子的逐字通过线依次为 60、50、30 分；等于阈值通过。
3. `PronAccuracy` 缺失、漏字及未返回逐字结果的规则明确且可预期。
4. 失败诊断中的原因和规则版本准确对应新的分类阈值，历史日志保留旧规则版本。
5. 自动测试覆盖三类目标及临界分数；设备上由用户完成儿童朗读验收。
