# 设计：儿童词句朗读评分放宽

## 问题分析

`LemonLiteracyApp.kt` 的逐字判定和失败原因均固定使用 60 分。一次词或句只要有一个汉字低于阈值就会被标红，因此统一 60 分对较长句子尤其严格。当前有可解析的 `PronAccuracy` 时不检查 `MatchTag`，即使该标记非 0 也可能通过。云函数写入诊断日志时固定标记 `pron-accuracy-60-v1`。家长端目前也将 `low_pron_accuracy` 解释为低于 60 分，属于独立应用的后续同步范围。

## 方案与待确认决策

按用户最新要求设逐字通过线：单字 **60 分**、词语 **50 分**、句子 **30 分**。每个映射到目标汉字的腾讯逐项结果先检查 `MatchTag`：只有数值为 **0** 才继续检查分数；非 0、缺失或无法解析都判该项未通过，即使 `PronAccuracy` 达标也是如此。`MatchTag=0` 且 `PronAccuracy` 等于阈值即通过，低于阈值标红。这些是应用教学规则，不是腾讯官方推荐值；`MatchTag=0` 自身仍不能证明发音正确。

统一从目标类型取得阈值，供逐字判定及 `low_pron_accuracy` 诊断原因共用。保留当前 0～1 与 0～100 分数量纲兼容、漏字和空结果处理。`PronAccuracy` 缺失或无法解析但 `MatchTag=0` 时，沿用现有回退行为判通过；这一结果只有“匹配”依据，诊断时不得写成分数达标。`MatchTag` 非 0 或不可用时，无论有无分数都判未通过。只对映射到目标汉字的逐项结果执行门槛；腾讯可能返回的 `Word="*"` 等非目标音段继续忽略。词句继续逐字判断，不改为只看整句平均分。

失败诊断将 `MatchTag` 非 0 和不可用分别记录为明确原因，`low_pron_accuracy` 仅表示该目标类型的分数低于对应阈值；同一项两条件都失败时可同时记录。云函数校验允许新原因，并保留旧日志原因以兼容历史数据。家长端现有原因文字未同步前，新原因可能显示为“未收录原因”，需在独立的 `parent-app` 流程处理。

云函数诊断规则版本改为能反映三类阈值的新版本；已落盘的 `pron-accuracy-60-v1` 日志不改写。该变更影响 `cloud-functions/evaluate-reading/index.js` 的 SCF 部署，需按 `AGENTS.md` 重新生成并核验部署 ZIP，更新其 README 的当前部署包文件名。

## 涉及文件与交互

- `kid-literacy-app/src/main/java/com/lemonkids/kidliteracy/LemonLiteracyApp.kt`：分类阈值、MatchTag 门槛、逐字判定、失败原因。
- `cloud-functions/evaluate-reading/index.js`：新诊断规则版本及新增失败原因校验，确保日志解释准确。
- `cloud-functions/evaluate-reading/test/reading-diagnostics.test.js`：规则版本相关校验。
- `kid-literacy-app/docs/LEARNING-RULES.md`：人工验收后同步长期有效的通过规则。
- `cloud-functions/evaluate-reading/README.md`：部署包文件名及诊断版本说明。

参考文本和 `EVAL_MODE=1`、`TEXT_MODE` 参数保持现状：`EVAL_MODE=1` 已是句子评测模式，适用于“花花花”；单字的 `TEXT_MODE=0` 仅表示 `RefText` 使用普通汉字文本，不表示单字评测模式。词句的 `TEXT_MODE=1` 表示音素结构文本。不改接口请求结构或数据库。家长端 `ReadingDiagnosticGuide.kt` 和 `ReadingDiagnosticScreen.kt` 的固定“低于 60”文案将不再适合新日志，须另立 `parent-app` 流程并独立取得设计、安装和人工测试确认；在该流程完成前，不能将其固定文案当作新规则解释。

## 风险与回滚

降低阈值会增加词句通过次数，可能放过部分含混发音；人工测试应覆盖明确错读、正常儿童发音和临界分数。可将分类阈值恢复为 60 并恢复诊断版本用于后续记录，历史日志仍保留各自版本。

## 验证与门禁

自动测试覆盖单字 59/60、词语 49/50、句子 29/30，且上述边界均以 `MatchTag=0` 为前提；另覆盖非 0 加高分、标记缺失或无法解析、`MatchTag=0` 但低分、分数缺失、漏字和空结果，并核对诊断原因。按项目现有构建/测试方式执行并记录。通过后才请求安装确认；安装后由用户人工测试，确认前不推送或标记完成。
