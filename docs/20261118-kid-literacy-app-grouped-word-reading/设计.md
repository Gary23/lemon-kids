# 词语整组连读设计（已批准）

对应：[需求](需求.md)。范围：儿童认字端待认识、已认识练习弹层。目标是合并录音入口，不合并词的音频、判定或进度身份。不改变家长端、发音分数线、主字及句子的录音方式。

## 入口和状态

当前 `LemonLiteracyApp.kt` 的 `StudyPracticeItem` 以单个目标启动内嵌录音；`wordTargets` 实际只有 `listOf(target)`，旧“下一词”分支不是整组录音。新设计只替换弹层的词区域，字、句沿用现有组件。

- 一个外框按 `card.terms` 的显示顺序排列，各词仍是独立文字组件，保留拼音、星标和结果；窄屏优先按整个词换行。框外只保留一个当前动作按钮。长按事件直接携带该词目标和词内字下标；播放该词音频，缺失则用该词文本回退，不从整组文本反查。词间空白不触发点读。录音/评测中禁播，启动录音先停止示范音，避免被录入。
- 初次全部待练：开始连读 → 一次录音 → 完成录音 → 等待结果 → 逐词显示。自然停顿不结束会话，不按静音切段。没有词则不显示开始按钮；仅一词时直接使用单词路径。
- 有结果后按显示顺序排出待补词。提示区指出“只读『花园』”，按钮沿用统一的“开始/重试”，一次只评该词；补对移出队列，全部通过则显示完成。退出再进入时按已保存进度恢复：已有部分通过，直接逐个补剩余词；已全通过不再要求录音。
- 网络错误或空回包提示重试，不等同于发音错误。录音互斥；结束、关闭或切换卡片后用会话标识隔离迟到回调，重复完成事件不得重复记星。

## 参考文本：复用单词准备，只合并腾讯会话

`ReadingEvaluationViewModel` 已能逐词预取 `PreparedEvaluation`。云函数 `prepareEvaluation` 对词校验授权目标及就绪音素，返回 `TEXT_MODE=1` 和包含 `wordList` 的 JSON。**准备参数的请求可以有多个，真正采集、发送和评测语音只有一次。**

首轮取同一卡片各词的已校验参考参数，按页面顺序拼接各自的 `wordList` 数组，重新序列化成一个 `refText`，不拼 JSON 字符串、不插入朗读标点、不改音素。另建本轮边界表：原词目标、词序、预期汉字范围与词内字序。任何词的准备失败、模式不兼容或参考内容与页面不符，都不启动录音，提示重试，不降级到普通文本。仅创建一个腾讯控制器，沿用中文引擎及关闭 VAD 的配置。补读复用原词参数。首要真机验证是 SDK 对合并参数的接受程度及回包粒度，不把推测的字段当作接口保证。

## 逐词判定与记录

- 解析最终 `Words` 有效项，忽略不对应汉字的额外音段。对整段参考序列做保序对齐（允许缺失、替换、额外项），不能沿用仅寻找下一个匹配文字后移动游标的做法。优先使用经样本验证的参考位置；没有可靠位置时比较最优对齐路径，只有对词归属一致的部分才下结论。
- 每个字必须有可归属的覆盖；匹配与准确度沿用现有 `word` 规则，不用句子阈值。覆盖完整且各项通过才给该词一星；明确错读或漏读只标记对应词。多个解释影响归属、跨词项仅有不可拆分的失败分数等情况，相关词标“没听清”，其余有充分证据的词照常记星。不把整段分数平均分给各词。
- 例：「花朵／花园／花生」只返回可靠的首尾两个词，中间范围缺失：仅花园进入补读队列。若重复字导致多种同样合理的解释，不靠返回项序号决定哪一个词错。
- 通过回调按原 `ReadingTarget` 更新本地并同步原逐词进度键；失败、未确定、点读和已达标项不增加次数。错字提示/诊断用词内位置，不把整组明细伪装成某一词的单词评测。沿用原同步重试机制，不新增整组进度行。

## 次数、兼容与回退

| 对象 | 原要求 | 新要求 |
| --- | --- | --- |
| 待认识每个词 | 2 | 1（每个词均须通过） |
| 已认识主字，按原有组序 | 3、2、1，此后为 1 | 2、2、1，此后为 1 |
| 其他项 | 现有要求 | 不变 |

`LiteracyPracticeProgressStore.kt` 修改词门槛，`LiteracyHomeViewModel.kt` 修改第一组规则，不调整分组日期或顺序。卡片、录音剩余次数、星标、完成筛选和家长通过快照统一取有效门槛；已有较高计数仅在显示或构造当前快照时封顶，不反写降低历史计数，不修改历史快照。云端已有逐项准备和进度接口，设计不新增接口、表或迁移；不改变旧客户端协议。若真实 SDK 明细不足以可靠判词，先暂停整组方案并反馈样本问题，不暗中改为按停顿分三次；回退可恢复原单词入口及旧门槛，保留原逐项记录。

## 验收和交付门禁

- 自动验证：用受控回包覆盖全对、中词错、漏中词、插读、重字歧义、空明细；断言每词状态、补读目标和记星次数。验证首轮只启动一次控制器、补读只传一个词、重复回调无副作用；验证新旧进度边界（词 0/1/2，第一组主字 1/2/3）及其他组不变。
- 人工验证：两种来源分别用真实设备自然连读、长停顿、跳中词；确认提示与实际读法相符，重开不要求重读已通过词。同框首中末词、相同字、换行后长按均只播命中词；录音时点读不串音。确认主字和句子无交互回归。
- 设计获批后才进入执行；自动测试后单独请求安装许可，安装后等待人工验收。验收后同步 `kid-literacy-app/README.md` 的朗读、点读和进度规则；本方案不需要部署云函数，如接口约束迫使改变方案，先说明影响并重新确认。

## 已归并的缺陷设计（最终有效）

### 共用练习行及左边距

原词区独立Surface/Button造成黄底、裸词及左下按钮差异；用户2026-11-18 23:02批准修复，并要求自动测试后直接安装Pad。新增纯UI `GroupedWordPracticeRow` 复用 `StudyPracticeRow`：左侧按词序独立空星/金星及词级语义，阅读槽内各词独立命中与标红、横排可换行，右侧单一渐变按钮。完成隐藏按钮，但录音即使计数全满仍可停止；准备/评测禁用、录音互斥、失败重试、提示区指出补读词。初始及完成态不显示额外文字，去除黄底和独立状态文字，不改字句或SDK/计分。

同缺陷边距返修：仅把FlowRow从整体居中改为Alignment.Start，额外留白为 `(内容框宽度 - 10dp) × 4%`，叠加每词原5dp内边距，与句子5dp外边距后92%阅读宽度居中一致。保留12dp词间距、整词换行。宽屏900dp/普通字号与窄屏460dp/1.5字号对比真实句子及首词文字左边线，误差<=1.5px。首轮58项、最终60项测试通过后按同缺陷授权更新Pad，用户最终确认通过。

### 发音准备失败的定向数据修复

云端 `prepareEvaluation` 按source/id/type/index寻找ready音素并核对原文，缺失返回409；客户端逐词准备时任一失败即不启动录音。正式授权接口 `get_phonetic_assets` 对测试字握返回 `assets=[]`，并非可证明等待即可完成。用户批准先仅修复该任务三词一句：私有备份任务/资产/进度，复用pinyin-pro 3.27.0按完整词句生成并校验音素；事务SQL检查孩子、任务、原文及资产为空，仅INSERT指定4条资产。回滚限本次新UUID及原值；不清理全局、不索取密钥、不降级TEXT_MODE=0。用户确认缺陷修复完成；未额外修改生产源码或重新安装。本结论不声称所有历史任务缺失根因已确定，也不声称后台会自动创建缺失行。

### 测试后数据维护边界

用户明确授权仅清空当前孩子2026-11-19任务快照及当日练习进度，SQL限定孩子及北京时间日期，快照明细外键级联；若发现当日整字已完成则中止，避免遗漏音素生命周期。此次无当日整字完成，不更改任务、已认识、字库或音素。云端确认清空后强停应用，仅清除相同孩子/日期的本地快照及进度/待同步标记，核验其他项保持不变。用户取消18日握的恢复，保留工作区外私有备份；此为一次性维护而非新业务功能。
