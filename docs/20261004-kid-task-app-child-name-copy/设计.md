# 设计：柠檬任务显示真实孩子姓名

## 问题分析

代码中仅两处运行时“小当家”：`KidTaskShellComponents.kt` 的 `ChildSummary` 固定显示“小当家”；`ProfileScreen.kt` 的成长页标题在 `profile.userName` 为空时回退“小当家”。侧栏由 `KidTaskNavGraph.kt` 的 `KidTaskMainScreen` 渲染，当前尚未传入孩子姓名。成长页的 `ProfileViewModel.loadProfile()` 只取一次 `AuthRepository.observeCurrentUser().first()`，资料若稍晚加载可能停留为空；改名成功时仓库会更新当前用户流，但成长页的资料快照不能保证随该流同步。

`:shared` 的 `User.name` 对应 `users.name`；`AuthViewModel.uiState.currentUser` 订阅同一当前用户流。该字段是产品现有的孩子姓名/昵称资料，当前可在成长页修改。没有其他独立的法定姓名字段。

## 方案目标与范围

- 固定侧栏与成长页使用当前登录孩子账号的 `users.name`；姓名变更和账号切换后同步更新。
- 布局、字号、颜色和编辑入口保持现有风格，仅为较长姓名补充单行省略，避免撑破侧栏。
- 姓名未加载时显示“姓名加载中”，已取得用户但姓名为空时显示“未设置姓名”。两种占位均不冒充真实姓名。
- 不改其他应用或共享数据接口，不新增字段及网络请求。

## 数据与交互流程

1. 在 `KidTaskMainScreen` 读取任务端根层 `AuthViewModel` 的当前用户状态，并将当前孩子的姓名与资料加载状态传给 `KidTaskSidebar`、`ChildSummary`；侧栏切 Tab 时持续使用同一用户流，切换账号时立即随会话变化，不缓存前一孩子姓名。
2. `ChildSummary` 显示 `name.trim()` 的非空值；用户状态尚未取得时显示“姓名加载中”，用户资料已取得但姓名空白时显示“未设置姓名”。文本限单行并省略超出的部分。
3. `ProfileViewModel` 持续订阅 `AuthRepository.observeCurrentUser()`，同步 `userName`、头像等当前资料；成长页标题用同一姓名和占位规则。成功修改姓名继续沿用现有 `updateName`，共享仓库更新当前用户流后两处一起刷新。失败沿用现有错误提示，展示旧姓名。
4. 注销或切换账号时清除旧用户资料在任务端可见的姓名；新绑定会话到达后再显示其 `users.name`。

## 接口、兼容性与风险

- 只消费现有 `User.name` / 当前用户流，无数据库迁移或共享接口改动；`User.name` 仍可由成长页原有入口编辑。
- 侧栏较窄，长姓名须省略显示；成长页仍应可通过原编辑框查看完整姓名。
- 登录恢复、退出登录及切换账号期间不能残留上一个孩子的姓名。自动测试覆盖姓名为空、改名更新和会话切换；设备上核对实际显示。
- 回滚为恢复本次界面及订阅改动；用户资料不受影响。

## 验收标准

1. 两处运行时姓名均来自当前孩子 `users.name`，不出现“小当家”。
2. 修改姓名成功后两处更新；换号后只显示新账号姓名；失败时不把未保存姓名当成已保存。
3. 加载中和空姓名分别显示“姓名加载中”“未设置姓名”；长姓名不破坏侧栏。
4. 自动测试、安装许可、设备人工测试及项目文档核对依照 `docs/README.md` 的门禁逐项完成。
