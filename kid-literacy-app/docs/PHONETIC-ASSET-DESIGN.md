# 认字词句音素资产化设计

## 目标

词、句的拼音不再由 DeepSeek 生成、展示或作为业务数据保存。新增内容时只生成并允许人工编辑汉字词句；保存后由服务端异步生成腾讯智聆口语评测需要的音素资产。

音素资产用于在腾讯 `TEXT_MODE=1` 中锁定多音字读音。例如“组长”的“长”必须按 `zhang` 评测，读成 `chang` 必须判错；不启用腾讯声调检测，因此孩子不会因声调差异被判错。

## 已确认的产品规则

- DeepSeek 只生成词和句子，不生成拼音。
- 待认识字和已认识字保留音素资产；已认识字复习词语仍使用腾讯指定读音评测。
- 任一待认识字或已认识字被“存入字库”时，立即清理它及其词句的音素资产；两条入口都不能遗留资产。
- 待认识内容保存后，词、句不可再修改；“我的 → 待认识的字”详情弹层只允许修改音素。
- 编辑器直接展示和保存腾讯数字拼音，如 `zhang3`，不展示带调字符拼音。
- 不需要区分 `generated` 与 `manual` 来源：一项拥有完整、有效的音素资产后，批处理不再覆盖或重新生成。

## 腾讯协议约束

腾讯的自定义中文注音使用 `TEXT_MODE=1` 和 JSON 音素结构。数字拼音必须带 1 至 4 的调号；腾讯当前不支持轻声。声调检测只有在 `RefText` 中显式增加 `{::cmd{F_TDET=true}}` 后才开启，本设计不会增加该命令。

发送给腾讯的内容由服务端从资产组装，Android 不再自行拼接发音描述块或给拼音统一追加 `1`。例如：

```json
{
  "wordList": [
    { "word": "组", "pron": [["zu3"]] },
    { "word": "长", "pron": [["zhang3"]] }
  ]
}
```

`zhang3` 的数字是协议需要的正确参考标注，不是孩子的评分要求；未开启 `F_TDET` 时，声调不参与对错判断，但 `zhang` 与 `chang` 仍会严格区分。

## 数据模型

新增 `literacy_phonetic_assets`，既作为异步队列也作为已完成资产记录。

| 字段 | 说明 |
| --- | --- |
| `id` | 资产 UUID |
| `content_source` | `pending` 或 `recognized` |
| `literacy_character_id` | 待认识字或已认识字记录 ID |
| `item_type` | `word` 或 `sentence` |
| `item_index` | 词/句在已保存 JSON 数组中的固定位置 |
| `item_text` | 创建资产时的原文，用于审计和服务端校验 |
| `phoneme_tokens` | 逐汉字音素结构；普通字保存如 `zhang3`，轻声或未指定字保存 `null` |
| `status` | `pending`、`processing`、`ready`、`failed` |
| `attempt_count`、`last_error` | 可重试生成与故障定位 |
| `generator_version` | 词组拼音词典/生成规则版本 |
| `created_at`、`updated_at` | 生命周期审计 |

唯一约束为 `(content_source, literacy_character_id, item_type, item_index)`。待认识内容保存后词句不可编辑，因此固定索引可稳定标识条目；服务端仍须以 `item_text` 与主表内容比对，避免历史数据错配。

`phoneme_tokens` 存储规范化的技术音素，而不是完整 `RefText` 字符串。这样腾讯 JSON 结构升级时可以重新组装协议内容，不必重写人工维护的数据。

## 自动生成

保存待认识内容时：

1. DeepSeek 只返回词、句文字。
2. 家长可在预览阶段编辑词、句并提交。
3. 服务端在同一事务内写入待认识字词句，并为每个词、句创建一条 `pending` 音素资产。
4. 成功写库后立即在服务端生成本次任务的音素；独立事件函数 `generate-literacy-phonetics` 每 30 分钟
   扫描并领取剩余的 `pending` 或可重试 `failed` 资产，作为低频兜底。

生成器使用词组级拼音词典（Node.js 纯 JavaScript 依赖，例如 `pinyin-pro`），对完整词句生成数字拼音：

```text
组长 -> ["zu3", "zhang3"]
长城 -> ["chang2", "cheng2"]
```

不能按单个汉字生成，因为多音字必须由完整词句确定。生成器需要校验：

- 音素条目数与汉字数一一对应；
- 非轻声音素符合腾讯格式 `^[a-zv]+[1-4]$`；
- 词典无结果、结果长度不匹配或存在不支持字符时标记 `failed`，不写半成品；
- 轻声不得伪造为 `1`、`5` 或 `0`。对应汉字的 `phoneme_tokens` 记录为 `null`，资产仍可 `ready`；服务端组装 `wordList` 时省略该字的 `pron`，交由腾讯内置词典处理。

系统应限制可重试的临时失败次数。词典无法解析、文本格式不支持等确定性失败不无限重试，需在详情弹层中展示原因。

## 人工维护音素

“我的 → 待认识的字”列表点击某个字后，详情弹层展示其主字、每个词、每个句以及已有音素。

- 词句只读，不提供编辑入口。
- 每个词、句按汉字顺序展示数字拼音，例如 `zu3 zhang3`；轻声位置标为“腾讯不支持指定轻声”，不提交 `0` 或 `5`。
- 保存前校验非轻声音素数量、顺序、字母和 `1` 至 `4` 调号；失败时明确指出第几个汉字。
- 保存操作只更新相应 `literacy_phonetic_assets.phoneme_tokens` 与 `status=ready`。
- 批处理仅领取没有 `ready` 有效资产的词句，因此手工保存后不会被覆盖，无须额外 `source=manual` 字段。

专有名词、地名和词典误判可由此入口直接改为正确的腾讯数字拼音。人工维护仍必须遵守腾讯音素格式；无效值不可保存。

## 朗读评测

现有 `issue_credentials` 继续只签发并缓存短期 STS 凭证。新增或恢复一个服务端评测配置接口，例如 `prepare_evaluation`：

1. Android 传递当前已授权的字 ID、内容类型及词/句选择。
2. 服务端从待认识/已认识主表确认归属，再查询对应 `ready` 音素资产。
3. 服务端将 `phoneme_tokens` 组装成腾讯 `wordList` JSON，返回 `{ refText, textMode: 1 }`。
4. Android 使用缓存凭证和服务端返回的配置启动 SDK。

没有 `ready` 资产时，朗读按钮显示“正在准备发音”，不能静默回退 `TEXT_MODE=0`；否则多音字指定读音会失效。客户端不再构造 `RefText`、不再追加数字 `1`、不再传未在官方文档定义的 `F_TDET=false` 参数。

## 生命周期

| 事件 | 音素资产处理 |
| --- | --- |
| 保存待认识词句 | 创建 `pending` 资产并触发生成 |
| 生成成功或人工保存 | 写入有效 `phoneme_tokens`，置为 `ready` |
| 待认识字转已认识字 | 同一事务中把资产 `content_source` 改为 `recognized`，完整保留 |
| 已认识字复习 | 使用保留的资产进行指定读音评测 |
| 待认识字或已认识字存入字库 | 删除该字及全部词句音素资产；字库不需要朗读评测资产 |
| 删除待认识/已认识内容 | 删除关联音素资产 |

## 验收场景

- 新增“组”后，DeepSeek/预览接口不返回拼音；词句保存后自动生成资产。
- “组长”资产生成 `zu3 zhang3`，读 `chang` 时评测不通过。
- 同一读音仅变更声调时，不因声调被判错。
- 人工改为合法数字拼音后，批处理不覆盖该值。
- 轻声词句不生成 `0`、`5` 或伪造一声，且不出现腾讯 `4001`、`4111`、`4113` 参数错误。
- 待认识转已认识后仍可进行词语指定读音评测。
- 待认识字直接存入字库、以及已认识字存入字库后，关联音素资产均被清理。
