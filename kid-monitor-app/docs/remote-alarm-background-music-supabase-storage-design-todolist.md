# 监控端远程闹钟背景音乐 Supabase Storage 设计与 ToDo List

## 决策

远程闹钟的背景音乐改为**运营维护的真实音频文件**，存储在项目既有的 Supabase Storage；家长端只选择已发布曲目，监控 Pad 自动下载、校验并离线循环播放。该方案不接入腾讯云 COS，不给 Android 客户端配置任何腾讯云存储密钥。

本方案解决当前实时合成音乐的听感问题，同时保留闹钟到点离线响铃的可靠性：音乐必须在闹钟生效前预先缓存，`AlarmReceiver` 的冷启动路径不得访问网络。

## 范围与边界

### 本期范围

1. 维护人员向 Supabase Storage 上传有合法授权的 OGG 或 MP3 音乐文件，并在曲目表发布元数据。
2. 家长端从已发布的曲目列表中选择背景音乐；旧闹钟继续使用默认曲目。
3. 监控 Pad 同步曲目元数据，下载后进行大小、MIME 类型和 SHA-256 校验，原子写入私有缓存。
4. 到点由 `AlarmAudioController` 循环播放本地文件；语音播放时沿用现有压低背景音、完成后恢复和 6 秒重播规则。
5. 下载或播放失败时，回退到现有本地合成的 `gentle_bell_v1`，不影响振动、全屏展示、关闭动作或闹钟回执。

### 非目标

- 不在一期增加“家长上传我的音乐”。这会增加私有文件隔离、容量配额、格式转码、版权提示、内容审核和删除生命周期，另行立项。
- 不复用 `literacy-audio` bucket。教学语音与闹钟背景音乐的公开性、生命周期和访问权限不同，必须隔离。
- 不在闹钟到点时下载音乐，也不把音乐预混进可变的提醒语音。
- 不采用腾讯云 COS；当前项目已有 Supabase Storage 能力，新增 COS 只会增加账号、费用和权限面。

## 文件与上传规范

首期采用经过听感验收的短循环曲目。优先 OGG（体积较小），兼容时允许 MP3。

| 项目 | 规则 |
| --- | --- |
| 时长 | 30～90 秒；首尾应可自然循环 |
| 文件大小 | 单文件不超过 5 MB |
| 格式 | `audio/ogg` 或 `audio/mpeg` |
| 内容 | 无人声歌词、无突兀音量峰值、拥有可用于 App 分发的授权 |
| 音量 | 按统一响度验收；设备最终仍受 Android 闹钟音量控制 |
| 版本 | 修改音频内容必须创建新版本，不覆盖已发布对象 |

维护人员通过 Supabase Dashboard 的 Storage 上传到私有 bucket `alarm-background-music`。对象路径固定为：

```text
published/{music_id}/{version}/background.{ogg|mp3}
```

上传后计算 SHA-256、试听和循环检查，再由受信任的管理操作写入曲目元数据并设为 `published`。客户端没有 bucket 写权限；生产期不将该 bucket 设置为公开读取。

## 数据与权限设计

### `alarm_background_music` 曲目表

建议新增只读曲目表：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| `id` | `seaside_sunrise_v2` | 稳定曲目 ID，家长闹钟保存此值 |
| `name` | `海边晨光` | 家长端展示名 |
| `version` | `2` | 缓存失效版本 |
| `object_path` | `published/.../background.ogg` | 仅服务端可写的 Storage 相对路径 |
| `mime_type` | `audio/ogg` | 下载校验依据 |
| `size_bytes` | `1830042` | 大小上限与完整性校验 |
| `sha256` | 64 位摘要 | 内容校验依据 |
| `duration_ms` | `60000` | 展示和运维检查 |
| `status` | `published` | 仅该状态可被客户端选择/下载 |
| `sort_order` | `20` | 家长端排序 |
| `created_at` / `updated_at` | 时间戳 | 审计 |

`alarms.background_music_id` 保留曲目 ID，而不是 URL 或对象路径。保存闹钟时，数据库/RPC 必须验证该 ID 对当前家庭可见且为 `published`；曲目下架后，已有 Pad 缓存可以继续用于已生效闹钟，新编辑不得选择。

RLS 规则：已认证且属于家庭的家长、已绑定的目标监控设备，只能读取 `published` 曲目的必要元数据；不允许任何客户端写表、上传或删除对象。对象下载由短时签名 URL 或受控下载函数提供，禁止向客户端发放 service-role 密钥。

## 下载、缓存与播放

```text
维护人员上传并发布曲目
  -> 家长端读取曲目表并保存 music_id 到 alarm
  -> Pad 同步 alarm + 曲目元数据
       -> 正常网络时请求短时下载地址
       -> 下载到临时文件，校验 MIME / 大小 / SHA-256
       -> 原子改名到应用私有缓存
  -> AlarmManager 到点
       -> AlarmAudioController 只读取本地缓存并循环播放
       -> 语音开始时背景音降至现有比例，语音结束后恢复
```

缓存键使用 `music_id + version + sha256`，文件位于应用私有目录，不能使用曲目名称作为文件路径。新的缓存校验成功后再删除同一曲目的旧版本；下载失败保留旧的校验通过文件，但只有元数据仍匹配时才可使用。存储不足、校验失败、签名 URL 过期和播放初始化失败都要写入设备诊断状态，并回退到 `gentle_bell_v1`。

当闹钟下发引用的曲目尚未缓存时，闹钟本身仍立即登记为 `deployed`；音乐缓存状态不得阻塞精确闹钟部署。家长端应区分“闹钟已部署”和“背景音乐已缓存”。

## 与现有实现的关系

当前 `gentle_bell_v1`、`seaside_sunrise_v1` 是监控端实时合成的离线兜底实现。本设计完成前继续保留它们，确保旧版本和无网环境可响铃。

本设计仅替换背景音乐来源；`AlarmAudioController` 的单次 `USAGE_ALARM` 焦点、语音期间压低音乐、Android 本地 TTS 兜底、关闭资源释放和 6 秒语音间隔均继续沿用。已有“语音 + 音乐”设计中关于腾讯预生成提醒语音的待办，不因此自动进入本期。
