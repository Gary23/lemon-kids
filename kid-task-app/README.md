# `:kid-task-app`：孩子任务端

## 当前职责

孩子通过任务绑定码进入应用，查看/完成任务、查看日历、兑换奖励和管理个人资料。模块依赖 `:shared`，不应直接实现 Supabase 数据访问。

## 路由与约束

- 首次会话检查由共享 `AuthViewModel` 完成；未登录进入 `task_binding_code`，成功后进入 `task_main`。
- 任务端固定 4 个 Tab：`home`、`calendar`、`reward`、`profile`；`plan` 是子页面而非 Tab。
- 绑定页必须传递 `type = "task"` 和 Android `ANDROID_ID`。不得将其改为监控端的单设备重绑语义。
- 任务端会在本 App 私有存储中保存已验证的 `task` 绑定码。任务/番茄请求前检查会话及有效期，必要时有限刷新；运行中认证恢复失败（包括 SDK 已清空失效会话）由根层显示与认字端一致的不可关闭恢复弹层，提供“重试刷新”和“使用绑定码登录”，后者使用本机保存的绑定码静默登录，不另开输入页。恢复成功后重拉任务与积分、补传本机番茄并刷新数量；番茄大窗暂时让出恢复入口，不改变当前计时。主动切换账号或清除应用数据后必须重新绑定。
- 日历页采用横屏双栏：左侧月历以右上圆点表示状态、右下显示真实得星，底部左侧以小番茄图标+数量显示当日番茄数（0 不显示角标，超过两位显示“99+”）；右侧按选中日期展示摘要和平铺任务卡，摘要显示“🍅 当日番茄 N 个”。首页任务卡维持独立布局。可切换月份、回到今天和选择日期，月份与选中日保持同步；内容区较窄时顺序堆叠并可滚动。
- 月历日期任务、完成状态、选中日任务数与进度均来自真实任务；日期详情保留任务朗读、完成确认和撤销操作。月度统计、成长足迹和鼓励寄语目前没有可靠数据源，逐处标为“演示”，不计入真实积分或写入服务端。
- “未来计划”从“我的成长”进入，按日期升序只读展示全部未来有日期的真实任务，包括本周以外及非待完成任务，并显示各任务的真实状态和积分；完成和撤销仍在日历日期详情操作。
- 任务完成和撤销依赖 `:shared` Repository/RPC。奖励页从家庭奖励目录读取真实心愿、本人积分余额、本月任务收益和兑换记录；兑换时由服务端事务扣星，使用前取消按原价退星。若星星已花费且余额不足，任务撤销由服务端拒绝。
- 奖励目录由家长维护，同一家庭的孩子共享启用的奖励，其他家庭的奖励不可见。一次性奖励全家总共只能成功兑换一次，未使用的兑换取消后恢复名额（奖励仍启用时）；常规奖励可重复兑换，每次生成独立记录。余额未取得时不可兑换，积分不足时显示差额；兑换须二次确认，失败不改变页面余额或记录并可重试。未使用的兑换可取消并按原价退星，已使用的兑换保留历史且不可取消，已取消记录仅留服务端审计；旧版有效兑换仍可在记录中辨识。正在攒星星的大心愿在本人存在待使用或已使用的兑换后，卡片连同章节标题从兑换区移除，也不会落入小心愿区；只有取消该兑换后恢复展示，目录与历史数据不受影响。可重复的小心愿兑换后继续常驻并可再次兑换。
- 奖励兑换页的大心愿和小心愿卡片展示本家庭启用奖励的家长上传图片；无图、图片签名中或失败、图片加载失败时显示浅灰色图片区，名称、积分和兑换照常可用。进入页面或点击“刷新奖励”会重读目录；同一张已显示的图片在滚动、页面恢复和刷新时保持显示，临近短期地址到期才重新签名，并在新图加载成功后切换。家长替换或移除图片后刷新即可更新，不沿用旧路径图片。孩子端没有图片修改入口，兑换历史仍只显示文字；图片读取依赖 `:shared` 的签名接口及 Supabase 私有 `reward-images` 存储权限。
- 有截止时间的待完成任务会在孩子端以本地通知提醒；首次启动需取得通知权限。
- `MainActivity` 固定主横屏方向；公共壳层始终使用 184 dp 左侧四入口导航，底部保留儿童摘要。今日任务顶部直接显示进度，不展示时段问候及重复的天数、积分标签；待办/已完成按 1.25:0.75 双列布局，待办及已错过任务使用卡片右端仅显示“打卡”的黄色文字操作按钮，并沿用原确认流程。待办及已错过任务卡在分类标签后显示真实 `+n 积分`，不在卡片底部显示截止时间；已完成卡标题下显示“获得 N 颗星星”。不提供竖屏版或底部导航。首页仅展示当日任务，首次会等待任务和分类均返回后再展示；未手动排序时按家长端配置的创建顺序分组，避免首屏重排。分类图标按分类稳定标识选择；分类颜色按当天可见分类集合分配，最多十类同屏不撞色，同一集合内刷新和任务排序不改变颜色。超过十类可能复用颜色，分类集合增删可能使部分分类换色。十种底色依项目 Stitch UI 色卡调整为较浅配色，今日待办及过期卡片的分类标签与左侧竖条直接共用同一不透明颜色。已完成任务会脱离原分类，统一置于末尾的孩子端专用“已完成”分组。
- 首页仅“待完成任务”列表支持整卡长按拖动，可跨分类重排；左侧无独立把手。长按卡片文字、空白或操作区会出现抬起、黄色描边、轻摆及触感反馈，实际拖动时邻卡让位；静止长按不自行换位，反复交换也不使无关卡片串位。短按朗读、打卡和普通滚动仍可使用；“今天已完成”列表不可拖动，拖动不会改任务分类、状态或积分。
- 待完成列表标题下不显示拖动提示行，拖动时也不出现该提示；空列表提示保留。任务卡显示并朗读当前任务实例的每日描述，内容由家长端逐日发布，不从任务库固定描述继承。
- 待完成顺序只保存在本机 App 私有存储，按孩子账号和任务日期隔离；退出重开、从后台恢复或任务刷新后继续使用已保存顺序。新待完成任务和撤销完成后返回的任务追加在末尾，已完成任务移出待完成列表；没有手动顺序时沿用默认分类顺序。保存失败会恢复先前顺序并提示重试。排序不向服务端、家长端、日历或桌面小部件同步；另一设备、卸载或清除应用数据后不恢复本机顺序。
- 今日任务右上角的番茄钟入口替换原神秘盲盒，默认显示“今日收获 N 个/暂无”，运行中显示“专注中/休息中 · mm:ss”，提醒中显示“🔔 提醒中 · 专注完成/休息结束”。点击打开近全屏弹层；弹层包含整幅倒计时、今日数量、同步状态、关闭按钮和隐藏式“时长设置”覆盖面板，设置完成后回到计时视图且不自动开始。
- 番茄钟专注可选 10/15/20/25/30/35/40 分钟，休息可选 3/5/10/15 分钟，默认 25+5；当前轮未结束时不能修改时长。专注和休息均可暂停/继续，暂停冻结剩余时间。完整专注结束只计 1 个番茄，红色圆环停在 00:00，必须手动点击“开始休息”才开始完整休息时长；休息结束后手动点“下一轮”，不自动切换或循环。
- 专注和休息到点都会响铃+震动，提醒最长 60 秒；“停止响铃”与暂停/继续、开始休息、结束本轮等适用按钮等高、在圆环外单行排列，不显示额外提醒说明。停止提醒或超时只停止声振，不开始休息；开始休息、下一轮或结束本轮会清除旧提醒。关闭弹层或打开小窗不停止提醒。
- 未完成的运行/暂停轮次关闭大窗后，在全应用右上角保留仅圆环和时间的小窗；时间、进度及专注红/休息绿与大窗一致，跨页面继续保持。小窗只有点击打开原大窗一个操作，不提供暂停、停止、拖动或长按；点击不改变计时或声振，到点只提醒、不自动展开。根层统一持有计时会话，结束本轮后大窗和小窗均关闭。
- 进行中的当前轮只保存在内存，不写本机快照；退出 App（返回键、最近任务划掉、进程结束）即结束当前轮，重新打开为准备态，不恢复、不补算、不补响；切后台和回前台不做特殊处理，前台服务只用于让计时和响铃尽量按系统能力继续，系统冻结或回收时自然停止。已完成番茄按 Asia/Shanghai 日期计数，退出后仍保留，在弹层、今日任务入口和日历三处使用同一口径；未同步记录在本机暂存并显示待同步，数据库或网络不可用时不把数量伪装为 0。数据经 `:shared` 的 `PomodoroRepository` 写入 `pomodoro_completions`，读取失败与上传失败分别展示，可重试；上传回执不确定时按 sessionId 核验，避免重复计数。新环境依赖 `supabase/sql/20261111_pomodoro_completions.sql`，已有环境须额外部署 `supabase/sql/20261111_pomodoro_pause_compatibility.sql` 才支持暂停后真实经过时间更长的记录。暂停兼容 SQL 已交付，但目标库部署尚未确认；未部署时此类记录可能保留本机待同步，不能宣称服务端已兼容。
- 固定侧栏四入口名称为“今日任务”“任务日历”“奖励兑换”“我的成长”。奖励页按 Stitch 展示“我的星星银行”、大心愿、Pad 横屏三列小心愿和单列表真实兑换记录；刷新按钮位于星星银行，刷新中仍保持白字与深绿背景。不提供“投递新愿望”入口。成长页展示真实资料、等级、勋章和足迹，并保留计划、使用限制和切换账号入口。
- 固定侧栏孩子摘要与“我的成长”标题显示当前绑定孩子账号的 `users.name`；成长页姓名只读。资料加载中显示“姓名加载中”，字段为空显示“未设置姓名”，长姓名省略显示。侧栏摘要显示当前孩子的圆形头像和 `Lv.N` 角标；头像未取得时使用默认孩子图，成长快照未取得时不显示等级，切换账号不沿用前一孩子资料。
- 任务完成与撤销的确认入口按任务防重复提交；首页先即时反馈卡片，成功后刷新任务观察流，得星动画只在确认完成成功后播放，总积分只采用权威积分流。首页与日历失败均显示提示，首页恢复最近权威状态或原状态，并只读刷新核验；超时或响应不确定不盲目重放写操作。
- 应用从后台恢复时会检查 Supabase 会话，有效凭证不强制刷新，必要时受控刷新并立即重拉任务；会话恢复有八秒期限，网络暂不可用时会结束加载态，会话无法恢复时由根层登录恢复弹层接管。
- 任务端提供标准 Android 桌面小部件“今日任务卡片”：作为首页当日任务的只读镜像，不展示问候头部，按相同分类展示全部当日任务及待完成、已完成、已过期状态；已完成任务同样固定归入末尾的“已完成”分组。设备解锁及日期、时间、时区变化时会刷新，并在后台进程重建时使用当天最近一次成功同步的快照兜底。点按小部件任意位置只会进入任务端首页，不会在桌面修改任务。
- 启动图标使用 `drawable-nodpi/ic_launcher_foreground_lemon.png` 的柠檬吉祥物前景，配合自适应图标浅绿色底色。

## 我的成长：真实数据与展示规则

- 页面从当前登录孩子的 `growth_snapshot()` 只读快照取得任务摘要、EXP、勋章进度和最近足迹；星星余额仍取现有真实积分来源。加载、无记录、读取失败分别展示，不用演示数字或零值冒充失败结果。读接口只允许孩子读取本人快照；家长端的 13 条专项手动进度经独立受控接口维护，任务端不能编辑。任务库领域不推动专项勋章；两条任务习惯勋章由真实任务计算。依赖 `:shared` 的 `GrowthRepository` 和 `supabase/sql/20261005_kid_growth_snapshot.sql`；先部署家长端进度能力，再部署孩子端只读快照。
- 四张统计卡显示有效完成任务数、打卡天数、已获得的勋章阶段枚数和可用星星，数字不带单位。`1` 颗有效任务到账星星计 `1 EXP`，不消耗星星余额，也不把奖励兑换、退款或家长人工积分计入 EXP。总等级从 Lv.1 至 Lv.85，星星、月亮、太阳依次进位，四太阳后为“柠檬之冠”；任务完成、撤销等事实变化可使 EXP 与等级变化。顶部白色资料卡显示孩子头像、等级与勋章称号和今日真实任务打卡。等级卡首行显示当前 `Lv.N`、等级图标及名称和“当前成长值”，中间是进度条，下方显示下一等级及差额；满级不显示下一级。当前版本没有成长纪念卡和等级外观解锁入口。
- 勋章馆按“全部/语文阅读/英语/数学/生活实践/成长习惯”筛选，主列表一类一卡，只展示累计进度大于零的类型；有正数进度但未获首级的类型仍可查看。类型卡等高，显示到下一门槛的真实进度条，点击后查看该类型全部等级的名称、门槛、临时图标及“已获得/未获得”状态。每个已获得的等级阶段独立计一枚勋章，六级类型满级计六枚；顶部和馆内数量都按阶段枚数计算。13 条手动专项加两条任务习惯共 15 条类型；高效英语和思维火箭尚未制定等级。各级名称和门槛见[勋章说明](勋章说明.md)。每类各阶段暂复用本地矢量图标，逐等级图片生成、Supabase Storage 托管与加载留待后续需求。
- 最近成长足迹按可核实事件倒序最多读取 10 条，默认显示 3 条，可用箭头展开剩余最多 7 条并收起。足迹日期按上海时区显示 `yyyy-MM-dd`，无法解析时不展示原始字符串；当前勋章类型卡和详情不显示更新时间。无进度分类与无足迹均显示空状态。进入成长页和从后台恢复会重新读取快照，账号切换后清除旧快照。

## 本地调试包

- 仅用于本机联调：`kid-task-app/scripts/build-local-debug.sh --url http://<IP>:54421` 先跑任务端与 `:shared` 单元测试，再以 `-PlocalSupabase=true` 构建，生成 `com.lemonkids.kidtask.local` / `1.0.0-local` 的独立包（启动器名“柠檬任务·本地”），交付副本和脱敏元数据位于 `build/outputs/apk/local-debug/`；失败时不沿用旧产物。
- 首次启动先显示本地地址页；地址页、绑定码登录页和“我的成长 → 设置与账户”都可修改地址。不可达地址不会覆盖已保存配置；改变地址会经前台辅助进程重启，并清除旧会话、绑定码、任务缓存与提醒，必须重新绑定。
- 本地包与线上包共用 `:shared` 代码，但应用数据、绑定码、提醒和桌面卡片各自隔离；`auth/ChildBindingStore` 须同时精确识别 `com.lemonkids.kidtask` 与 `com.lemonkids.kidtask.local`。默认 `assembleDebug`、`assembleRelease` 仍连接线上环境。
- 依赖本地库已部署孩子端支持增量（`supabase/sql/20261030_local_kid_task_support.sql`，前提见 `supabase/LOCAL_REVIEW.md`）；线上账号、家庭和任务不会出现在本地库，测试账号见本地调试流程文档。

## UI 参照顺序

柠檬任务的 UI 修改必须先通过 Stitch MCP 获取目标屏幕的实际截图和 HTML，以 MCP 实际效果为主要依据；MCP 缺失或不明确的部分才参考本地下载的 `ui` 目录。此规则适用于本次及后续修改。具体屏幕和例外须记入对应的 `docs/20260922-kid-task-app-*` 需求与设计文档，不扩展到其他应用或全局规范。
